## 字典数据模型

字典由「类型」与「数据」两张表组成，通过 `type_id` 关联，没有外键约束。

### 字典类型 `sys_dict_type`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键，UUID |
| `name` | 类型名称，例如「任务日志状态」 |
| `code` | 类型编码，全局唯一（`uk_dict_code`），例如 `job_log_status` |
| `status` | 启用状态，`1` 启用 |
| `remark` | 备注 |
| `is_deleted` | 逻辑删除标记 |

### 字典数据 `sys_dict_data`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键，UUID |
| `type_id` | 所属字典类型的 id |
| `label` | 展示文本，`i18n_key` 为空时作为兜底文案 |
| `i18n_key` | 翻译 key，优先于 `label` |
| `list_class` | 展示样式，前端用于徽标颜色 |
| `value` | 字典值，字符串存储 |
| `sort_order` | 排序值 |
| `status` | 启用状态 |

字段定义见 `server/drizzle/schema/system/dictType.ts`、`server/drizzle/schema/system/dictData.ts`。

## 前端字典用法

| API | 返回 | 适用场景 |
| --- | --- | --- |
| `useDictOptions(code, includeValues?)` | `{ value, label }[]` | 下拉框（字符串值） |
| `useDictNumberOptions(code, includeValues?)` | `{ value: number, label }[]` | 下拉框（数值值） |
| `useDictBadgeConfig(code, defaultColor?)` | `Record<string, BadgeConfig>` | 表格状态列的徽标颜色 |
| `useDictStore()` | Pinia store | 需要手动加载或清理时 |

三个 composable 都返回 `computed`，并在调用时触发一次 `loadDict(code)`，因此可以直接绑定到模板。

### 文案与颜色规则

- 展示文案优先取 `i18n_key`，为空时退回 `label`，最终由 `$ts()` 翻译；
- 徽标颜色取 `list_class`，只接受 Nuxt UI 支持的色值（`primary`、`secondary`、`success`、`warning`、`error`、`info`、`neutral`），其它值回退到默认色 `neutral`；
- `includeValues` 用于只保留指定值，例如某个表单只允许 `0` / `1`。

### 会话内的前端缓存

`useDictStore` 在浏览器侧做了一层会话级缓存（`app/stores/dict.ts`）：

| 成员 | 作用 |
| --- | --- |
| `itemsByCode` | 按字典编码缓存数据 |
| `loadingByCode` / `errorByCode` | 加载与错误状态 |
| `loadDict(code, force?)` | 已有数据直接返回；同一编码的并发请求会合并为一次查询 |
| `clearDict(code?)` | 清理单个编码或全部 |
| `clearDictByCodes(codes)` / `clearDictByTypeIds(ids, fallbackCode?)` | 字典维护页在写入后清理受影响编码 |
| `codeByTypeId` / `getCodeByTypeId(typeId)` | 由类型 id 反查编码，供维护页使用 |

这层缓存只存在于当前页面会话，不写入 `localStorage`，刷新后重新拉取。

## 服务端字典缓存

字典读取走 `DictCacheService`，默认 TTL 30 分钟，缓存键为 `cache:dict:{encodeURIComponent(code)}`：

```ts
const items = await cache.getByTypeCode(
  'user_status',
  () => sysDictDataRepo(ctx).listByTypeCode('user_status')
)
```

| 方法 | 作用 |
| --- | --- |
| `getByTypeCode(code, loader)` | 缓存优先，miss 时执行 loader 并回填 |
| `invalidate(code)` | 失效单个字典编码 |
| `invalidateAll()` | 清空整个字典缓存前缀 |

写操作的失效点已经集中在服务层，调用方通常不需要手动清理：

| 触发场景 | 失效范围 |
| --- | --- |
| 新增/修改字典数据 | 该数据所属类型对应编码 |
| 删除字典数据 | 所属编码；取不到类型时清空全部 |
| 批量删除字典数据 | 涉及的全部编码；取不到时清空全部 |
| 字典类型新增/修改/删除 | 清空全部字典缓存 |

实现见 `server/sys-router/storage/cache/DictCacheService.ts`、`server/sys-router/dictData/SysDictDataService.ts`、`server/sys-router/dictType/SysDictTypeService.ts`。

**注意**：只能缓存 `listByTypeCode` 的结果，不需要在业务侧自行拼缓存 key 或设置 TTL，键与有效期统一维护在 `server/sys-router/storage/cache/StorageCacheKeys.ts`。

## 系统配置

### 数据模型 `sys_config`

| 字段 | 说明 |
| --- | --- |
| `config_name` | 配置名称（展示用） |
| `config_key` | 配置键，业务引用标识 |
| `config_value` | 配置值，统一以字符串存储 |
| `config_type` | 配置类型标记，默认 `1` |
| `status` | 启用状态 |
| `remark` | 备注 |

### 接口

| 方法 | 权限码 | 说明 |
| --- | --- | --- |
| `sysConfig.getValueByKey` | 无需登录（`publicProcedure`） | 按键取值，返回 `string \| null` |
| `sysConfig.page` / `getOne` / `getById` | `system:config:list` | 查询 |
| `sysConfig.create` | `system:config:add` | 新增 |
| `sysConfig.update` | `system:config:edit` | 修改 |
| `sysConfig.remove` / `batchDelete` | `system:config:del` | 删除 |

`getValueByKey` 特意使用 `publicProcedure`，让登录页在未登录状态下也能读取开关（例如是否开放注册）。

### 前端读取

```ts
const { getConfigValue } = useConfig()

// 有值返回配置值；无值且有默认值时返回默认值
const enabled = await getConfigValue('system_register_enable', 'no')

// 无值且未传默认值时：抛出异常并弹出一条 warning 提示
const value = await getConfigValue('some_key')
```

实现见 `app/composables/useConfig.ts`。

### 已知配置键

| 配置键 | 取值 | 用途 |
| --- | --- | --- |
| `system_register_enable` | `yes` / `no` | 是否开放注册，非 `yes` 时注册接口返回 `auth.registerDisabled` |
| `system_otherlogin_enable` | `true` / `false` | 是否显示其它登录入口，缺失时按启用处理 |

常量定义在 `shared/constants/business.ts` 的 `systemRegisterEnum` 与 `systemOtherLoginEnum`。

## 新增字典或配置的步骤

1. **字典**：在字典类型页新增类型并取得 `code` → 在字典数据页维护该类型的选项（值、文案、颜色）→ 若代码需要引用，在 `businessDictCode` 中补一个常量 → 页面用 `useDictOptions` / `useDictBadgeConfig` 绑定。
2. **配置**：在系统配置页新增配置项，约定好 `config_key` 与取值含义 → 在 `shared/constants/business.ts` 中登记常量 → 服务端用 `sysConfigService(ctx).getValueByKey(key)` 读取，前端用 `useConfig().getConfigValue(key, defaultValue)` 读取。

## 注意事项

| 事项 | 说明 |
| --- | --- |
| 值为字符串 | 无论配置还是字典，`value` 都是字符串，数值比较前需要自行转换 |
| 缓存是进程内的 | 字典缓存 30 分钟，重启即失效；多实例部署时各自维护 |
| 失效优先于 TTL | 写操作会主动失效，TTL 只是兜底 |
| 前端不持久化字典 | 只保留在当前会话，避免脏数据长期驻留浏览器 |
