## 路由文件组织

每个业务模块一个目录，目录下的 `index.ts` 就是该模块的 tRPC 路由：

```text
server/sys-router/<模块>/
├── index.ts            # tRPC 路由（router）
├── Sys<模块>Repo.ts    # 数据访问
└── Sys<模块>Service.ts # 业务逻辑
```

路由只做三件事：声明权限、绑定输入 schema、把 `ctx` 与 `input` 转交 Service。

```ts
// server/demo-router/index.ts（节选）
export const demoRouter = router({
    create: proc({ permission: 'demo:add' }).input(DemoAddSchema)
        .mutation(async ({ ctx, input }) => {
            return demoService(ctx).create(input)
        }),
    page: proc({ permission: 'demo:list' }).input(DemoPageQuerySchema)
        .query(async ({ ctx, input }) => {
            return demoService(ctx).page(input)
        })
})
```

## procedure 类型

`server/trpc/init.ts` 导出的 procedure 与工厂：

| 导出 | 说明 |
| --- | --- |
| `publicProcedure` | 完全公开，不校验登录、不记日志，用于登录、注册等入口 |
| `protectedProcedure` | `publicProcedure` + 日志中间件 + 登录校验，只要求登录不校验权限 |
| `permissionProcedure(code)` | `protectedProcedure` + 单个权限码校验 |
| `proc(options)` | **项目统一使用的工厂**，把登录/权限/数据权限/demo 只读/日志收敛为一组参数 |
| `customProcedure` | 不做任何中间件处理的自定义 procedure，仅在确有特殊需要时使用 |
| `crudPermissionProcedures(resource)` | 一次性生成 list/add/edit/del 四个 procedure 的工厂 |

## proc() 参数

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `permission` | `string` | 不传 | 权限码；不传表示仅需登录，等价于 `protectedProcedure` |
| `log` | `boolean` | `true` | 是否记录操作日志；显式传 `false` 可跳过噪音较大的接口 |
| `dataScope` | `boolean` | `true` | 是否应用数据权限；`false` 表示该接口不做数据范围限制 |
| `readonly` | `boolean` | `false` | 是否在 demo 模式下禁止调用；实际开关是 `demoMode \|\| readonly` |

```ts
create: proc({ permission: 'system:job:add' }).input(SysJobAddSchema)
    .mutation(({ ctx, input }) => sysJobService(ctx).create(input)),

enable: proc({ permission: 'system:job:edit' }).input(SysJobStatusSchema)
    .mutation(({ ctx, input }) => sysJobService(ctx).enable(input.id)),

runNow: proc({ permission: 'system:job:run' }).input(z.string().nonempty('form.id.required'))
    .mutation(async ({ input }) => {
        return runTask('sys-job:run', { payload: { jobId: input, triggerType: 'manual' } })
    }),
```

> `proc()` 不传任何参数也可以调用，表示「登录 + 记日志 + 应用数据权限」，例如 `auth.profile` 与 `auth.myProfile`。

## 权限码书写约定（重要）

`server/trpc/init.ts` 中确实导出了 `crudPermissionProcedures` 工厂，但**项目约定不使用它**，而是显式书写每个接口的权限码：

```ts
// 项目约定写法
const listProc = proc({ permission: 'system:job:list' })
const addProc = proc({ permission: 'system:job:add' })
const editProc = proc({ permission: 'system:job:edit' })
const delProc = proc({ permission: 'system:job:del' })

// 而不是使用工厂
// const { list, add, edit, del } = crudPermissionProcedures('system:job')
```

原因与约束：

- 显式权限码便于在代码里直接搜索定位，也便于与 `sys_menu.code` 逐条核对。
- `proc({ readonly: true })` 需要在编辑/删除接口单独声明，工厂的固定组合无法表达这类差异。
- 生成新模块时必须与[新建模块 · 后端步骤](/docs/new-module/backend-steps)的「操作类型与 proc() 参数」约定和[文件清单](/docs/new-module/checklist)的注意事项第 5 条保持一致。

权限码命名规则：

| 场景 | 形态 | 示例 |
| --- | --- | --- |
| 标准 CRUD | `<resource>:<action>` | `system:user:list`、`system:user:add`、`system:user:edit`、`system:user:del` |
| 自定义动作 | `<resource>:<action>` | `system:user:resetPwd`、`system:job:run`、`system:storage:del` |

权限码来源是 `sys_menu.code`，构造工具在 `shared/auth/permission.ts`（`buildPermissionCode` / `customPermissionCode` / `crudPermissionCodes`）。

## 输入校验与操作类型

- `.input(schema)` 使用 `shared/` 下的 Zod schema；无入参时可用 `z.string()` / `z.array(z.string())`，需要必填提示时写 i18n key，例如 `z.string().nonempty('form.id.required')`。
- 读取用 `.query()`，写入与执行动作（含「立即执行」这类触发型操作）用 `.mutation()`。
- 校验失败会由 `errorFormatter` 汇总字段错误信息后返回，前端无需自行拼装。

## 注册到 appRouter

新模块必须在 `server/trpc/routers.ts` 的 `appRouter` 中挂载，命名空间即前端调用前缀：

```ts
export const appRouter = router({
    auth: authRouter,
    sysJob: sysJobRouter,
    // ...
});
export type AppRouter = typeof appRouter;
```

`AppRouter` 类型同时是前端 `$trpc` 的类型来源，注册后前端才能获得补全与类型检查。

## 常用方法命名

模块内保持一致的方法名，前端页面与新建模块的模板都依赖这套命名：

| 方法 | 类型 | 说明 |
| --- | --- | --- |
| `list` | query | 不分页条件查询 |
| `page` | query | 分页查询 |
| `getOne` | query | 按条件取一条 |
| `getById` | query | 按主键取一条 |
| `create` | mutation | 新增 |
| `update` | mutation | 按主键更新（入参含 id） |
| `remove` | mutation | 单条删除 |
| `batchDelete` | mutation | 批量删除 |
| 自定义动作 | mutation | 如 `enable` / `disable` / `runNow` / `resetPwd` |

## 新增一个接口的步骤

1. 确认入参 schema 已在 `shared/<模块>/input.ts` 中定义（没有就补上）。
2. 在 `<模块>/index.ts` 中用 `proc({ permission: '<resource>:<action>' })` 声明 procedure。
3. `.input(schema)` 绑定校验，选择 `.query()` 或 `.mutation()`。
4. 方法体只调用 Service，不写业务与 SQL。
5. 若是新模块，在 `server/trpc/routers.ts` 中注册命名空间。
6. 在 `sys_menu` 中补对应按钮权限并授权给角色，否则非管理员调用会被拒绝（`auth.forbidden`）。
