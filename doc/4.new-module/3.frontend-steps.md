## Step 10：创建列表页面

路径 `app/pages/<模块名>/index.vue`（目录用 kebab-case，例如 `system/oauthAccount` → `app/pages/system/oauth-account/`）。

必须先声明布局：

```typescript
definePageMeta({
  layout: 'system'
})
```

核心要点：

- 用 `usePaginatedTable` 管理分页查询，用 `useTableOperate` 管理新增 / 编辑 / 删除。
- 用 `useSelectionColumn` 生成选择列、`useBadgeColumn` 生成状态标签列。
- 用 `useCrudPermissions('<resource>')` 生成前端权限码与权限状态。
- `TableHeaderOperation` 必须传入 `:add-permission="permissions.codes.add"` 与 `:delete-permission="permissions.codes.del"`。
- 行内编辑按钮由 `permissions.canEdit` 控制，行内删除按钮由 `permissions.canDel` 控制。
- 没有删除权限时隐藏选择列；没有编辑/删除权限时隐藏操作列。
- 通过 `$trpc.<模块路由名>.<方法>` 调用后端，用 `$ts()` 取翻译文案。
- **组件 import 必须带显式 `.vue` 后缀**。

关键导入：

```typescript
import type { DemoDto, DemoQueryDTO } from "#shared/demo"
import DemoSearch from './components/demo-search.vue'
import DemoOperate from "./components/demo-operate.vue"
```

权限声明：

```typescript
const demoPermissions = useCrudPermissions('demo')
```

```vue
<TableHeaderOperation
  :add-permission="demoPermissions.codes.add"
  :delete-permission="demoPermissions.codes.del"
/>
```

列定义（含按权限隐藏操作列）：

```typescript
const columns = computed<TableColumn<DemoDto>[]>(() => {
  const actionColumn: TableColumn<DemoDto> = {
    id: 'actions',
    header: () => $ts('common.operate'),
    cell: ({ row }) => {
      const UButton = resolveComponent('UButton')
      const Popconfirm = resolveComponent('Popconfirm')
      const actions = []

      if (demoPermissions.canEdit.value) {
        actions.push(h(UButton, {
          variant: 'outline',
          color: 'primary',
          size: 'xs',
          onClick: () => handleEdit(row.original.id as string)
        }, { default: () => $ts('common.edit') }))
      }

      if (demoPermissions.canDel.value) {
        actions.push(h(Popconfirm, {
          onConfirm: () => handleDelete(row.original.id as string)
        }, {
          trigger: () => h(UButton, {
            variant: 'outline',
            color: 'error',
            size: 'xs'
          }, { default: () => $ts('common.delete') })
        }))
      }

      return h('div', { class: 'flex gap-2' }, actions)
    }
  }

  return [
    ...(demoPermissions.canDel.value ? [selectionColumn] : []),
    // ...业务列
    ...(demoPermissions.canOperate.value ? [actionColumn] : [])
  ]
})
```

完整示例可对照 `app/pages/demo/index.vue`（最小模块）与 `app/pages/system/user/index.vue`（完整模块）。

## Step 11：创建搜索组件

路径 `app/pages/<模块名>/components/<前缀>-search.vue`。

- 用 `UForm` + `UFormField` + `UBaseInput` / `USelect` 构建搜索表单。
- 通过 `@search` 事件触发父级列表查询。
- 用 `translateOptions`（从 `~/utils/common` 导入）把常量配置转成下拉选项。

> **常见错误**：搜索组件里的 `schema` 变量必须指向**当前模块**的 `QuerySchema`，抄模板时最容易残留上一个模块的引用，导致搜索条件静默失效。

## Step 12：创建操作弹窗组件

路径 `app/pages/<模块名>/components/<前缀>-operate.vue`。

- 用 `UModal` 作为弹窗容器。
- 用 `UForm` + `useZodValidation` 做表单校验（校验失败的消息会自动走翻译）。
- 根据 `operateType`（`add` / `edit`）动态使用 `AddSchema` 或 `UpdateSchema`。
- 提交走 `$trpc.<模块路由名>.create.mutate()` 与 `$trpc.<模块路由名>.update.mutate()`。
- 新增时**不要**自己生成 id，由后端 Service 生成。

## Step 13：添加翻译 key

### 13.1 落点

翻译词条**只能**加在这两个文件里：

- `app/locales/zh.json`
- `app/locales/en.json`

多级模块用嵌套 key 表达：模块名 `system/ossConfig` 对应 `module.system.ossConfig`，代码里用 `$ts('module.system.ossConfig.title')` 引用。

```json
{
  "module": {
    "system": {
      "oauthAccount": {
        "title": "第三方账号绑定",
        "provider": "登录平台",
        "providerUserId": "平台用户ID",
        "providerLogin": "平台账号",
        "userId": "系统用户ID",
        "createdAt": "创建时间",
        "form": {
          "provider": "请输入登录平台，例如 github",
          "providerUserId": "请输入平台用户ID",
          "providerLogin": "请输入平台账号",
          "userId": "请输入系统用户ID"
        },
        "addSysOauthAccount": "新增绑定",
        "editSysOauthAccount": "编辑绑定"
      }
    }
  }
}
```

约定：

- `form.*` 子对象放表单占位符与校验提示；
- `title` 用于列表页标题与表头前缀；
- `add<Business>` / `edit<Business>` 命名新增 / 编辑弹窗标题，`<Business>` 用业务名（如 `SysOauthAccount`）。

> **不要手写** `app/locales/pages/**` 与 `server/assets/_locales/**` —— 它们是 `nuxt-i18n-micro` 在构建时生成的产物（已加入 `.gitignore`），手写会在下次构建时被覆盖。

### 13.2 校验方法

生成后逐个核对页面里的 `$ts('...')` 是否都能在词条文件里查到：

```powershell
# 提取页面中所有 $ts('key')，便于与 zh.json 对照
Select-String -Path app/pages/<module>/**/*.vue -Pattern "\`$ts\('([^']+)'\)" -AllMatches |
  ForEach-Object { $_.Matches } | ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
```

同时确认两个 JSON 文件仍能正常解析（`ConvertFrom-Json` / `JSON.parse`），插入时注意逗号与缩进。

## Step 14：业务常量配置（可选）

如果模块有状态或枚举字段需要在表格里显示彩色标签（badge），或在搜索/表单里做下拉选择，就在 `shared/constants/business.ts` 里补充配置。

状态 badge 配置：

```typescript
export const <MODULE>_STATUS_CONFIG = {
    '1': { i18nKey: 'page.manage.common.status.enable', color: 'success' },
    '2': { i18nKey: 'page.manage.common.status.disable', color: 'warning' }
} as const
```

下拉选项配置：

```typescript
export const <module>StatusRecord: Record<string, string> = {
    '1': 'page.manage.common.status.enable',
    '2': 'page.manage.common.status.disable'
};

export const <module>StatusOptions = transformRecordToOption(<module>StatusRecord);
```

## 命名映射速查

| 层次 | 命名 |
| --- | --- |
| 模块名 | `system/oauthAccount` |
| 页面目录 | `app/pages/system/oauth-account/`（kebab-case） |
| tRPC 路由名 | `sysOauthAccount`（保留 `sys` 前缀） |
| 资源码 | `system:oauthAccount` |
| i18n key | `module.system.oauthAccount`（小驼峰） |

三者大小写风格不同，生成时不要混用。完整对照表见[文件清单与注意事项](/docs/new-module/checklist)。
