## 设计思路

数据库里的任务只保存「何时执行」和「执行哪段逻辑」的引用，真正的业务代码是 Handler。`sys_job.handler_code` 与 Handler 的 `code` 一一对应，两者不一致时任务无法运行。

这样拆分的好处是：任务可以随时新建、改表达式、启停，不需要改代码；而代码上线即可被后台选择，不需要提前在数据库里建任务。

## Handler 契约

```ts
export type SysJobRunContext = {
  db: MySql2Database<typeof schema>
  jobId: string
  jobCode: string
  triggerType: 'schedule' | 'manual'
}

export type SysJobHandler = {
  code: string
  name: string
  description: string
  run: (ctx: SysJobRunContext) => Promise<unknown>
}
```

| 成员 | 说明 |
| --- | --- |
| `code` | 唯一编码，写入 `sys_job.handler_code`，建议使用 `模块:动作` 形式 |
| `name` | 展示名，出现在后台任务表单的 Handler 下拉框 |
| `description` | 用途说明，出现在 `availableHandlers` 接口返回中 |
| `run(ctx)` | 执行体，返回值会序列化写入 `sys_job_log.result` |

`run` 的返回值应当是 JSON 可序列化的对象或基本类型，便于在日志详情里直接查看；抛出异常即视为执行失败。

## 内置 Handler

| code | 名称 | 行为 |
| --- | --- | --- |
| `system:clean-log` | Clean system logs | 软删除 30 天前的 `sys_system_log` 与 `sys_job_log`（`is_deleted` 置 1），返回两张表各自的影响行数 |
| `system:reset-demo-data` | Reset demo data | 保留位示例：不修改任何数据，只回显 `jobCode`、`triggerType` 与说明 |

两者都在 `server/sys-router/job/handlers.ts` 中定义。

## 注册表接口

| 函数 | 作用 |
| --- | --- |
| `listSysJobHandlers()` | 返回 `{ code, name, description }[]`，供前端下拉框使用 |
| `getSysJobHandler(code)` | 按编码取 Handler，执行时使用 |
| `hasSysJobHandler(code)` | 判断编码是否已注册，新增/修改/启用任务时校验 |

注册表由模块内的 `handlers` 数组构建成 `Map`，因此新增 Handler 只需往数组里追加一项。

## 新增一个 Handler

1. **定义 Handler**：在 `server/sys-router/job/handlers.ts` 中按 `SysJobHandler` 结构新增常量，`code` 取值避免与已有重复。

2. **追加到注册表**：把新常量加入文件底部的 `handlers` 数组，`Map` 会随之更新。

3. **在数据库创建任务**：打开后台「任务管理」，新增一条任务并选择刚注册的 Handler；也可以先建任务再上线代码，但任务在 Handler 未注册期间执行会失败。

4. **验证执行**：用列表里的「立即执行」触发一次，然后到任务日志页确认状态为成功、`result` 符合预期。

5. **确认下次执行时间**：任务启用状态下，保存时会自动计算 `next_run_at`；若为 `null`，说明表达式匹配不到可执行时间或任务处于停用状态。

一个最小骨架：

```ts
const archiveNoticeHandler: SysJobHandler = {
  code: 'system:archive-notice',
  name: 'Archive notices',
  description: 'Archive published notices older than 90 days.',
  async run({ db, triggerType }) {
    const result = await db.execute(
      sql`update sys_notice set is_deleted = 1 where is_deleted = 0 and created_at < date_sub(now(), interval 90 day)`
    )

    return {
      triggerType,
      affectedRows: Number((result[0] as { affectedRows?: number })?.affectedRows ?? 0)
    }
  }
}
```

## 前端可选 Handler

后台任务表单的 Handler 选项来自 tRPC 接口 `sysJob.availableHandlers`：

```ts
handlers.value = await $trpc.sysJob.availableHandlers.query()
```

接口返回 `listSysJobHandlers()` 的结果，因此**新 Handler 上线后，刷新任务表单即可看到新选项，无需改前端代码**。对应实现见 `app/pages/system/job/components/sys-job-operate.vue` 与 `server/sys-router/job/index.ts`。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 保存任务时报 `module.system.job.handlerMissing` | `handler_code` 未注册 | 核对 `code` 拼写，确认已加入 `handlers` 数组并重新部署 |
| 任务一直失败并提示找不到 Handler | 代码回滚后任务仍指向已删除的 Handler | 修改任务绑定到现存 Handler，或停用该任务 |
| `result` 为空 | Handler 没有返回值 | 让 `run` 返回一个描述性对象，便于排查 |
| 日志里 `errorStack` 很长 | Handler 内抛出了未包装的异常 | 预期内的失败可以在 Handler 内先记录再抛出，或用 `AppError` 提供可翻译的错误 key |
