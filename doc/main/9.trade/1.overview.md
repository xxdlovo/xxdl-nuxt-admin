交易模块提供「维护商品与服务 → 会员在商城下单 → 余额冻结或在线支付 → 确认/关闭/交付 → 超时兜底关单」这一条完整链路的服务端能力，以及四个配套页面（后台商品管理、后台订单管理、会员自助商城、我的订单）与头像菜单入口。它不自己实现资金与优惠码：余额冻结走 `domain/wallet`，优惠码走 `domain/member`，在线支付单走[支付模块](/docs/main/payment/overview)，三条线通过明确的接口协作。

## 一、能力边界

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**交易模块只有一张商品表 `sys_goods`，服务不是独立实体。**

「应用迁移」这类人工服务用 `type = 'service'` 表达，差异只有三点：不扣库存（需要把 `unlimited_stock` 打开）、`contact` 必填、支付后要由后台「交付」。这条设计写在建表脚本头部注释里（`doc/main/mysql-ddl-goods-order.sql:14-19`）与 `server/trade-router/domain/goods/types.ts:1-6`：订单侧只感知类型，不感知业务名词。
::

其他边界：

- **价格来源只实现了两级**：`等级价 (level) > 基础价 (base)`。`PriceSource` 里的 `member`（会员协议价）**是预留值，没有任何写入方**（`server/trade-router/domain/goods/types.ts:11-15`、`domain/goods/GoodsService.ts:41-68`）。
- **支付方式只有两种**：`balance`（余额冻结 + 确认实扣）与 `online`（在支付模块下一张 `bizType = 'order'` 的支付单）。没有组合支付、没有部分支付、没有余额+在线混付。
- **没有购物车与多商品订单**：一单一商品，`quantity` 对非服务类商品才可大于 1。
- **`physical`（实物）只是预留类型**：`shared/system/goods/input.ts:6` 的枚举里有它，代码里没有任何物流/收货地址逻辑，它的 `fulfill_status` 恒为 `none`。
- **没有退款**：订单一旦 `OD`（已完成）就是收入凭证，不可删除也不可回退；`sys_order` 上没有退款相关字段。
- **优惠码只支持单张且不叠加**：`resolveCoupon()` 只接受一个 `code`（`domain/member/MemberService.ts:321-394`），抵扣金额落 `discount_amount`。
- **后台订单不提供「新增」**：订单由会员自助下单产生，后台只有查询、改备注、确认、关闭、同步、交付、删除（`app/pages/system/order/index.vue:50-63` 刻意不传新增按钮）。
- **商品删除没有「有订单不可删」的保护**：订单上的 `goods_name` / `goods_cover` / `goods_type` / `unit_price` 都是下单时的快照（`server/drizzle/schema/system/order.ts:9-12`），删商品不影响历史单。

## 二、分层调用链与文件地图

交易代码与支付、会员一样收在 `server/trade-router/` 下，也遵守「Router 不写业务、Service 不写 SQL、Repo 不做业务判断」（见[后端手册的 Repo 与 Service](/docs/main/backend-handbook/repo-service)）：

```text
tRPC 控制层   server/trade-router/modules/goods|order/index.ts
                 │  只声明权限码与入参 schema；会员自助接口用 protectedProcedure
                 ▼
模块 Service  modules/goods/SysGoodsService.ts      入参收敛、等级名合并、等级价整体替换透传
              modules/order/SysOrderService.ts      归属校验、商城卡片组装、后台动作编排
                 │
                 ▼
领域服务      domain/goods/GoodsService.ts           上架校验、等级价解析、库存与销量
              domain/order/OrderService.ts           事务边界与状态机（下单/确认/支付成功/关闭/交付/超时）
                 │  不写 SQL，只 import ./repo/*
                 ▼
mapper 层     domain/goods/repo/goodsRepo.ts         条件 UPDATE 扣减/回滚库存、销量
              domain/goods/repo/goodsLevelPriceRepo.ts  等级价整体替换（物理删除）
              domain/order/repo/orderRepo.ts         条件 UPDATE 状态推进 + 后台联表分页
                 │
                 ▼
复用其它领域  domain/wallet/WalletService.ts（freeze/confirm/release）
              domain/member/MemberService.ts（getMember/resolveCoupon/lockCoupon/…）
              domain/pay/PayOrderService.ts（createPayment/queryPayment/closePayment/getById）
```

领域层所有工厂都接收 `AppExecutor`（连接 `AppDb` 或事务 `AppTx`），所以「下单事务里复用商品能力」不需要第二份实现：`goodsServiceIn(tx)` / `walletServiceIn(tx)` / `memberServiceIn(tx)` 就是同域方法的事务绑定版（`domain/goods/GoodsService.ts:206-220`、`domain/order/OrderService.ts:137-141`）。

## 三、三张表概览

| 表 | Schema | 职责 | 关键唯一键 |
| --- | --- | --- | --- |
| `sys_goods` | `server/drizzle/schema/system/goods.ts:3-28` | 商品与服务（一个实体，用 `type` 区分） | 无业务唯一键；索引 `idx_goods_status`、`idx_goods_type` |
| `sys_goods_level_price` | `server/drizzle/schema/system/goodsLevelPrice.ts:3-20` | 商品 × 会员等级的专属价，一行一个等级 | `uk_goods_level(goods_id, level_id)` |
| `sys_order` | `server/drizzle/schema/system/order.ts:3-54` | 交易订单，一行一单；商品的快照 + 资金结论 + 履约状态 | `uk_order_no(order_no)`、`uk_order_request(request_id)` |

建表与配套数据由**一个脚本整段执行**（`doc/main/mysql-ddl-goods-order.sql`），四段结构：

| 段 | 内容 | 位置 |
| --- | --- | --- |
| Part 1 | 建 3 张表（只新增，不改既有表） | `doc/main/mysql-ddl-goods-order.sql:23-121` |
| Part 2 | 16 行菜单/权限（1 目录 + 4 页面 + 11 按钮），id 段 `...11xx` | `:124-159` |
| Part 3 | 1 条定时任务 `order:expire-close`，**默认 `status = 0` 禁用** | `:162-174` |
| Part 4 | 执行结果自检 SQL（预期 3 张表 / 16 行菜单 / 1 条任务） | `:177-192` |

两点约定：

- 三张表的**结构以 `server/drizzle/schema/system/*.ts` 为准**，`shared/system/goods/common.ts` 与 `shared/system/order/common.ts` 与之保持一致；改表后要同步 Schema、契约、mapper 三处（与[支付模块](/docs/main/payment/overview)同一套做法）。
- 表名用 `sys_order` 是因为 `order` 是 SQL 关键字（`:71` 注释）。

## 四、资金状态与履约状态

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**两个维度必须分开看，这是交易模块最重要的一条约定**（`server/trade-router/domain/order/types.ts:1-7`）：

- `status`（`WP` / `OD` / `CL` / `FL`）**只描述资金**；
- `fulfill_status`（`none` / `pending` / `delivered`）**只描述履约**。

交付不涉及资金，所以「交付」这个动作**不推进 `status`、不写任何余额流水**，避免与余额流水口径纠缠（建表脚本 `doc/main/mysql-ddl-goods-order.sql:17-19`）。
::

资金状态（徽标定义在 `shared/constants/business.ts:206-211`）：

| 状态 | 名称 | 含义 | 徽标色 | 进入方式 |
| --- | --- | --- | --- | --- |
| `WP` | 待支付 | 已落单，等待付款；余额单此时钱是**冻结**状态 | warning | 下单初始状态（`OrderService.ts:231`） |
| `OD` | 已完成 | 余额已实扣或渠道已收款，**终态** | success | `markCompleted`（`orderRepo.ts:61-82`） |
| `CL` | 已关闭 | 用户取消 / 后台关闭 / 超时任务关闭 | neutral | `markClosed`（`orderRepo.ts:85-102`） |
| `FL` | 发起失败 | 在线支付单创建失败，纯为排查保留，可删除 | error | `markFailed`（`orderRepo.ts:105-120`） |

履约状态（`shared/constants/business.ts:220-224`）：

| 状态 | 名称 | 何时写入 |
| --- | --- | --- |
| `none` | 无需交付 | 非服务类商品下单即写入（`OrderService.ts:236`） |
| `pending` | 待交付 | 服务类商品下单即写入（同上），**支付前后都是它** |
| `delivered` | 已交付 | 后台「交付」调用 `markFulfilled`（`orderRepo.ts:163-185`） |

状态推进**全部是条件 UPDATE + `affectedRows` 判定**，因此重复回调、重复点击、并发请求都只生效一次：

| mapper 方法 | `where` 条件 | 影响行数为 0 时 |
| --- | --- | --- |
| `markCompleted` | `id = ? and status = 'WP'`（`orderRepo.ts:79`） | 抛内部 `OrderAlreadySettledError`，外层重读后按「已处理」返回（`OrderService.ts:558-576`） |
| `markClosed` | `id = ? and status = 'WP'`（`:99`） | 同上 |
| `markFailed` | `id = ? and status = 'WP'`（`:117`） | 同上 |
| `markFulfilled` | `id = ? and status = 'OD' and fulfill_status = 'pending'`（`:178-182`） | 同上 |

## 五、权限码与菜单

后台接口用 `proc({ permission })` 显式声明权限码，权限码来源是 `sys_menu.code`（规则见[权限模型](/docs/main/reference/rbac)）。本模块共 11 个权限码：

| 模块 | 权限码 | 覆盖的接口 |
| --- | --- | --- |
| 商品管理 | `system:goods:list` | `getOne` / `getById` / `page` / `levelOptions` / `levelPrices`（`modules/goods/index.ts:14,36-59`） |
| | `system:goods:add` | `create` |
| | `system:goods:edit` | `update`、`saveLevelPrices`（等级价与商品编辑共用权限，`:62-65`） |
| | `system:goods:del` | `remove` / `batchDelete` |
| 订单管理 | `system:order:list` | `getOne` / `getById` / `page` / `summary` / `userOptions`（`modules/order/index.ts:21,31-92`） |
| | `system:order:edit` | `update`（只改备注） |
| | `system:order:del` | `remove` / `batchDelete` |
| | `system:order:confirm` | `confirm`（余额单实扣，动钱） |
| | `system:order:close` | `close`（释放冻结/券/库存） |
| | `system:order:sync` | `sync`（外呼渠道并推进状态） |
| | `system:order:fulfill` | `fulfill`（服务交付） |

会员自助接口用 `protectedProcedure`（只要求登录、不要求管理权限，`server/trpc/init.ts:31`）：`myPage` / `myDetail` / `myCreate` / `myConfirm` / `myCancel` / `mySync` / `myPayment`，外加商城浏览 `mallList` / `mallDetail`（`modules/order/index.ts:94-148`）。它们全部在 Service 层做**归属校验**：订单不存在或不属于当前用户统一按「不存在」返回，避免用订单号探测他人订单（`modules/order/SysOrderService.ts:83-96`）。

菜单侧：Part 2 插入的 16 行里，`system:trade` 是目录、`system:goods` / `system:order` / `system:mall` / `system:myOrder` 是 4 个页面菜单（`doc/main/mysql-ddl-goods-order.sql:136,139,146,156,159`）。商城与我的订单**页面本身不做路由级权限拦截**，放进菜单只为演示方便，头像菜单里另有入口（`:127-129`）。

## 六、定时任务

| 项 | 值 | 依据 |
| --- | --- | --- |
| 任务编码 | `order:expire-close` | `doc/main/mysql-ddl-goods-order.sql:174` |
| cron | `0 0/5 * * * *`（每 5 分钟，`Asia/Shanghai`） | 同上 |
| 默认状态 | `status = 0`（**禁用**），需在定时任务页手动启用 | 同上；`doc/main/mysql-ddl-goods-order.sql:163-168` |
| handler | `orderService(db).expireClose()` | `server/sys-router/job/handlers.ts:163-170` |
| 扫描条件 | `status = 'WP' and expire_at <= now`，单次 200 条 | `domain/order/repo/orderRepo.ts:188-199`、`domain/order/types.ts:28` |
| 返回 | `{ scanned, closedCount, recoveredCount, failures }` | `domain/order/types.ts:94-100` |

订单支付窗口由常量 `ORDER_TTL_MINUTES = 15` 决定（`domain/order/types.ts:25`），下单时写入 `expire_at`（`OrderService.ts:209`）。余额单的冻结**不设过期**（`ttlMinutes: 0` → `expire_at = null`），所以这个任务也是余额单唯一的自动释放触发点（`OrderService.ts:266-276`、`domain/wallet/WalletService.ts:526-529`、`domain/order/types.ts:20-25`）。
