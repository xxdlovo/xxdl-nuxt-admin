## 组件总览

扫码支付的前端唯一入口是 `app/components/ScanPay.vue`（组件名 `ScanPay`，已全局自动导入，无需手写 import）。它把「解析渠道 → 统一下单 → 展示二维码/支付链接 → 轮询推进状态」全部封装在内部，调用方只需要给金额和（可选的）渠道。

对外只暴露两个高频参数：`amount` 必填，`channel` 可留空走默认渠道，其余都有默认值。

## 属性

| 属性 | 类型 | 默认值 | 留空或特殊值时的行为 |
| --- | --- | --- | --- |
| `amount` | `number \| string` | 无（必填） | 内部 `Number()` 后必须有限且 `> 0`，否则本地直接报错 `module.system.scanPay.amountRequired`，不发起下单；合法时按两位小数提交 |
| `channel` | `string` | `''` | 空 → 取渠道列表里 `isDefault === 1` 的渠道；匹配不到 → 报 `noDefaultChannel`。非空时按「渠道名（`config_name`）→ 渠道 ID → 渠道编码」顺序匹配，都匹配不到 → 报 `channelNotFound` |
| `outTradeNo` | `string` | `''` | 空 → 后端生成（`PAY` + `yyyyMMddHHmmss` + 6 位随机大写字母数字）；重复订单号会被唯一索引拒绝 |
| `subject` | `string` | `''` | 空 → 用 `module.system.scanPay.title`（「扫码支付」） |
| `attach` | `string` | `''` | 空 → 作为 `undefined` 提交，不下发给渠道 |
| `notifyUrl` | `string` | `''` | 空 → 用渠道配置的 `notify_url`；渠道也没配 → 服务端按当前请求 `origin` 推导 `/api/pay/notify/{渠道}`；仍为空则报 `module.system.payChannel.notifyUrlRequired` |
| `bizType` | `string` | `''` | 空 → 服务端按 `test` 落库；正式业务请显式传入（例如 `recharge`），只有 `test` 订单允许「模拟支付成功」 |
| `pollInterval` | `number` | `5000` | `<= 0` → 完全不自动轮询，只能手动点「查询状态」；实际调度取 `Math.max(pollInterval, 1000)`，小于 1 秒会被抬到 1 秒 |
| `pollTimeout` | `number` | `600000`（10 分钟） | 从开始轮询计时，超时后停止并 `emit('error')` |
| `autoStart` | `boolean` | `false` | `true` 时在 `onMounted` 里自动调用 `create()` |
| `platform` | `'auto' \| 'alipay' \| 'wechat'` | `'auto'` | `auto` 按渠道名与二维码/支付链接推断平台；显式传值则强制使用对应品牌外框。平台只影响展示，不影响下单参数 |
| `showOrderInfo` | `boolean` | `true` | 控制订单号 / 金额 / 标题 / 过期时间四行明细是否渲染 |
| `showTrigger` | `boolean` | `true` | 控制空态下的「生成二维码」按钮。使用方自己有提交按钮时传 `false`，避免两个按钮做同一件事（仍可用 `ref.create()` 触发） |

## 事件与暴露的方法

| 事件 | 载荷 | 触发时机 |
| --- | --- | --- |
| `created` | `order`（订单快照，状态通常是 `WP`） | 下单成功、订单写入 `v-model:order` 之后 |
| `status-change` | `(order, previousStatus)` | 订单状态发生变化时（轮询或主动查询导致），`previousStatus` 首次为 `null` |
| `success` | `order` | 状态由非 `OD` 变为 `OD` 时触发一次 |
| `error` | `message`（已本地化，可直接展示） | 渠道解析失败、下单失败、轮询超时、轮询连续失败 3 次 |
| `update:order` | `order \| null` | 支持 `v-model:order`，父组件可自由读取状态；出错时会置为 `null` |

通过 `defineExpose` 暴露三个方法，配合 `ref` 使用：

| 方法 | 用途 |
| --- | --- |
| `create()` | 重新走一遍「解析渠道 → 下单 → 开始轮询」 |
| `syncStatus()` | 主动查询一次渠道状态并推进本地状态（对应界面上的「查询状态」） |
| `stop()` | 停止自动轮询（组件卸载时也会自动调用） |

`#actions` 插槽用于在使用方注入额外按钮（典型场景是测试页的「模拟支付成功」）。插槽参数为：

| 参数 | 说明 |
| --- | --- |
| `order` | 当前订单快照，可据此判断状态再决定按钮是否显示 |
| `create` | 等同组件内的 `create()` |
| `sync` | 等同 `syncStatus()` |
| `syncing` | 主动查询是否进行中，可直接绑到按钮的 `loading` |

插槽渲染在操作栏末尾、内置的「查询状态」「重新下单」按钮之前。

## 组件内部流程

```text
onMounted(autoStart) / 父组件 ref.create()
   └─ 校验 amount（不合法 → error，结束）
        └─ resolveChannel()
             ├─ 渠道列表为空 → 调一次 sysPayTest.channels.query()，之后复用缓存
             ├─ matchChannel：渠道名 → ID → 渠道编码；channel 为空则取 isDefault === 1
             ├─ 未匹配 → error（channelNotFound / noDefaultChannel）
             └─ matched.verifyStatus !== 1 → error（channelNotVerified）
                  └─ sysPayTest.create.mutate({ channelId, amount, subject, attach, notifyUrl, outTradeNo, bizType })
                       ├─ 成功 → 写入 v-model:order、emit('created')，状态为 WP 则 startPolling()
                       └─ 失败 → v-model:order 置 null、emit('error')
```

- **未测试的渠道不能下单**：组件在 `verifyStatus !== 1` 时直接给出可读文案；服务端 `sysPayTest.create` 有同样的拦截（报 `module.system.payChannel.notVerified`），组件这层只是为了更早、更友好地提示。
- **轮询**：`scheduleNextPoll()` 每次延时 `pollInterval` 后调用 `sysPayTest.syncStatus.mutate`，停止条件为——订单状态不再是 `WP`、累计时长超过 `pollTimeout`（报 `module.system.scanPay.pollTimeout`）、或**连续失败 3 次**（报 `pollFailed`）。失败计数在一次成功后清零，偶发网络抖动不会立即停。
- **服务端 3 秒节流**：`PayOrderService.queryPayment()` 用 `lastQueryAt` 限制对平台的真实调用不低于每 3 秒一次；命中节流时直接返回本地快照，不请求平台。因此默认 5 秒的客户端轮询不会把平台查询接口打爆。
- **二维码区三分支**：有 `qrImageUrl` → 直接渲染图片；只有 `qrContent` → 只读文本框 + 复制按钮（本模块未引入本地二维码渲染依赖，虎皮椒也不会返回该字段）；两者都没有 → 提示 `noQrcode`（有支付链接）或 `noQrcodeNoUrl`（都没有，提示去看订单的「渠道原始数据」）。任何情况下只要有 `payUrl`，都额外渲染「打开支付链接」。
- **公网可达性提醒**：订单的 `notifyUrl` 为空、以 `http://` 开头，或命中 `localhost` / `127.0.0.1` / `0.0.0.0` / `192.168.` / `10.` / `172.16~31.` / `.local` 时，组件展示 `module.system.payTest.notifyUrlWarning` 警告条。

## 平台品牌外框

`platform` 为 `auto`（默认）时，`inferPlatform()` 会把**渠道名、渠道编码、`qrImageUrl`、`payUrl`、`subject`** 拼成一个小写字符串再匹配：

| 命中规则 | 推断结果 |
| --- | --- |
| `/alipay\|支付宝/` | `alipay` |
| `/wechat\|weixin\|wxpay\|微信/` | `wechat` |
| 都不命中 | `null`，不套品牌外框，二维码区只保留默认边框 |

推断结果驱动 `PLATFORM_META`：

| 平台 | 图标 | 主色 | 外框 |
| --- | --- | --- | --- |
| 支付宝 | `i-simple-icons-alipay` | `#1677FF` | `border-[#1677FF]/40 bg-[#1677FF]/5` |
| 微信支付 | `i-simple-icons-wechat` | `#07C160` | `border-[#07C160]/40 bg-[#07C160]/5` |

图标来自项目已内置的 Iconify `simple-icons` 集合，不需要额外依赖。识别到平台且渲染了二维码图片时，下方还会补一句 `module.system.scanPay.scanTip`（「请使用{platform}扫描上方二维码完成支付」）。

## 用法示例

最简：用默认渠道、默认标题、默认 5 秒轮询。

```vue
<ScanPay :amount="0.01" auto-start />
```

指定渠道：`channel` 支持渠道名、渠道 ID、渠道编码三者之一。

```vue
<ScanPay :amount="1" channel="虎皮椒_支付宝" auto-start />
```

受控用法：接管订单对象与各类事件，自定义全部参数。

```vue
<script setup lang="ts">
import type { SysPayTestStatusDTO } from '#shared/system/payTest'

const order = ref<SysPayTestStatusDTO | null>(null)

function onCreated(current: SysPayTestStatusDTO) {
  console.log('订单已创建', current.outTradeNo)
}

function onPaid(current: SysPayTestStatusDTO) {
  console.log('支付成功', current.paidAt)
}

function onError(message: string) {
  console.error(message)
}
</script>

<template>
  <ScanPay
    v-model:order="order"
    :amount="9.9"
    channel="虎皮椒_支付宝"
    out-trade-no="ORDER20261001001"
    subject="会员充值"
    attach="userId=123"
    notify-url="https://example.com/api/pay/notify/xunhupay"
    :poll-interval="3000"
    :poll-timeout="600000"
    @created="onCreated"
    @success="onPaid"
    @error="onError"
  />
</template>
```

## 扫码支付测试页

页面位于 `app/pages/system/pay-test/index.vue`，路由 `/system/pay-test`，左右两栏布局：左栏收集参数，右栏就是 `ScanPay` 组件。

左栏表单：

| 控件 | 说明 |
| --- | --- |
| 渠道 | 下拉来自 `sysPayTest.channels.query()`，选项文案是「配置名（渠道编码 · 币种）」；进入页面后默认选中 `isDefault` 的渠道，没有默认则选第一个 |
| 金额 | `UInputNumber`，范围 `0.01 ~ 99999999.99`，步长 `0.01` |
| 标题 | 必填，默认「扫码支付测试」 |
| 业务备注 | 可留空 |
| 回调地址 | 可留空，帮助文案提示「留空使用渠道配置或自动推导」 |

渠道列表为空时，左栏不渲染表单而是显示 `payTest.noChannel` 警告。提交按钮走的是 `scanPayRef.value?.create()`，并且组件传入 `:show-trigger="false"`，避免出现两个下单按钮。

右栏的额外操作通过 `#actions` 注入「模拟支付成功」：

- 按钮只在 `order.status === 'WP'` 时显示；
- 前端权限：`isAdmin || hasPermission('system:payTest:simulate')`；
- 组件提供的只读开关：`simulateEnabled`（环境开关）与 `simulateSupported`（渠道是否实现 `buildSimulatedNotify`）任一为假则按钮置灰；
- 服务端还有两道拦截：生产环境必须显式设置 `NUXT_PAY_SIMULATE_ENABLED=true`，且订单 `biz_type` 必须是 `test`（否则报 `module.system.payTest.simulateOnlyTest`）；
- 模拟成功后的 toast 会把 `processResult` 一并带出，便于确认走的是「验签 → 幂等 → 金额核对」链路。

## 渠道配置页

页面位于 `app/pages/system/pay-channel/index.vue`，弹窗表单在 `app/pages/system/pay-channel/components/sys-pay-channel-operate.vue`。

**动态表单**：表单不硬编码字段，而是调 `sysPayChannel.providerMetas.query()` 拿到 `providers[].fields`，按 `type`（`text` / `password` / `textarea` / `switch` / 数字）渲染，`label`、`placeholder`、`help` 都是 i18n key，由 `$ts()` 翻译。切换「渠道类型」时会用新渠道的 `fields` 重建表单模型，避免把上一家的密钥写到新渠道。

**密钥留空 = 不修改**：编辑态下密钥字段一律置为空字符串，占位符显示 `module.system.payChannel.secretKeepHint`（「留空表示不修改已保存的密钥」）。服务端 `buildConfigForWrite()` 把「空字符串 / 掩码值」视为不修改：既不覆盖原密文，也不参与 `configSchema` 校验（否则 `min(1)` 会把留空判成失败）。只有本次真正提交的新密钥才参与校验，并且会先检查加密主密钥是否可用。

- 服务端校验只针对本次提交的新值：新增时缺少必填字段报 `configFieldRequired`（消息里列出缺失字段名）；字段类型不合规报 `configInvalid`；切换渠道类型却没提交凭据报 `configRequiredOnTypeChange`。
- **未配置加密 key 的警告**：`providerMetas` 同时返回 `encryptionReady` 与 `encryptionReason`。`encryptionReady` 为假时表单顶部显示警告条，`encryptionReason === 'invalid'` 用 `module.system.payChannel.encryptionInvalid`（格式不对，需要用 `openssl rand -base64 32` 重新生成 `NUXT_PAY_CONFIG_KEY`），否则用 `encryptionMissing`（压根没配置）。

**列表操作**：新增 / 批量删除由 `TableHeaderOperation` 的默认按钮提供（带 `system:payChannel:add`、`system:payChannel:del` 权限）；行内操作按权限渲染「编辑」「测试配置」「设为默认」「删除」。

- 「测试配置」调 `sysPayChannel.verify`，成功用绿色 toast 提示返回文案，失败提示 `verifyFailed` 并把渠道返回的 `message` 作为错误详情展示；刷新后 `verify_status` 徽标会更新（`payChannelVerifyConfig`：未验证 / 已验证 / 验证失败）。
- 「设为默认」调 `sysPayChannel.setDefault`，服务端先清掉其他渠道的默认标记，保证全局唯一。
- 凭据或渠道类型一旦变更，`verify_status` 会被重置为 `0`，必须重新测试。

## 支付记录页与回调日志页

两页都用 `TableWithPagination` + `TableHeaderOperation`，并且都通过**空的默认插槽** `<template #default />` 关掉内置的新增 / 批量删除按钮——支付记录由支付链路写入、回调日志只读，都不允许手工新增。

**支付记录页**（`app/pages/system/pay-order/index.vue`）：

| 项 | 说明 |
| --- | --- |
| 查询条件 | 商户订单号、商品标题、支付渠道、支付状态、业务类型、金额下限 / 上限、创建起始 / 截止 |
| 区间查询 | 日期选择器只取到「日」，提交时补全为 `YYYY-MM-DD 00:00:00` 与 `YYYY-MM-DD 23:59:59` 后再交给后端按字符串区间比较 |
| 列表列 | 序号、商户订单号、支付渠道、金额+币种、支付状态、平台订单号、交易号、支付时间、创建时间 |
| 详情 | 弹窗展示全部字段 + `provider_data` 原始 JSON + 「回调与查询记录」时间线（调 `sysPayOrder.notifyLogs`） |
| 同步状态 | 调 `sysPayOrder.syncStatus`，需要 `system:payOrder:query` 或管理员（主动查询会推进状态，属有副作用的写操作） |
| 关闭 | 仅 `status === 'WP'` 且拥有编辑权限时显示，调 `sysPayOrder.close`；只改本地状态（虎皮椒等平台没有取消接口） |
| 删除 | 需要 `system:payOrder:del` |

**回调日志页**（`app/pages/system/pay-notify-log/index.vue`）：

| 项 | 说明 |
| --- | --- |
| 查询条件 | 商户订单号、支付渠道、来源（平台回调 / 主动查询 / 本地模拟 / 对账任务）、处理结论、本地订单 ID、起始 / 截止时间（同样补全为 `00:00:00` 与 `23:59:59`） |
| 列表列 | 序号、时间、支付渠道、商户订单号、来源、验签、处理结论、金额+币种、幂等键、来源 IP |
| 详情 | 弹窗展示原始报文、原始请求头与处理说明 |
| 删除 | 需要 `system:payNotifyLog:del` |

各 `process_result` 的含义与处置见 `/docs/main/payment/troubleshooting`。

## i18n 键位置

支付模块的全部文案集中在 `app/locales/zh.json` 与 `app/locales/en.json` 的 `module.system` 命名空间下，两份文件的结构一致：

| 键前缀 | 覆盖内容 |
| --- | --- |
| `module.system.payChannel` | 渠道配置页：字段标签、表单占位符、验证状态、加密 key 提示、按钮与错误码 |
| `module.system.payOrder` | 支付记录页：列表列名、订单状态、发起方式、查询条件、操作成功提示与错误码 |
| `module.system.payNotifyLog` | 回调日志页：来源、处理结论、详情字段、查询条件 |
| `module.system.payTest` | 扫码支付测试页：表单、状态提示、模拟支付相关提示与错误码 |
| `module.system.scanPay` | `ScanPay` 组件自身：标题、空态、按钮、平台名、`pollTimeout` / `pollFailed` 等错误文案 |

新增文案时五个前缀都要在 `zh.json` 与 `en.json` 里同时补齐，否则切换语言会出现 key 原文。
