本页覆盖后端的 Step 1 ～ Step 9.1：从建表到 tRPC 路由注册与 RBAC 权限配置，每一步都给出关键代码与易错点。文件级清单见[文件清单与注意事项](/docs/main/new-module/checklist)。

## Step 1：数据库建表

由人工在数据库中执行建表 SQL。项目表结构的统一约定：

```sql
CREATE TABLE `my_business` (
  `id` varchar(36) NOT NULL,
  `field1` varchar(100) DEFAULT NULL,
  `status` tinyint DEFAULT 1,
  `remark` varchar(255) DEFAULT NULL,
  `created_by` varchar(36) DEFAULT NULL,
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_by` varchar(36) DEFAULT NULL,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `is_deleted` tinyint DEFAULT 0,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**必须包含的字段**（缺任何一个都会让通用 Repo 与审计逻辑失效）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `varchar(36)` 主键 | 主键，由 Service 用 `randomUuid()` 生成 |
| `created_by` | `varchar(36)` | 创建人，由 Repo 自动填充 |
| `created_at` | `timestamp` 默认 `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_by` | `varchar(36)` | 更新人，由 Repo 自动填充 |
| `updated_at` | `timestamp` 默认 `CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |
| `is_deleted` | `tinyint` 默认 `0` | 逻辑删除标记 |

完整范例见 `doc/main/mysql-ddl.sql`（含 `sys_user`、`sys_role`、`sys_job` 等全部表的定义）。

> **建表完成并经用户确认后**，才继续后续步骤；如果用户还没执行建表 SQL，先停下来等待。

建完表后确认 `.env` 里的数据库配置正确（`DB_HOST`、`DB_USER`、`DB_PASSWORD`、`DB_DATABASE`），否则 Step 2 的 `db:pull` 会直接失败。

## Step 2：生成 Drizzle Schema

```bash
pnpm db:pull
```

该命令读取数据库结构，输出到 `server/drizzle/out/schema.ts` 与 `server/drizzle/out/relations.ts`。配置见 `server/drizzle/drizzle.config.ts`（`schema: './server/drizzle/schema/*'`、`out: './server/drizzle/out'`、`dialect: 'mysql'`）。

## Step 3：对比并确认新表

从 `out/schema.ts` 里找出本次新增的表，与 `server/drizzle/schema/index.ts` 已导出的表对比，列出新表与字段结构，**向用户确认**后再继续。

复制到目标位置：

- 单级模块：`server/drizzle/schema/<module>/index.ts`（例如 `demo/index.ts`）
- 两级模块：`server/drizzle/schema/system/<业务名>.ts`（例如 `system/user.ts`）

复制时必须清理自动生成文件里的多余 import（`mysqlSchema`、`AnyMySqlColumn`、`sql` 等），只保留实际用到的。

表定义的最小形态：

```typescript
import { mysqlTable, primaryKey, varchar, tinyint, timestamp } from "drizzle-orm/mysql-core"

export const demo = mysqlTable("demo", {
    id: varchar({ length: 36 }).notNull(),
    status: tinyint().default(1),
    remark: varchar({ length: 255 }),
    createdBy: varchar("created_by", { length: 36 }),
    createdAt: timestamp("created_at", { mode: 'string' }).defaultNow().notNull(),
    updatedBy: varchar("updated_by", { length: 36 }),
    updatedAt: timestamp("updated_at", { mode: 'string' }).defaultNow().onUpdateNow().notNull(),
    isDeleted: tinyint("is_deleted").default(0),
    field1: varchar({ length: 100 }),
    field2: varchar({ length: 100 }),
},
(table) => [
    primaryKey({ columns: [table.id], name: "demo_id" }),
]);
```

## Step 4：在 Schema Index 中导出

在 `server/drizzle/schema/index.ts` 添加 import 与 export。变量名规则：**表名 snake_case → 小驼峰**。

| 数据库表名 | Drizzle 变量名 | 模块路径 |
| --- | --- | --- |
| `demo` | `demo` | `demo/index.ts` |
| `sys_user` | `sysUser` | `system/user.ts` |
| `sys_role` | `sysRole` | `system/role.ts` |

```typescript
import { demo } from "./demo/index"
import { sysUser } from "./system/user"

export {
  demo,
  sysUser,
  // ... 其他表
};
```

> 如果表名无法直观推断出小驼峰变量名，先向用户确认，不要自行猜测。

## Step 5：创建共享类型（`shared/<module>/`）

四个文件，全部放在 `shared/<module>/` 下：

### 5.1 `common.ts` — 基础 Schema

```typescript
import z from 'zod'

export const DemoBaseSchema = z.object({
    id: z.string().nullish(),
    field1: z.string().nullish().meta({ query: 'like' }),
    field2: z.string().nullish().meta({ query: 'like' }),
    status: z.number().nullish(),
    remark: z.string().nullish().meta({ query: 'like' }),
    createdBy: z.string().nullish(),
    createdAt: z.string().nullish(),
    updatedBy: z.string().nullish(),
    updatedAt: z.string().nullish(),
    isDeleted: z.number().nullish(),
})
export type DemoDto = z.infer<typeof DemoBaseSchema>
```

关键约定：

- 需要模糊查询的字段加 `.meta({ query: 'like' })`，后端 `buildWhereBySchema` 会自动生成 `LIKE %xxx%`；精确匹配字段不加。
- BaseSchema 里所有字段统一 `.nullish()`，便于 `pick()` / `extend()` 复用；必填规则在 `input.ts` / `output.ts` 里覆盖。

### 5.2 `input.ts` — 增删改查 DTO

```typescript
import { z } from 'zod'
import { DemoBaseSchema } from './common'
import { ApiRequestSchema } from "#shared/types/common"

// 新增
export const DemoAddSchema =
    DemoBaseSchema.pick({
        field1: true,
        field2: true,
        status: true,
        remark: true,
    }).extend({
        id: DemoBaseSchema.shape.id.nonoptional()
    })
export type DemoAddDTO = z.infer<typeof DemoAddSchema>

// 修改：在新增基础上让 id 必填
export const DemoUpdateSchema = DemoAddSchema.extend({
    id: z.string().nonempty('form.id.required'),
})
export type DemoUpdateDTO = z.infer<typeof DemoUpdateSchema>

// 查询条件
export const DemoQuerySchema = DemoBaseSchema.pick({
    id: true,
    field1: true,
    field2: true,
    status: true,
    remark: true,
})
export type DemoQueryDTO = z.infer<typeof DemoQuerySchema>

// 分页查询：查询条件 + 分页参数
export const DemoPageQuerySchema =
    DemoQuerySchema.extend(ApiRequestSchema.shape)
export type DemoPageQueryDTO = z.infer<typeof DemoPageQuerySchema>
```

### 5.3 `output.ts` — 输出 Schema（可选）

仅当需要裁剪或定制响应字段时才写，否则可省略。

```typescript
import { DemoBaseSchema } from './common'
import { z } from 'zod'

export const DemoRespSchema = z.object({
    id: DemoBaseSchema.shape.id,
    field1: DemoBaseSchema.shape.field1,
    field2: DemoBaseSchema.shape.field2,
    status: DemoBaseSchema.shape.status,
    remark: DemoBaseSchema.shape.remark,
});
export type DemoRespDTO = z.infer<typeof DemoRespSchema>;
```

### 5.4 `index.ts` — 统一导出

```typescript
export * from './common'
export * from './input'
export * from './output'
```

## Step 6：创建后端 Repo

路径 `server/sys-router/<模块>/<Business>Repo.ts`，最短的写法只有两行：

```typescript
import { CommonRepo } from "#server/drizzle/CommonRepo";
import { DemoBaseSchema } from "#shared/demo/common";
import { demo } from "~~/server/drizzle/schema";

export const demoRepo = CommonRepo(demo, DemoBaseSchema)
```

原理：`CommonRepo(table, schema?)` 是一个工厂，返回 `(ctx) => repo`。它自动提供 `list` / `page` / `getOne` / `getById` / `create` / `updateById` / `remove` / `batchRemove`，并且：

- 所有查询都会经过 `buildScopedWhere`，自动叠加数据权限条件；
- `buildWhereBySchema` 会把 Zod Schema 里的 `.meta({ query: 'like' })` 解析为模糊查询；
- 新增与更新会自动补 `createdBy` / `updatedBy` / `isDeleted` 等审计字段（仅当表中确实有这些列），更新时不会覆盖 `createdBy` / `createdAt` / `isDeleted`；
- `remove` / `batchRemove` 都是软删除（置 `isDeleted = 1`）。

需要额外查询时，在工厂结果外再包一层（参考 `server/sys-router/oss/SysOssRepo.ts` 的 `createUploadRecord`）：

```typescript
export const sysOssRepo = (ctx: Context) => {
    const base = CommonRepo(sysOss, SysOssBaseSchema)(ctx)
    return {
        ...base,
        async createUploadRecord(record: SysOssUploadRecord) {
            // 自定义写入逻辑
        }
    }
}
```

## Step 7：创建后端 Service

路径 `server/sys-router/<模块>/<Business>Service.ts`。Service 承载业务规则与抛错，固定 7 个方法：

```typescript
import { useLogger } from 'evlog'
import { demoRepo } from './DemoRepo'
import type { Context } from '#server/trpc/context';
import { AppError } from '#server/utils/appError'
import type { OrmPageResp } from '#server/utils/ApiResp'
import type { DemoAddDTO, DemoDto, DemoPageQueryDTO, DemoQueryDTO, DemoUpdateDTO } from "#shared/demo";
import { randomUuid } from "#shared/utils/uuid";

export function demoService(ctx: Context) {
    const repo = demoRepo(ctx)
    // evlog 宽事件：只记动作与标识（id / 条数），不打印完整入参出参
    const log = useLogger(ctx.event, 'server/demo-router')

    return {
        async create(data: DemoAddDTO): Promise<boolean> {
            const uuid = randomUuid()
            const pojo = { ...data, id: uuid }
            await repo.create(pojo)
            log.info('demo created', { demo: { action: 'create', id: uuid } })
            return true
        },
        async remove(id: string): Promise<boolean> {
            await repo.remove(id)
            log.info('demo removed', { demo: { action: 'remove', id } })
            return true
        },
        async batchRemove(ids: string[]): Promise<number> {
            await repo.batchRemove(ids)
            log.info('demo batch removed', { demo: { action: 'batchRemove', count: ids.length } })
            return ids.length
        },
        async updateById(id: string, data: DemoUpdateDTO): Promise<boolean> {
            await repo.updateById(id, data)
            log.info('demo updated', { demo: { action: 'update', id } })
            return true
        },
        async getOne(req: DemoQueryDTO): Promise<DemoDto> {
            const pojo = await repo.getOne(req)
            if (!pojo) throw new AppError('common.notExist')
            log.info('demo fetched', { demo: { action: 'getOne' } })
            return pojo
        },
        async getById(id: string): Promise<DemoDto> {
            const pojo = await repo.getById(id)
            if (!pojo) throw new AppError('common.notExist')
            log.info('demo fetched', { demo: { action: 'getById', id } })
            return pojo
        },
        async page(req: DemoPageQueryDTO): Promise<OrmPageResp> {
            const { page, pageSize, ...dto } = req
            const result = await repo.page(page, pageSize, dto)
            log.info('demo page queried', { demo: { action: 'page', page, pageSize, total: result.total } })
            return result
        },
        async list(dto: any): Promise<DemoDto[]> {
            const list = await repo.list(dto)
            log.info('demo listed', { demo: { action: 'list', count: list.length } })
            return list
        },
    }
}
```

要点：

- **主键由 Service 用 `randomUuid()` 生成**，前端不需要传 id。
- 查不到数据时抛 `new AppError('common.notExist')`，不要自己拼中文文案。
- `ctx` 是 tRPC 上下文，Repo 与 Service 都通过 `ctx` 拿到数据库连接与当前用户。
- **每个方法都要打一条 evlog 日志**（见下方 Step 7.1），只记动作与标识。

### 7.1 evlog 日志打印

每个 Service 方法都要往请求宽事件里追加一条日志，写法固定：

| 约定 | 说明 |
| --- | --- |
| 取 logger | `const log = useLogger(ctx.event, 'server/<模块路径>')`；第二个参数覆盖事件里的 `service`，日志中显示具体模块而不是全局应用名 |
| 日志字段名 | 用模块目录名（`notice`、`user`、`goods`…），与 tRPC 命名空间区分开 |
| 写操作 | `log.info('<模块> created' / 'removed' / 'updated', { <模块>: { action, id } })`；批量删除记 `count`，**不要**记 `ids` 数组 |
| 查询 | `log.info('<模块> fetched' / 'page queried', { <模块>: { action } })`；分页可带 `page` / `pageSize` / `total` |
| 位置 | 写在 `await repo.*` **之后**：记录的是「确实执行成功」的事实，失败由 tRPC / Nitro 的错误链路记录 |
| 禁止 | 不打印完整入参出参（`data`、`req`、`dto`、`pojo`、`list`、`result` 整体），不打印密码、token、密钥等敏感字段 |

几个补充说明：

- 宽事件由 evlog 的 Nitro 插件在请求开始时创建、响应结束时自动输出，业务代码只负责追加字段；**一个请求只会产生一条事件**，所以查询方法加日志不会额外产生日志行；
- 查询未命中走 `throw new AppError('common.notExist')` 的分支不加日志，事件的 `status` 会体现 404；
- 日志文件位置、等级过滤、检索方式见[运行时日志](/docs/main/backend-handbook/runtime-logs)；
- 领域服务（`server/trade-router/domain/` 下，入参是 `db`/`executor` 的那类）没有 `ctx`，用 `server/utils/evlogLogger.ts` 的 `resolveLogger()` 取 logger，且只记写操作 —— 见[运行时日志 · 领域服务怎么取 logger](/docs/main/backend-handbook/runtime-logs)。


## Step 8：创建后端 Router

路径 `server/sys-router/<模块>/index.ts`。

**资源码规则**：模块名把 `/` 换成 `:`，例如 `system/user` → `system:user`；四个标准权限码是 `<resource>:list` / `<resource>:add` / `<resource>:edit` / `<resource>:del`。

在文件顶部显式声明四个 procedure，再在路由里引用。**不要使用 `crudPermissionProcedures` 工厂** —— 隐式拼接权限码不利于检索，项目已统一改为显式写法。

```typescript
//#server/demo-router
import { router, proc } from '~~/server/trpc/init'
import { demoService } from './DemoService'
import z from 'zod'
import {
    DemoAddSchema,
    DemoUpdateSchema,
    DemoQuerySchema,
    DemoPageQuerySchema
} from '#shared/demo'

const listProc = proc({ permission: 'demo:list' })
const addProc = proc({ permission: 'demo:add' })
const editProc = proc({ permission: 'demo:edit' })
const delProc = proc({ permission: 'demo:del' })

export const demoRouter = router({
    create: addProc.input(DemoAddSchema)
        .mutation(async ({ ctx, input }) => {
            return demoService(ctx).create(input)
        }),
    remove: delProc.input(z.string())
        .mutation(async ({ ctx, input }) => {
            return demoService(ctx).remove(input)
        }),
    batchDelete: delProc.input(z.array(z.string()))
        .mutation(async ({ ctx, input }) => {
            return demoService(ctx).batchRemove(input)
        }),
    update: editProc.input(DemoUpdateSchema)
        .mutation(async ({ ctx, input }) => {
            return demoService(ctx).updateById(input.id, input)
        }),
    getOne: listProc.input(DemoQuerySchema)
        .query(async ({ ctx, input }) => {
            return demoService(ctx).getOne(input)
        }),
    getById: listProc.input(z.string())
        .query(async ({ ctx, input }) => {
            return demoService(ctx).getById(input)
        }),
    page: listProc.input(DemoPageQuerySchema)
        .query(async ({ ctx, input }) => {
            return demoService(ctx).page(input)
        })
})
```

固定 7 个接口方法（`create` / `remove` / `batchDelete` / `update` / `getOne` / `getById` / `page`），保证一致性：查询类统一用 `listProc`，新增用 `addProc`，修改用 `editProc`，删除与批量删除用 `delProc`。

## Step 8.1：操作类型与 `proc()` 参数

### 操作类型逐条核对

| 操作类型 | 用于哪些接口 |
| --- | --- |
| `.query()` | `getOne`、`getById`、`page`、`list`（纯读取，无副作用） |
| `.mutation()` | `create`、`update`、`remove`、`batchDelete` |

> **常见错误**：把只做查询的接口写成 `.mutation()`（例如内部只调用 `getById` 的统计/调试接口）。生成后逐个核对，读接口一律 `.query()`。

### `proc()` 只传 `permission`

| 参数 | 是否需要显式声明 | 说明 |
| --- | --- | --- |
| `permission` | **必传** | 权限码，规则见上 |
| `readonly` | 一般不传 | `NUXT_DEMO_MODE=true` 时由它统一决定，mutation 自动受保护 |
| `log` | 一般不传 | 不传时按操作类型决定：mutation 记录、query 跳过。需要审计查询时显式传 `log: true` |
| `dataScope` | 仅特殊接口传 | 默认应用数据权限。列表接口需要完整数据（树结构、选择器、授权）时传 `dataScope: false` **并加注释说明原因** |

```typescript
// 角色列表类接口需要完整角色数据（用于选择器/授权），不做数据范围限制
// 参考实现：server/sys-router/role、server/sys-router/dept
const listProc = proc({ permission: 'system:role:list', dataScope: false })
```

### 控制器格式化规范

`.input(...)` 与 `.query(...)` / `.mutation(...)` **分两行书写**，方法体三行展开，不要压成单行链式：

```typescript
// ✅ 正确
page: listProc.input(DemoPageQuerySchema)
    .query(async ({ ctx, input }) => {
        return demoService(ctx).page(input)
    }),

// ❌ 错误：后续加逻辑容易出错
page: listProc.input(DemoPageQuerySchema).query(({ ctx, input }) => demoService(ctx).page(input)),
```

另外：import 语句一行一个来源；从同一模块导入多个符号时用多行花括号；文件首行保留 `//#server/<模块>-router` 定位注释。

## Step 9：注册 tRPC Router

在 `server/trpc/routers.ts` 的 `appRouter` 中加入新命名空间：

```typescript
import { router } from '~~/server/trpc/init'
import { demoRouter } from '#server/demo-router'

export const appRouter = router({
    // ... 已有路由
    demo: demoRouter,
});

export type AppRouter = typeof appRouter;
```

注册名即前端调用前缀：注册成 `sysOauthAccount`，前端就要写 `$trpc.sysOauthAccount.page.query()`。

## Step 9.1：配置 RBAC 菜单与按钮权限

接口级权限与前端按钮权限都依赖 `sys_menu.code`，**必须同步写入权限码**，否则普通用户即使分配了角色也访问不到接口。

```sql
-- 页面菜单：侧边栏入口 + 页面访问
INSERT INTO sys_menu
  (id, parent_id, name, code, type, path, component, icon, sort_order, visible, status, remark, created_by, updated_by, is_deleted)
VALUES
  ('<menu_id>', '<parent_dir_id>', 'Demo管理', 'demo:list', 1, '/demo', 'demo/index', 'i-lucide-table', 40, 0, 1, 'Demo列表权限', '<admin_id>', '<admin_id>', 0);

-- 按钮权限：新增 / 编辑 / 删除按钮与接口鉴权
INSERT INTO sys_menu
  (id, parent_id, name, code, type, path, component, icon, sort_order, visible, status, remark, created_by, updated_by, is_deleted)
VALUES
  ('<add_id>', '<menu_id>', 'Demo新增', 'demo:add', 2, NULL, NULL, NULL, 1, 1, 1, 'Demo新增权限', '<admin_id>', '<admin_id>', 0),
  ('<edit_id>', '<menu_id>', 'Demo编辑', 'demo:edit', 2, NULL, NULL, NULL, 2, 1, 1, 'Demo编辑权限', '<admin_id>', '<admin_id>', 0),
  ('<del_id>', '<menu_id>', 'Demo删除', 'demo:del', 2, NULL, NULL, NULL, 3, 1, 1, 'Demo删除权限', '<admin_id>', '<admin_id>', 0);
```

`type` 与 `visible` 的取值：

| 层级 | `type` | `visible` | 说明 |
| --- | --- | --- | --- |
| 目录 | `0` | `0` | 仅作为父节点分组，如「系统管理」「文件管理」，无 `path`/`component` |
| 页面菜单 | `1` | `0` | 侧边栏可见入口，`path` 指向路由，`component` 指向 `app/pages` 下的相对路径 |
| 按钮权限 | `2` | `1` | `path`/`component` 留空，只提供 `code` 供接口与按钮鉴权 |

页面菜单需要先在 `sys_menu` 中找到合适的父目录作为 `parent_id`；也可以直接在后台的菜单管理页里维护。
