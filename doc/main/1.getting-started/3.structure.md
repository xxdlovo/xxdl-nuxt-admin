项目根目录分为四个主要区域：前端 `app/`、后端 `server/`、前后端共享契约 `shared/`、文档 `doc/main/`。下面是代表性的目录树（同类系统模块只列一次，其余按同一模式重复）。

## 一、总览

```text
.
├── app/                      # 前端（页面、组件、布局、状态、插件）
├── server/                   # 后端（tRPC、Drizzle、任务、原生接口）
├── shared/                   # 前后端共享的类型、Zod Schema、权限码、工具
├── doc/                      # 多套文档的根目录
│   ├── main/                 # 默认系统文档源文件
│   └── moduleA/              # 业务 A 文档源文件
├── scripts/                  # 独立脚本（管理员初始化、测试类型检查）
├── tests/                    # Vitest 测试
├── public/                   # 静态资源（图片等）
├── nuxt.config.ts            # Nuxt 配置（模块、runtimeConfig、nitro、i18n）
├── content.config.ts         # Nuxt Content 集合定义（指向 doc/main/）
├── vitest.config.ts          # 测试配置
├── Dockerfile                # 镜像构建
└── package.json              # 依赖与脚本
```

## 二、前端 `app/`

```text
app/
├── app.vue                   # 应用根组件
├── app.config.ts             # Nuxt UI 应用级配置（主题、toaster 等）
├── assets/                   # css / icons / imgs
├── components/               # 全局公共组件（自动注册）
│   ├── base/                 #   BaseSearch、BaseWatermark、BaseThemePick …
│   ├── table/                #   TableWithPagination、TableHeaderOperation、TableColumnSetting
│   ├── u/                    #   BaseInput 等对 Nuxt UI 的二次封装
│   ├── Popconfirm.vue
│   ├── SplitLayout.vue
│   └── UserProfile.vue
├── composables/              # 组合式函数（自动导入）
│   ├── useTable/             #   表格与 CRUD 相关 hooks
│   ├── useCrudPermissions.ts #   前端 CRUD 权限
│   ├── useRbacProfile.ts     #   权限集合与登录用户
│   ├── useDict.ts            #   字典读取
│   ├── useConfig.ts          #   系统配置读取
│   ├── useZodValidation.ts   #   表单校验与消息翻译
│   ├── useLayoutMode.ts      #   布局模式
│   └── useThemeColors.ts     #   主题色
├── features/landing/         # 落地页相关资源
├── layouts/                  # 布局
│   ├── default.vue / system.vue / docs.vue / landing.vue
│   └── modules/              #   布局内的功能块（header/sider/tab/theme-drawer …）
├── locales/                  # 国际化词条（zh.json / en.json 为手写落点）
├── middleware/               # 路由中间件
├── pages/                    # 文件路由
│   ├── login.vue / register.vue
│   ├── demo/                 #   最小示例模块（含完整的增删改查页面）
│   ├── docs/                 #   文档站路由（/docs/main/**）
│   ├── landing/              #   落地页
│   ├── show-case/            #   示例页
│   └── system/               #   后台模块页面（user、role、menu、dept、job …）
├── plugins/                  # Nuxt 插件（tRPC 客户端、错误处理、权限）
├── stores/                   # Pinia store（dict、rbacProfile）
├── types/                    # 前端类型
└── utils/                    # 前端工具（common、navigation、toast）
```

约定：

- 页面按模块分目录，目录名与后端模块名一致，例如 `app/pages/system/user/`。
- 模块自己的局部组件放在该模块的 `components/` 子目录，命名带模块前缀，例如 `sys-user-search.vue`。
- 跨模块复用的组件才上提到 `app/components/`。
- `layouts/modules/**` 下的组件**不会**被注册为布局（`nuxt.config.ts` 的 `app:resolve` hook 会过滤掉它们），这是为了保留 HMR，同时避免它们出现在布局选择列表里。
- `app/locales/pages/**` 是 `nuxt-i18n-micro` 构建时生成的产物，手写内容会被覆盖。

## 三、后端 `server/`

```text
server/
├── api/                      # 原生 Nitro 接口
│   ├── trpc/[trpc].ts        #   tRPC 统一入口
│   └── system/               #   非 tRPC 接口（如 oss 上传、头像上传）
├── assets/                   # Nitro 资源挂载（assets:server）
│   └── storage/              #   只读资源桶根目录
├── demo-router/              # 最小示例模块（router/service/repo）
├── drizzle/                  # 数据层
│   ├── db.ts                 #   useDb() 数据库连接
│   ├── CommonRepo.ts         #   通用查询封装
│   ├── drizzle.config.ts     #   db:push / db:pull 配置
│   ├── queries/              #   复杂查询片段
│   └── schema/               #   表结构定义（demo/ 与 system/ 分组）
├── routes/auth/              # 认证相关的原生路由
├── storage/                  # 本地存储目录（当前仅占位文件）
├── sys-router/               # 业务模块（每个模块一个目录）
│   ├── auth/ config/ dept/ dictData/ dictType/
│   ├── job/ jobLog/ loginLog/ menu/ notice/
│   ├── oauthAccount/ oauthConfig/ oss/ ossConfig/
│   ├── role/ roleMenu/ systemLog/ user/ userRole/
│   └── storage/              #   存储管理 + cache/ 缓存门面
├── tasks/sys-job/            # Nitro 任务（定时任务派发与执行）
├── trpc/                     # tRPC 基础设施
│   ├── context.ts            #   请求上下文
│   ├── errorFormatter.ts     #   错误归一化与翻译
│   ├── init.ts               #   proc() 工厂与各类 procedure
│   ├── routers.ts            #   appRouter 注册
│   └── middlewares/          #   logger / auth / permission / demo / dataScope
└── utils/                    # 服务端工具（AppError、翻译、日志、密码）
```

约定：

- 每个业务模块一个目录，标准构成是 `<模块>/index.ts`（tRPC 路由）+ `<业务>Repo.ts`（数据访问）+ `<业务>Service.ts`（业务逻辑），按需再增加 `cache/`、`providers/`。
- 模块前缀统一用 `sys`，例如 `sysUser`、`sysJob`。
- 跨模块复用的服务端工具放在 `server/utils/`。

## 四、共享层 `shared/`

```text
shared/
├── auth/                     # 权限码生成（permission.ts）、RBAC 常量（rbac.ts）
├── constants/business.ts     # 业务常量
├── demo/                     # 示例模块的类型与 Schema
├── system/<模块>/            # 每个模块的 common / input / output / index
├── types/                    # 通用类型（common/、nuxtui/、auth.d.ts）
└── utils/                    # randomUuid、通用函数、klona
```

约定：**所有前后端共用的数据契约都放这里**。前端用它做表单校验与类型提示，后端用它做 `.input()` 校验与返回值类型；不要放依赖 Node.js API 的代码，因为它会被前端打包引用。

## 五、文档 `doc/main/`

```text
doc/main/
├── index.md                  # 文档门户
├── 1.getting-started/        # 快速开始（本分组）
├── 2.frontend-handbook/      # 前端手册
├── 3.backend-handbook/       # 后端手册
├── 4.new-module/             # 新建模块（模块代码生成与 14 步流程）
├── 5.features/               # 功能组件（错误 / 文件 / 缓存）
├── 6.scheduled-jobs/         # 定时任务
├── 7.reference/              # 参考手册
├── mysql-ddl.sql             # 建表脚本
├── init.sql                  # 初始化数据脚本
└── mock_sql/                 # 演示数据参考脚本
```

- 只有 `.md` 与 `.yml` 会被 Nuxt Content 收集成页面，`.sql` 等文件只作为附件存在。
- 目录名前缀数字决定侧栏顺序，分组标题与图标来自各级 `.navigation.yml`。
- 新增文档页的完整规则见[文档站维护](/docs/main/getting-started/docs-guide)。

## 六、命名对照速查

| 层 | 示例 | 规则 |
| --- | --- | --- |
| 数据库表 | `sys_user` | snake_case，系统表加 `sys_` 前缀 |
| Drizzle 导出 | `sysUser` | camelCase |
| 模块目录 | `server/sys-router/user` | 与页面前缀一致 |
| 前端页面 | `app/pages/system/user/index.vue` | 模块名对应目录 |
| 路由命名空间 | `sysUser` | `$trpc.sysUser.page.query()` |
| 权限码 | `system:user:list` | `<resource>:<action>` |
| 翻译 key | `module.system.user.title` | 与模块路径对应 |
