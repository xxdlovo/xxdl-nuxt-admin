## 两层职责

- **Repo**：只做数据访问。默认 CRUD 直接复用 `CommonRepo`，需要联表、聚合或特殊列裁剪时在工厂基础上扩展。
- **Service**：业务规则的唯一入口。校验业务约束、生成主键、调用 Repo、抛业务错误、失效相关缓存。

Router 层不写业务，Service 不写 SQL，Repo 不做业务判断。

## CommonRepo 工厂

`server/drizzle/CommonRepo.ts` 提供标准的 CRUD 仓储工厂：

```ts
import { CommonRepo } from "#server/drizzle/CommonRepo"
import { DemoBaseSchema } from "#shared/demo/common"
import { demo } from "~~/server/drizzle/schema"

export const demoRepo = CommonRepo(demo, DemoBaseSchema)
```

`CommonRepo(table, schema?)` 返回的是一个 **接受 `ctx` 的函数**，调用后才拿到仓储实例：

```ts
const repo = demoRepo(ctx)
```

### 提供的方法

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `list` | `list(dto = {}, orderBy = [], extraWhere = [])` | 条件查询，返回数组 |
| `page` | `page(page, pageSize, dto, orderBy = [], extraWhere = [])` | 分页查询，返回 `{ total, page, pageSize, list }` |
| `getOne` | `getOne(req)` | 按条件取一条，返回记录或 `null` |
| `getById` | `getById(id)` | 按主键取一条，返回记录或 `null` |
| `create` | `create(data)` | 新增，自动补审计字段 |
| `updateById` | `updateById(id, data)` | 按主键更新，自动剥离创建期审计字段 |
| `remove` | `remove(id)` | 按主键逻辑删除 |
| `batchRemove` | `batchRemove(ids)` | 批量逻辑删除，空数组直接返回 `0` |

### 条件自动生成

传入第二个参数 `schema` 后，`list` / `page` / `getOne` 会用 `buildWhereBySchema(schema, table, dto)` 自动生成查询条件：

- 字段值 `undefined` / `null` / 空字符串会被跳过，空条件不会污染 SQL。
- 默认按等值匹配；schema 字段上声明了 `meta({ query: 'like' })` 时改为 `LIKE '%value%'`。
- 表里不存在的字段会被忽略，因此 DTO 可以比表字段更宽。

### 所有查询都会叠加数据权限

每个方法最终都通过 `buildScopedWhere(table, ctx, ...条件)` 生成 where，它由 `mergeWhere` 用 `AND` 合并三类条件：

1. 系统条件：`is_deleted = 0`（表存在该字段时）。
2. 数据权限条件：按当前用户角色解析出的部门范围 / 本人范围。
3. 业务条件：`buildWhereBySchema` 生成的条件与调用方传入的 `extraWhere`。

数据权限细节见[上下文与鉴权](/docs/main/backend-handbook/context-auth)。

### 审计字段自动填充

| 场景 | 行为 |
| --- | --- |
| 新增 | 有 `isDeleted` 字段则置 `0`；`createdBy` / `updatedBy` 为空时写入当前操作人 |
| 更新 | 强制剥离 `createdBy` / `createdAt` / `isDeleted`，只写 `updatedBy`，避免普通更新篡改创建信息或误恢复已删除数据 |
| 删除 | 写入 `isDeleted = 1` 与 `updatedBy`，即逻辑删除 |

操作人统一取 `ctx.user?.id ?? null`——定时任务等无登录上下文时写入 `null`，不会报错。表如果没有对应字段则跳过写入，因此不是每个表都必须定义完整审计字段。

## 两种 Repo 写法

### 写法一：直接导出工厂结果（推荐用于纯 CRUD）

```ts
// server/demo-router/DemoRepo.ts
import { CommonRepo } from "#server/drizzle/CommonRepo";
import { DemoBaseSchema } from "#shared/demo/common";
import { demo } from "~~/server/drizzle/schema";
export const demoRepo = CommonRepo(demo, DemoBaseSchema)
```

### 写法二：包一层扩展自定义方法

```ts
// server/sys-router/oss/SysOssRepo.ts
const baseRepo = CommonRepo(sysOss, SysOssBaseSchema)

export const sysOssRepo = (ctx: Context) => {
    const base = baseRepo(ctx)

    return {
        ...base,
        async createUploadRecord(data: InferInsertModel<typeof sysOss>) {
            return base.create(data)
        }
    }
}
```

`...base` 保留全部标准能力，再追加模块特有查询。当自定义查询需要联表或裁剪列时，同样使用 `buildScopedWhere` + `buildWhereBySchema` 手写，保证数据权限不丢失：

```ts
// server/sys-router/user/SysUserRepo.ts（节选）
async pageWithDept(page: number, pageSize: number, dto: any) {
  const offset = (page - 1) * pageSize
  const dynamicWhere = buildWhereBySchema(SysUserBaseSchema, sysUser, dto)
  const where = await buildScopedWhere(sysUser, ctx, ...dynamicWhere)
  // 再自行 count + leftJoin 查询并返回 { total, page, pageSize, list }
}
```

> 手写查询时不要绕开 `buildScopedWhere`，否则该接口会绕过数据权限与逻辑删除过滤。

## Service 约定

统一形态是「工厂函数 + 返回方法对象」，入参固定为 `ctx`：

```ts
// server/demo-router/DemoService.ts（节选）
export function demoService(ctx: Context) {
    const repo = demoRepo(ctx)

    return {
        async create(data: DemoAddDTO): Promise<boolean> {
            const uuid = randomUuid()
            await repo.create({ ...data, id: uuid })
            return true
        },
        async getById(id: string): Promise<DemoDto> {
            const pojo = await repo.getById(id)
            if (!pojo) {
                throw new AppError('common.notExist')
            }
            return pojo
        },
        async page(req: DemoPageQueryDTO): Promise<OrmPageResp> {
            const { page, pageSize, ...dto } = req
            return await repo.page(page, pageSize, dto)
        },
    }
}
```

固定套路：

| 场景 | 约定 |
| --- | --- |
| 主键 | `randomUuid()` 生成，Service 负责拼进 data，Repo 不生成主键 |
| 查询未命中 | 抛 `AppError('common.notExist')`，不要返回 `null` 给前端 |
| 分页 | 解构出 `page` / `pageSize`，其余字段作为查询 dto 传给 Repo，返回 `OrmPageResp` |
| 批量删除 | 返回受影响条数（`ids.length` 或 Repo 结果） |
| 写操作返回值 | 常规 CRUD 返回 `boolean`，需要返回完整记录时返回 DTO |
| 业务校验 | 放在 Service，例如定时任务会校验 handler 存在、时区支持与 cron 合法性 |

业务校验示例（`SysJobService`）：`validateTask()` 依次校验 `handlerCode` 是否已注册、`cronTimezone` 是否为 `Asia/Shanghai`、cron 表达式能否解析，任意一项不通过就抛对应的 `AppError`，校验通过后才写库。

## 新增一个模块的顺序

1. `shared/<模块>/` 补 BaseSchema、Input/Output schema 与 DTO 类型。
2. `server/drizzle/schema/` 定义表并在 `schema/index.ts` 导出。
3. `<模块>Repo.ts` 用 `CommonRepo` 建仓储，需要扩展就包一层。
4. `<模块>Service.ts` 写业务方法，查询未命中抛 `common.notExist`。
5. `<模块>/index.ts` 声明 tRPC 路由并注册到 `appRouter`。
6. 前端按 `$trpc.<模块>.<方法>` 调用。
