## schema 目录结构

表定义放在 `server/drizzle/schema`，按业务归属分目录：

```text
server/drizzle/
├── schema/
│   ├── index.ts          # 汇总导入并统一导出所有表
│   ├── system/           # 系统模块表：user、role、menu、dept、dict、job、oss、log 等
│   └── demo/             # 示例模块表
├── queries/              # 查询条件构建器（buildScope 等）
├── out/                  # drizzle-kit 生成物目录
├── CommonRepo.ts         # 通用 CRUD 仓储工厂
├── db.ts                 # mysql2 连接池 + drizzle 实例
└── drizzle.config.ts     # drizzle-kit 配置
```

每个表一个文件，例如：

- `server/drizzle/schema/system/user.ts` → `sysUser`
- `server/drizzle/schema/system/job.ts` → `sysJob`
- `server/drizzle/schema/system/jobLog.ts` → `sysJobLog`
- `server/drizzle/schema/demo/index.ts` → `demo`

### 汇总导出是必须的一步

`drizzle.config.ts` 的 `schema` 配置是 `'./server/drizzle/schema/*'`，只匹配一级文件，不会递归扫描 `system/`、`demo/`。因此新建表后必须在 `server/drizzle/schema/index.ts` 中 import 并加入导出列表，否则该表不会被 drizzle-kit 识别，业务里也拿不到 `ctx.db` 的类型提示：

```ts
// server/drizzle/schema/index.ts
import { sysJob } from "./system/job"
import { demo } from "./demo/index"

export {
  demo,
  sysJob,
  // ...其余表
}
```

## 表定义写法

```ts
// server/drizzle/schema/demo/index.ts
import { mysqlTable, primaryKey, varchar, tinyint, timestamp } from "drizzle-orm/mysql-core"

export const demo = mysqlTable("demo", {
  id: varchar({ length: 36 }).notNull(),
  status: tinyint().default(1),
  remark: varchar({ length: 255 }),
  createdBy: varchar("created_by", { length: 36 }),
  createdAt: timestamp("created_at", { mode: 'string' }).defaultNow().notNull(),
  updatedBy: varchar("updated_by", { length: 36 }),
  updatedAt: timestamp("updated_at", { mode: 'string' }).defaultNow().onUpdateNow().notNull(),
  isDeleted: tinyint("is_deleted").default(0),
  field1: varchar({ length: 100 }),
  field2: varchar({ length: 100 }),
},
(table) => [
  primaryKey({ columns: [table.id], name: "demo_id" }),
]);
```

约定与要点：

- **主键统一用 `varchar(36)` 存 UUID 字符串**，由业务层 `randomUuid()` 生成，不使用数据库自增。
- **时间字段统一 `mode: 'string'`**：Drizzle 返回 `YYYY-MM-DD HH:mm:ss` 字符串，与 `formatMysqlDate()`（定时任务里使用）格式一致，避免 Date 与字符串混用。
- **主键在表级回调中声明**：`primaryKey({ columns: [table.id], name: "<table>_id" })`。
- 布尔语义统一用 `tinyint`：`status` / `isDeleted` 等，`1` 为真、`0` 为假。
- 金额、序号等数值字段用 `int` / `decimal` 对应列类型；长文本用 `text`。

## 审计字段约定

系统表普遍包含这 6 个字段，且**由 `CommonRepo` 自动写入**，业务代码不需要关心：

| 字段 | 含义 | 写入时机 |
| --- | --- | --- |
| `created_by` | 创建人 id | 新增时取 `ctx.user?.id ?? null` |
| `created_at` | 创建时间 | 数据库默认值 `defaultNow()` |
| `updated_by` | 最后操作人 id | 新增/更新/软删除时都写入 |
| `updated_at` | 更新时间 | 数据库 `onUpdateNow()` |
| `is_deleted` | 逻辑删除标记 | 新增置 `0`，删除置 `1`，普通更新不改动 |
| `status` | 业务启停状态 | 业务字段，非审计字段 |

> 系统定时任务等无登录用户的场景下，操作人会被写成 `null`。

## drizzle-kit 配置与命令

```ts
// server/drizzle/drizzle.config.ts
export default defineConfig({
  schema: './server/drizzle/schema/*',
  out: './server/drizzle/out',
  dialect: 'mysql',
  dbCredentials: {
    host: process.env.DB_HOST!,
    user: process.env.DB_USER!,
    password: process.env.DB_PASSWORD!,
    database: process.env.DB_DATABASE!,
  },
});
```

可用脚本：

| 命令 | 作用 |
| --- | --- |
| `pnpm db:pull` | 从数据库反向生成 schema，适合已有表结构变更后同步 |
| `pnpm db:push` | 按 schema 定义推送到数据库 |
| `pnpm seed:admin` | 写入初始管理员账号（读取 `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_EMAIL`） |

`dbCredentials` 只读取 `DB_*` 环境变量（不使用 Nuxt 的 `NUXT_DB_*`），所以本地 `.env` 必须配置 `DB_HOST` / `DB_USER` / `DB_PASSWORD` / `DB_DATABASE`。

## 新增一张表的完整流程

1. 在 `server/drizzle/schema/<模块>/<表名>.ts` 中定义 `mysqlTable`，字段命名（数据库列）使用 snake_case。
2. 在 `server/drizzle/schema/index.ts` 中导入并导出该表。
3. 执行 `pnpm db:pull` 与数据库比对，或直接按建表 SQL 手动建表后 `db:pull` 核对差异。
4. 需要给前端查询条件加模糊匹配时，在 `shared/` 的 BaseSchema 上补充 `meta({ query: 'like' })`（见[共享契约层](/docs/main/backend-handbook/shared-contract)）。
5. 继续按[Repo 与 Service](/docs/main/backend-handbook/repo-service) 与[后端路由](/docs/main/backend-handbook/trpc-router) 补业务代码。

## 数据库连接

```ts
// server/drizzle/db.ts
export const useDb = () => { /* 模块级单例 + mysql2 pool(connectionLimit: 10) */ }
```

- `useDb()` 在模块作用域缓存实例，重复调用命中同一连接池，不要自行 `createPool`。
- 配置优先级：`DB_HOST` / `DB_USER` / `DB_PASSWORD` / `DB_DATABASE` 环境变量优先，未设置时回退到 `runtimeConfig.db.*`。
- 缺少 `host` / `user` / `database` 时直接抛错，启动阶段即可暴露配置问题。
- `createTestDb()` 是测试专用入口，只读环境变量、不依赖 Nuxt 运行时。
- 连接池 `connectionLimit` 固定为 10，并发更高的部署场景需要按实际情况调整。
