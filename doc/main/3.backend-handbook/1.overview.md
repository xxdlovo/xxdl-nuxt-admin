## 后端由什么组成

本项目是单 Nuxt 4 应用的全栈项目，后端不是独立服务，而是运行在同一个 Nuxt 进程中的 Nitro 服务端：

- 业务接口统一走 **tRPC**（`/api/trpc`），由 `trpc-nuxt` 提供的 handler 承载。
- 少数无法走 tRPC 的场景（文件上传、OAuth 回调等）使用 **Nitro 原生路由**（`server/api/**`、`server/routes/**`）。
- 数据库访问统一走 **Drizzle ORM + mysql2**，表定义在 `server/drizzle/schema`。
- 入参校验与类型契约统一放在 **`shared/`**，前后端共用同一份 Zod schema。
- 认证使用 **nuxt-auth-utils** 的加密 session cookie，权限使用基于 `sys_menu.code` 的 **RBAC 权限码**。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `server/api/**` | Nitro 原生接口，暴露在 `/api/**` 下；含 tRPC 入口 `server/api/trpc/[trpc].ts` |
| `server/routes/**` | Nitro 原生路由，无 `/api` 前缀（当前用于 OAuth 回调） |
| `server/trpc/**` | tRPC 初始化、上下文、错误格式化、中间件、根路由注册 |
| `server/sys-router/**` | 业务模块后端实现，每个模块含 Repo / Service / Router（`index.ts`） |
| `server/demo-router/**` | 单级模块的参考实现（可直接照抄的最小闭环） |
| `server/drizzle/**` | Drizzle 表定义、连接池、通用 Repo、查询条件构建器、drizzle-kit 配置 |
| `server/tasks/**` | Nitro tasks（定时任务分发与执行） |
| `server/utils/**` | 跨模块工具：业务错误、服务端翻译、请求信息、操作日志、密码 |
| `server/assets/storage` | Nitro `assets:server` 只读资源挂载目录 |
| `shared/**` | 前后端共用的 Zod schema、DTO 类型、权限码与工具函数 |

## 分层模型

后端按四层组织，职责边界清晰，越靠上层越接近 HTTP，越靠下层越接近数据库：

```text
Router（tRPC procedure）   权限声明、输入校验、调用 Service
  └─ Service               业务规则、组装数据、抛业务错误、缓存失效
       └─ Repo             数据访问，复用 CommonRepo，必要时扩展自定义查询
            └─ Drizzle     表定义 + SQL 构建 + 连接池
```

- **Router 不做业务判断**：只声明 `permission`、绑定 `input` schema、把 `ctx` 与 `input` 交给 Service。
- **Service 是业务唯一入口**：校验业务规则（例如定时任务的 cron 合法性）、生成主键、抛 `AppError`。
- **Repo 只负责取数/写数**：默认查询都会自动叠加逻辑删除条件与数据权限条件。
- **跨层共享的类型和校验**全部来自 `shared/`，不在 `server/` 内重复定义。

## 请求入口

只有一个 tRPC 入口，所有业务接口共享同一套上下文与中间件：

```ts
// server/api/trpc/[trpc].ts
import { createTRPCNuxtHandler } from 'trpc-nuxt/server'
import { createContext } from '~~/server/trpc/context'
import { appRouter } from '~~/server/trpc/routers'

export default createTRPCNuxtHandler({
  endpoint: '/api/trpc',
  router: appRouter,
  createContext: createContext,
})
```

`appRouter` 在 `server/trpc/routers.ts` 中集中注册，目前包含 21 个命名空间：

| 命名空间 | 说明 |
| --- | --- |
| `auth` | 注册、登录、登出、当前用户、资料与密码 |
| `sysUser` / `sysUserRole` | 用户与用户角色关系 |
| `sysRole` / `sysRoleMenu` | 角色与角色菜单授权 |
| `sysMenu` | 菜单与按钮权限 |
| `sysDept` | 部门树 |
| `sysDictType` / `sysDictData` | 字典类型与字典数据 |
| `sysConfig` | 系统参数 |
| `sysNotice` | 通知公告 |
| `sysOss` / `sysOssConfig` | 文件记录与对象存储配置 |
| `sysStorage` | Nitro 逻辑桶（memory / assets）管理 |
| `sysJob` / `sysJobLog` | 定时任务与任务日志 |
| `sysLoginLog` / `systemLog` | 登录日志与系统操作日志 |
| `sysOauthAccount` / `sysOauthConfig` | 第三方账号与 OAuth 平台配置 |
| `demo` | 示例模块 |

## 统一约定（写代码前必须知道）

1. 新接口一律通过 `proc({ permission, ... })` 声明，权限码显式书写，**不使用 `crudPermissionProcedures` 工厂**（理由见[后端路由](/docs/main/backend-handbook/trpc-router)）。
2. 业务错误一律 `throw new AppError('i18n.key')`，不在服务端拼中文文案，翻译由 `errorFormatter` 完成。
3. 数据访问一律复用 `CommonRepo` 或在其基础上扩展，查询条件通过 `buildScopedWhere` 统一叠加数据权限。
4. 所有写操作的审计字段（`createdBy`/`updatedBy`/`isDeleted`）由 Repo 自动填充，Service 不手写操作人。
5. 入参 schema 与 DTO 类型只写在 `shared/`，前端不重复定义。
6. 原生路由（`server/api/**`、`server/routes/**`）必须自己完成鉴权、日志与错误翻译，tRPC 不会介入。
