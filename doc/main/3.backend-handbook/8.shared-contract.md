## 为什么要有 shared

`shared/` 是前后端唯一的契约来源。服务端用它做入参校验，前端用它拿类型提示、表单校验与选项翻译，双方不各写一份：

```text
shared/  ←  server/（.input(schema) 校验、DTO 类型）
         ←  app/（$trpc 类型推导、useZodValidation 表单校验）
```

## 目录结构

```text
shared/
├── auth/            # 权限码构造 + RBAC 读模型类型
├── constants/       # 业务字典码与系统配置 key
├── demo/            # 示例模块契约
├── system/          # 系统模块契约（每个模块一个子目录）
├── types/           # 通用请求/响应类型
└── utils/           # 跨端纯函数工具
```

每个业务模块契约按「四文件模式」组织：

```text
shared/<模块>/
├── common.ts   # BaseSchema（表结构镜像）+ Dto 类型
├── input.ts    # Add / Update / Query / PageQuery schema + DTO 类型
├── output.ts   # 响应 schema + 类型
└── index.ts    # export * from 上述三个文件
```

## common.ts：BaseSchema

`BaseSchema` 是数据库表在契约层的镜像，字段全部 `nullish()`，只用于描述结构与查询条件：

```ts
// shared/demo/common.ts
import z from 'zod'

export const DemoBaseSchema = z.object({
    id: z.string().nullish(),
    field1: z.string().nullish().meta({ query: 'like' }),
    field2: z.string().nullish().meta({ query: 'like' }),
    status: z.number().nullish(),
    remark: z.string().nullish().meta({ query: 'like' }),
    createdBy: z.string().nullish(),
    createdAt: z.string().nullish(),
    updatedBy: z.string().nullish(),
    updatedAt: z.string().nullish(),
    isDeleted: z.number().nullish(),
})
export type DemoDto = z.infer<typeof DemoBaseSchema>
```

## meta({ query }) 契约（重要）

`.meta({ query: 'like' })` 是后端查询条件构建器 `buildWhereBySchema` 读取的约定：

| meta 配置 | 生成的条件 |
| --- | --- |
| 未声明 | `eq(column, value)` 等值匹配 |
| `{ query: 'like' }` | `like(column, '%value%')` 模糊匹配 |

规则细节（`server/drizzle/queries/buildWhereBySchema.ts`）：

- 只支持 `eq` 与 `like` 两种操作符。
- `undefined` / `null` / 空字符串的值会被跳过。
- schema 中声明但表里不存在的字段会被忽略，因此 BaseSchema 允许比表更宽。
- 注意 `CommonRepo` 只在传入 schema 时启用这套自动条件；不传第二个参数的 Repo 需要手写 `extraWhere`。

## input.ts：新增与查询

Add/Update 从 BaseSchema 上「挑字段 + 收紧校验」，PageQuery 在 Query 基础上叠加分页参数：

```ts
// shared/system/job/input.ts（节选）
export const SysJobAddSchema =
  SysJobBaseSchema.pick({
    jobName: true, jobCode: true, handlerCode: true,
    cronExpression: true, cronTimezone: true,
    status: true, sortOrder: true, remark: true,
  }).extend({
    id: SysJobBaseSchema.shape.id.nonoptional(),
    jobName: z.string().min(1, 'form.required'),
    jobCode: z.string().min(1, 'form.required'),
    handlerCode: z.string().min(1, 'form.required'),
    cronExpression: z.string().min(1, 'form.required'),
    cronTimezone: z.string().default('Asia/Shanghai'),
    status: z.number().default(1),
    sortOrder: z.number().default(0),
  })

export const SysJobUpdateSchema = SysJobAddSchema.extend({
  id: z.string().nonempty('form.id.required'),
})

export const SysJobPageQuerySchema = SysJobQuerySchema.extend(ApiRequestSchema.shape)
```

约定：

- **校验消息写 i18n key**，不写中文文案（如 `'form.required'`、`'form.id.required'`），由前端 `useZodValidation` 或服务端 `errorFormatter` 翻译。
- Update schema 必须把 `id` 收紧为必填。
- 分页查询用 `z.extend(ApiRequestSchema.shape)` 叠加 `page` / `pageSize`，不要重复定义。
- 状态、开关类操作用独立的窄 schema，例如 `SysJobStatusSchema = z.object({ id: z.string().nonempty('form.id.required') })`。

## output.ts：响应类型

```ts
// shared/system/job/output.ts
export const SysJobRespSchema = SysJobBaseSchema
export type SysJobRespDTO = z.infer<typeof SysJobRespSchema>

export const SysJobHandlerRespSchema = SysJobHandlerSchema
export type SysJobHandlerRespDTO = z.infer<typeof SysJobHandlerRespSchema>
```

多数模块的响应就是 BaseSchema 本身，`output.ts` 保留是为了给「额外字段、联表字段、聚合结果」留位置（例如用户列表会带上 `deptName`）。

## types：通用请求与响应

### 分页请求

`shared/types/common/ApiReq.ts`：

| 导出 | 说明 |
| --- | --- |
| `ApiRequestSchema` | `page`（≥1，默认 1）、`pageSize`（1~1000，默认 10） |
| `ApiQueryRequestSchema` | 在分页基础上增加 `filter`（`Record<string, any>`，默认 `{}`） |
| `ApiReqWithSortSchema` | 在分页基础上增加 `sort` 数组（`field` + `asc/desc`） |

### 分页响应

`shared/types/common/ApiResp.ts`：

| 导出 | 说明 |
| --- | --- |
| `createPaginationSchema(itemSchema)` | HTTP 风格响应：`code` / `success` / `msg` / `total` / `list` |
| `createPlainDataSchema(dataSchema)` | HTTP 风格单对象响应：`code` / `success` / `msg` / `data` |
| `TrpcPageResponseSchema(itemSchema)` | tRPC 风格分页响应：`list` / `total` / `page` / `pageSize`，无外层包裹 |
| `TrpcPageResp<T>` | 上述 tRPC 分页类型（前端 `useTable` 系列直接使用） |

> 当前项目的 tRPC 接口以 `TrpcPageResponseSchema` 形态返回分页数据；`ApiResp()`（`successPage`）与 HTTP 风格的包裹 schema 主要服务于原生路由场景。

### 错误结构

`shared/types/common/TRPCFormattedError.ts` 定义前端拿到的错误对象：

| 字段 | 说明 |
| --- | --- |
| `message` | 已翻译的错误消息 |
| `i18nKey` | `AppError` 的原始 key，供前端按业务错误分支处理 |
| `type` | 错误类型（服务端错误 / 校验错误 / 数据库错误等） |
| `code` | tRPC 错误码（`BAD_REQUEST`、`UNAUTHORIZED` 等） |
| `httpStatus` | HTTP 状态码 |
| `stack` | 堆栈，仅开发环境返回 |
| `path` / `timestamp` | 可选附加信息 |

## auth：权限码与 RBAC 类型

`shared/auth/permission.ts`：

| 导出 | 说明 |
| --- | --- |
| `PERMISSION_ACTIONS` | 标准动作常量：`list` / `add` / `edit` / `del` |
| `buildPermissionCode(resource, action)` | 生成 `system:user:list` 形式的标准权限码 |
| `customPermissionCode(resource, action)` | 生成自定义动作权限码，如 `system:job:run` |
| `crudPermissionCodes(resource)` | 一次生成四个标准权限码对象 |

`shared/auth/rbac.ts` 定义 RBAC 读模型：`RbacUser`、`RbacRole`、`RbacMenu`（含 `children` 树）、`RbacFlatMenu`、`RbacProfile`（`{ user, roles, permissions, menus }`）。`authService(ctx).getRbacProfile(user)` 的返回值类型就是 `RbacProfile`，前端菜单与权限判断都基于它。

## constants：字典码与配置 key

`shared/constants/business.ts`：

- `businessDictCode`：系统字典码集中定义，例如 `ossService`、`userGender`、`enableStatus`、`jobRunningStatus`、`jobLogStatus`、`jobTriggerType`、`dataScope`、`menuType`、`noticeType`、`sysLogLevel` 等；新增字典必须在这里登记，避免业务代码里散落字符串。
- `systemRegisterEnum`：注册开关配置项（key 为 `system_register_enable`，取值为 `yes` / `no`）。
- `systemOtherLoginEnum`：其他登录入口开关（key 为 `system_otherlogin_enable`，取值为 `true` / `false` 字符串）。
- `OAUTH_PLACEHOLDER_PASSWORD`：OAuth 建号时的密码占位标记 `!oauth-no-password!`。以 `!` 开头，与 `$scrypt$...` 哈希形态不可能混淆，且永远无法通过密码校验；业务据此判断「未设置过密码」。

## utils：跨端纯函数

| 文件 | 导出 | 用途 |
| --- | --- | --- |
| `shared/utils/uuid.ts` | `randomUuid()` | 基于 `crypto.randomUUID()` 生成主键 |
| `shared/utils/common.ts` | `transformRecordToOption(record)` | 把 `{ key: label }` 转成 `[{ value, label }]` 供下拉选项使用 |
| `shared/utils/common.ts` | `toggleHtmlClass(className)` | 安全切换 `html` 上的 class，无 DOM 时返回空操作 |
| `shared/utils/klona.ts` | `jsonClone` | JSON 深拷贝 |

## 约定与注意事项

1. **DTO 类型只在这里定义**，`server/` 与 `app/` 都从 `#shared/<模块>` 导入，不在本地重复声明。
2. **BaseSchema 字段一律 `nullish()`**：它同时承担「查询条件」职责，必填约束放在 input.ts 里收紧。
3. **校验消息必须是 i18n key**，且 key 要在 `app/locales/zh.json` 与 `en.json` 中存在对应文案。
4. **模糊查询要显式声明 `meta({ query: 'like' })`**，否则默认按等值匹配，前端传部分字符串会查不到数据。
5. **索引文件必须导出**：`shared/<模块>/index.ts` 用 `export * from './common'` 等三行统一导出，模块外的引用都走 `#shared/<模块>`。
6. 新增字典时同步更新 `businessDictCode`，并补对应字典数据，否则前端 `useDict` 取不到选项。
