## runtimeConfig 结构

服务端运行期配置集中在 `nuxt.config.ts` 的 `runtimeConfig`：

```ts
runtimeConfig: {
    demoMode: process.env.NUXT_DEMO_MODE === 'true',
    session: {
        password: '',            // 占位，运行时由 NUXT_SESSION_PASSWORD 覆盖
        cookie: {
            path: '/',
            sameSite: 'lax',
            httpOnly: true,
            secure: sessionCookieSecure
        }
    },
    db: {
        host: '',
        user: '',
        password: '',
        database: '',
    },
    public: {
        appName: 'Nuxt Admin System'
    }
}
```

| 键 | 说明 |
| --- | --- |
| `demoMode` | demo 演示模式开关，来自 `NUXT_DEMO_MODE` |
| `session.password` | session 加密密钥；源码中必须是空字符串，真实密钥由 `NUXT_SESSION_PASSWORD` 注入 |
| `session.cookie` | session cookie 属性，`secure` 由环境推导 |
| `db.*` | 数据库连接配置，可被 `DB_*` 环境变量覆盖 |
| `public.appName` | 客户端可读的应用名，来自 `NUXT_PUBLIC_APP_NAME` |

> `session.password` 的字段在 `nuxt-auth-utils` 类型定义中是必填项，因此源码里必须保留空字符串占位，不能省略，也不要在源码中写真实密码。

## 环境变量清单

以下变量与 `.env.example` 完全一致，新增或删改变量时需要同步更新该文件：

| 变量 | 示例值 | 作用与读取位置 |
| --- | --- | --- |
| `DB_HOST` | `localhost` | MySQL 主机；`server/drizzle/db.ts`、`drizzle.config.ts` |
| `DB_DATABASE` | `nuxt_admin` | 数据库名；同上 |
| `DB_USER` | `root` | 数据库用户名；同上 |
| `DB_PASSWORD` | `root` | 数据库密码；同上 |
| `NUXT_PUBLIC_APP_NAME` | `Nuxt Admin System` | 应用名，映射到 `runtimeConfig.public.appName` |
| `NODE_ENV` | `development` | 运行环境；参与 session cookie `secure` 推导，以及错误堆栈是否返回 |
| `NUXT_DEMO_MODE` | `true` | demo 只读模式开关 |
| `NUXT_SESSION_PASSWORD` | `replace-with-at-least-32-random-characters` | session 加密密钥，生产环境建议至少 32 位随机字符串 |
| `NUXT_SESSION_COOKIE_SECURE` | `false` | session cookie 是否要求 HTTPS |
| `ADMIN_USERNAME` | `admin` | 仅 `pnpm seed:admin` 使用 |
| `ADMIN_PASSWORD` | `change-me-before-seeding` | 仅 `pnpm seed:admin` 使用；**必填且长度至少 6 位**，否则脚本直接抛错 |
| `ADMIN_EMAIL` | `admin@example.com` | 仅 `pnpm seed:admin` 使用，缺省时按 `<username>@example.com` 生成 |
| `ENABLE_LOGGING` | `true` | **当前服务端代码未读取**，改动不会影响记录行为 |
| `LOG_LEVEL` | `info` | **当前服务端代码未读取**；`LogRecorderService` 内的 `LOG_LEVEL` 是同名本地常量，与 env 无关 |

关于日志两个变量的说明：是否记录操作日志由 `proc({ log })` 与 operation 类型（`mutation` 记录、`query` 默认不记录）决定，日志级别由 `LogRecorderService` 内部各方法固定指定。自建部署时保留这两个变量只是为了不破坏 `.env` 模板形态。

## 数据库配置优先级

```ts
// server/drizzle/db.ts
const dbConfig = {
    host: process.env.DB_HOST || config.db.host,
    user: process.env.DB_USER || config.db.user,
    password: process.env.DB_PASSWORD || config.db.password,
    database: process.env.DB_DATABASE || config.db.database,
}
```

优先级：`DB_*` 环境变量 → `runtimeConfig.db.*`。

`runtimeConfig.db.*` 可以按 Nuxt 约定用 `NUXT_DB_HOST` / `NUXT_DB_USER` / `NUXT_DB_PASSWORD` / `NUXT_DB_DATABASE` 覆盖。三者都缺失 `host` / `user` / `database` 时会抛出：

```text
Database config is missing. Set DB_HOST/DB_USER/DB_DATABASE or NUXT_DB_HOST/NUXT_DB_USER/NUXT_DB_DATABASE.
```

注意 drizzle-kit（`pnpm db:push` / `db:pull`）只读取 `DB_*`，不读取 `NUXT_DB_*`，因此本地 `.env` 必须配置 `DB_*` 系列变量。

## session cookie 的 secure 判定

```ts
const sessionCookieSecure = process.env.NUXT_SESSION_COOKIE_SECURE !== undefined
    ? process.env.NUXT_SESSION_COOKIE_SECURE === 'true'
    : process.env.NODE_ENV === 'production'
```

| 场景 | 结果 |
| --- | --- |
| 显式设置 `NUXT_SESSION_COOKIE_SECURE` | 以该值为准 |
| 未设置且 `NODE_ENV=production` | `secure = true`（要求 HTTPS） |
| 未设置且非生产环境 | `secure = false`（兼容 HTTP） |

通过 `http://IP:端口` 访问时，浏览器会拒绝保存 `Secure` cookie，典型表现是「登录接口返回成功，但后续请求仍是未登录」。此时在生产环境需要显式设置 `NUXT_SESSION_COOKIE_SECURE=false`。

## demo 模式的影响面

`NUXT_DEMO_MODE=true` 时会依次影响：

1. `runtimeConfig.demoMode` 变为 `true`。
2. `server/trpc/init.ts` 在模块加载时求值一次 `demoMode`（不在每次请求重复解析）。
3. `proc()` 计算 `demoMode || options.readonly === true`，命中时由 `demoReadonlyMiddleware` 抛出 `AppError('system.demoReadonly')`。
4. 声明了 `readonly: true` 的接口（常规的编辑、删除类）在演示环境下直接失败；只读查询不受影响。

## Nitro 相关配置

```ts
nitro: {
    storage: {
        memory: { driver: 'memory' }
    },
    experimental: {
        tasks: true
    },
    scheduledTasks: {
        // '* * * * *': ['sys-job:dispatch']
    }
}
```

| 配置 | 说明 |
| --- | --- |
| `storage.memory` | 为业务临时数据显式声明独立 memory 命名空间，避免误读 Nitro 默认 storage 中的 `data`、`cache`、`root`、`build` 等框架内部内容 |
| `experimental.tasks` | 开启 Nitro tasks 能力，`runTask()` 可用 |
| `scheduledTasks` | **当前处于注释状态**，即定时任务的自动调度默认未启用 |

`scheduledTasks` 的注释状态意味着：`sys-job:dispatch` 与 `sys-job:run` 两个 task 已注册可手动调用，但不会周期性自动触发。需要自动调度时必须显式放开，例如按分钟扫描：

```ts
scheduledTasks: {
    '* * * * *': ['sys-job:dispatch']
}
```

## 其他影响服务端行为的配置项

| 配置 | 说明 |
| --- | --- |
| `ssr: false` | 应用为 SPA 模式，页面在客户端渲染，服务端只提供 API |
| `routeRules` | `/fi/**` 使用 `system` 布局 |
| `hooks['app:resolve']` | 过滤 `app/layouts/modules/` 下的布局，避免被当作独立布局注册 |
| `hooks['prepare:types']` | 摘除生成的 `libReplacement` 选项，规避当前 TypeScript 版本的类型检查报错 |
| `build.transpile: ['trpc-nuxt']` | `trpc-nuxt` 内部使用 Nuxt 虚拟模块 `#imports`，必须参与构建转译 |
| `devServer` | 开发服务器监听 `0.0.0.0:3001` |
| `css` | 全局样式入口 `~/assets/css/main.css` |
| `ui.fonts: false` | 关闭 Google 字体请求 |
| `icon` | 图标由服务端提供，并注册 `./app/assets/icons` 自定义图标集合 |
| `i18n` | `strategy: 'no_prefix'`，语言 cookie 统一为 `i18n_locale`，语言包目录 `app/locales` |
| `echarts` | 按需注册柱状图 / 折线图 / 饼图与相关组件 |

## 部署注意

1. 必须设置 `NUXT_SESSION_PASSWORD`，否则 session 无法正常加解密。
2. HTTPS 部署保持 `secure = true`；仅 HTTP 部署需显式 `NUXT_SESSION_COOKIE_SECURE=false`。
3. 生产环境建议关闭 `NUXT_DEMO_MODE`。
4. `memory` 缓存只存在于当前 Node.js 进程，多实例部署时缓存不共享，不能作为持久化依赖。
5. 定时任务自动调度需要在 `nitro.scheduledTasks` 中显式开启。
