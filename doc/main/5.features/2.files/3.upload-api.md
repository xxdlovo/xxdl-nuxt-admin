## 为什么上传不走 tRPC

上传需要读取 `multipart/form-data` 并可能传输大文件，tRPC 的输入校验与批处理链路不适合承载二进制体。因此系统用 Nitro 的 `defineEventHandler` 独立实现上传端点，并手动补齐 tRPC 侧自动提供的鉴权、翻译与日志能力。

## 接口契约

| 项 | 值 |
| --- | --- |
| 方法 / 路径 | `POST /api/system/oss/upload` |
| Content-Type | `multipart/form-data` |
| 字段 | `configId`（存储配置 ID）、`file`（文件本体） |
| 请求头 | `x-locale`、`accept-language`（用于错误文案与日志语言） |
| 成功响应 | `{ success: true, data: SysOssDto }` |
| 失败响应 | Nitro 错误，`statusCode` 由 `resolveAppErrorStatus` 决定（401 / 403 / 400，业务错误不再是 500），`message` 为已翻译文案 |

`data` 中可直接使用的字段：`id`、`originalName`、`fileName`、`fileSize`、`service`、`bucketName`、`objectName`、`url`。

## 鉴权与状态码

端点内**不使用** tRPC 中间件，权限在 handler 里显式判断（见 `assertUploadPermission`）：

```ts
const user = ctx.user
if (!user) {
  throw new AppError('auth.unauthorized')      // → 401
}

if (user.isAdmin === 1) {
  return                                        // 管理员直接放行
}

const permissionCodes = await authService(ctx).listPermissionCodes(user)
if (!permissionCodes.includes(crudPermissionCodes('system:oss').add)) {
  throw new AppError('auth.forbidden')          // → 403
}
```

| 情况 | 状态码 |
| --- | --- |
| 未登录 | 401 |
| 已登录但缺少 `system:oss:add` | 403 |
| 未传文件 / 未传 configId / 配置不可用 | 400 |
| 其它意外异常 | 500 |

## 前端调用方式

页面上传使用 `UFileUpload` 选择文件，再用 `XMLHttpRequest` 提交，目的是拿到上传进度（`fetch` 无法获取上传进度）。`app/pages/system/oss/components/sys-oss-operate.vue` 是完整参考：

```ts
const formData = new FormData()
formData.append('configId', configId.value)
formData.append('file', file.value)

const xhr = new XMLHttpRequest()
xhr.open('POST', '/api/system/oss/upload')
// 会话 Cookie 必须显式携带，原生请求不像 tRPC 客户端那样默认注入
xhr.withCredentials = true

const locale = useCookie<string>('i18n_locale').value || 'en'
xhr.setRequestHeader('x-locale', locale)
xhr.setRequestHeader('accept-language', locale)

xhr.upload.onprogress = (event) => {
  if (!event.lengthComputable) return
  // 到 100% 只代表上传完成，仍要等服务端响应，因此进度条封顶 95%
  progress.value = Math.min(95, Math.round((event.loaded / event.total) * 100))
}

xhr.onload = async () => {
  if (xhr.status >= 200 && xhr.status < 300) {
    progress.value = 100
    await props.refresh?.()
  } else {
    // 服务端已翻译好文案，优先取 message / statusMessage
    useToastError('上传失败', 5000, parseUploadError(xhr))
  }
}
```

要点：

- 字段名必须与服务端一致（`configId`、`file`），拼错时服务端会返回「请选择文件」；
- `withCredentials = true` 不可省，否则会话 Cookie 不发送，接口返回 401；
- 失败时按 `body.message → body.statusMessage → xhr.statusText` 的顺序取文案（服务端已经翻译）；
- 上传前先本地校验 `configId` 与文件是否已选择，避免无意义的请求。

## 常见问题

| 现象 | 原因 |
| --- | --- |
| 上传返回 401 | 未设置 `withCredentials`，或会话已过期 |
| 上传返回 403 | 当前账号无 `system:oss:add` 权限，且不是管理员 |
| 报「请选择已启用且已验证的存储配置」 | `configId` 未传、配置被禁用，或从未通过连通性验证 |
| 报「暂不支持该存储服务」 | `sys_oss_config.service` 不在 `aliyun` / `aws` / `tencent` 之列 |
| 前端提示「上传失败」但看不到细节 | 查看系统日志中 `sysOss.upload` 模块的失败记录，含入参与异常信息 |
