## 方法一览

`server/sys-router/storage/SysStorageService.ts` 暴露五个缓存方法，key 会自动归一化到 `cache:` 命名空间：

| 方法 | 签名 | 语义 |
| --- | --- | --- |
| `getCache` | `<T>(key: string): Promise<T \| null>` | 命中且未过期返回 `T`；不存在、已过期或缓存异常返回 `null` |
| `setCache` | `<T>(key: string, value: T, ttlSeconds: number): Promise<void>` | 写入 envelope；`ttlSeconds` 非正数或非有限数时直接跳过 |
| `removeCache` | `(key: string): Promise<void>` | 删除单个 key |
| `clearCache` | `(prefix: string): Promise<void>` | 删除某逻辑前缀下的全部 key（如 `dict:`、`rbac:user:`） |
| `rememberCache` | `<T>(key: string, loader: () => Promise<T> \| T, options: { ttlSeconds: number }): Promise<T>` | 缓存优先，miss 时执行 loader 并回填 |

## 基础用法

```ts
import { SysStorageService } from '#server/sys-router/storage/SysStorageService'

const storage = new SysStorageService()

// 写入：ttlSeconds 单位为秒
await storage.setCache('example:config', { enabled: true }, 60)

// 读取：未命中返回 null，调用方必须处理
const value = await storage.getCache<{ enabled: boolean }>('example:config')

// 删除单个
await storage.removeCache('example:config')

// 按前缀批量清理：example:config、example:user:1 都会被删除
await storage.clearCache('example:')
```

注意 `clearCache` 接收的是**逻辑前缀**，允许以冒号结尾（如 `dict:`），不要传完整 key。

## rememberCache：自动回源

适合「缓存没命中才查数据库或调用外部服务」的场景：

```ts
const config = await storage.rememberCache(
  'example:config',
  async () => {
    // 只有 miss 时才会执行
    return await loadConfigFromDatabase()
  },
  { ttlSeconds: 5 * 60 }
)
```

它的行为：

1. 先 `getCache`，命中直接返回；
2. 未命中时检查进程内的 `pendingCacheLoads`，若同一 key 已有进行中的 loader，则**直接复用该 Promise**，不重复查询；
3. 否则执行 loader，写入缓存后返回；
4. 无论成功失败，都会在 `finally` 中清理 `pendingCacheLoads`。

因此同一个 key 的并发请求在单进程内只会触发一次 loader，这也是它比「手写 get + set」更值得使用的原因。

## key 的归一化

- 传入 `dict:user_status` 会被写成 `cache:dict:user_status`；
- 已带 `cache:` 前缀的 key 不会重复叠加；
- key 会经过路径安全校验，包含绝对路径、`..` 或空段时直接抛错（不是静默失败）。

业务侧只需要传逻辑 key，命名规范见 `/docs/main/features/cache/conventions`。

## 错误与降级行为

| 场景 | 结果 |
| --- | --- |
| 读取时 `expiresAt` 已过 | 删除该 key，返回 `null` |
| envelope 结构不合法 | 返回 `null`（不抛错） |
| 写入失败 | 静默忽略，业务照常返回新计算的值 |
| `ttlSeconds <= 0` | 不写入，函数直接返回 |
| `clearCache` 的 storage 调用抛错 | 静默忽略，由 TTL 兜底 |

不要在业务代码里 `try/catch` 这些调用，服务类已经吞掉了缓存侧的异常。

## 新增缓存前先读

直接使用通用 key 前请确认：是否已有 `DictCacheService` / `RbacCacheService` 覆盖同类数据。重复缓存同一份数据会产生多个失效点，详见 `/docs/main/features/cache/conventions`。
