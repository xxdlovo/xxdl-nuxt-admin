## 技术栈与运行形态

后台前端与后端 API 在同一个 Nuxt 应用内，不存在独立的前端工程。关键版本以 `package.json` 为准：

| 依赖 | 作用 |
| --- | --- |
| `nuxt` 4.5.2 | 应用框架 |
| `vue` 3.5.x | 视图层 |
| `@nuxt/ui` 4.11.1 | UI 组件库（`U*` 前缀组件） |
| `tailwindcss` 4.x | 原子化样式，入口 `app/assets/css/main.css` |
| `pinia` + `@pinia/nuxt` | 状态管理 |
| `nuxt-i18n-micro` | 国际化，提供 `$t` / `$ts` |
| `trpc-nuxt` + `@trpc/client` | 类型安全的接口调用 |
| `motion-v` | 动画 |
| `nuxt-echarts` | 图表（首页仪表盘） |

前台形态是**纯客户端渲染**：`nuxt.config.ts` 中 `ssr: false`。因此不存在服务端渲染的 `useAsyncData` 预取需求，页面数据统一通过 `$trpc` 拉取。

开发服务器由 `nuxt.config.ts` 的 `devServer` 固定为 `host: '0.0.0.0'`、`port: 3001`，启动命令是 `pnpm dev`。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `app/pages` | 文件路由页面。后台页面集中在 `app/pages/system/**`，示范模块见 `app/pages/demo`，落地页见 `app/pages/landing`，文档站在 `app/pages/docs` |
| `app/components` | 公共组件，按用途分子目录：`table/`、`base/`、`u/` |
| `app/composables` | 组合式函数，表格相关集中在 `app/composables/useTable/` |
| `app/layouts` | 布局文件与布局内部模块（`app/layouts/modules/**`） |
| `app/stores` | Pinia store：`dict.ts`、`rbacProfile.ts`、`tabs.ts`、`theme.ts`、`persistedStorage.ts` |
| `app/plugins` | `01.client.ts` 注册 `$trpc`；`permission.ts` 注册 `v-permission` 指令 |
| `app/middleware` | 全局路由中间件：`auth.global.ts`（登录拦截）、`layout.global.ts`（落地页布局） |
| `app/locales` | 翻译源文件 `zh.json`、`en.json` |
| `app/utils` | `common.ts`、`navigation.ts`、`toast.ts` |
| `app/types` | 页面级类型（如 `app/types/landing/content.ts`） |
| `app/assets` | `css/`、`icons/`（自定义图标集合）、`imgs/` |
| `app/features` | 落地页私有模块（`app/features/landing`） |

## 应用入口链路

根组件 `app/app.vue` 只做全局装配，不承载业务：

```text
app/app.vue
  └─ UApp（提供全局 toast 容器）
       └─ NuxtLayout（按页面 meta.layout 选择布局）
            └─ NuxtPage（渲染 app/pages 下的页面）
       └─ ClientOnly > BaseWatermark（水印层）
```

`app/app.vue` 里发生的事：

- 用 `useThemeStore($pinia)` 绑定主题 store（显式传入 Pinia 实例，避免根组件 setup 阶段 `activePinia` 尚未就绪时报 “no active Pinia”）；
- `initializeThemeColors()` 读取 `localStorage` 中保存的主题色，并通过 `useHead` 注入 CSS 变量（`--ui-radius`、`--ui-primary` 等）；
- 根据 `themeStore.content.pageAnimate` 计算页面过渡，并对 `/docs/main` 系列路由强制关闭过渡。

## 可用布局

| 布局 | 文件 | 使用场景 |
| --- | --- | --- |
| `default` | `app/layouts/default.vue` | 极简上/中/下结构，未显式声明布局时的兜底 |
| `system` | `app/layouts/system.vue` | 后台主布局，提供菜单、页签、面包屑、水印等 |
| `docs` | `app/layouts/docs.vue` | 文档站布局，供 `app/pages/docs/main/**` 使用 |
| `landing` | `app/layouts/landing.vue` | 营销落地页，由 `app/middleware/layout.global.ts` 在 `/` 与 `/landing` 自动指定 |

后台页面必须显式声明布局：

```ts
definePageMeta({
  layout: 'system',
  title: 'Demo示例',
  icon: 'i-lucide-sparkles'
})
```

`title` / `icon` 会被页签（`app/layouts/modules/global-tab`）与导航使用。

> 布局细节、后台公共区域与模块页面目录规范见[页面与布局](/docs/main/frontend-handbook/pages-layouts)。

## 自动导入约定

Nuxt 会自动导入 `app/components`、`app/composables`、`app/utils`：

```vue
<!-- 无需 import：BaseWatermark 来自 app/components/base/BaseWatermark.vue -->
<BaseWatermark />

<script setup lang="ts">
// 无需 import：来自 app/composables 与 app/utils
const permissions = useCrudPermissions('demo')
useToastSuccess('保存成功')
</script>
```

**项目约定**：页面内引用业务组件时，显式写出 `import` 并带上 `.vue` 后缀。参见 `app/pages/demo/index.vue`：

```ts
import DemoSearch from './components/demo-search.vue'
import DemoOperate from './components/demo-operate.vue'
import TableWithPagination from '~/components/table/TableWithPagination.vue'
```

这样做的收益是来源明确、避免不同目录下同名组件冲突；新增模块时请沿用该写法。

## 布局目录不会被注册为布局

`nuxt.config.ts` 用 `app:resolve` 钩子把 `app/layouts/modules/**` 下被 Nuxt 识别出来的布局**删除注册**：

```ts
hooks: {
  'app:resolve'(app) {
    for (const [name, layout] of Object.entries(app.layouts)) {
      if (layout.file.replace(/\\/g, '/').includes('/app/layouts/modules/')) {
        delete app.layouts[name]
      }
    }
  }
}
```

原因写在配置注释里：这些文件是布局的内部拼装件（`global-header`、`global-sider`、`theme-drawer` 等），保留文件导入以获得 HMR，但不希望它们成为可选布局名。新增这类内部模块时放进 `app/layouts/modules/**` 即可，不必手动清理注册。

如果只是想新增一个普通组件，更推荐放到 `app/components`。
