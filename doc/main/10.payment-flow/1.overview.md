本分组讲的是**业务视角的端到端支付流程**：一笔钱从业务侧发起，到「余额真的变了」或「订单真的完成了」，中间经过哪些步骤、每一步失败了会留下什么痕迹、账实怎么保证、出了问题从哪捞。

**支付能力本身不在这里讲。** 渠道配置、统一下单 / 查询 / 关闭、回调验签与幂等、适配器实现见[支付模块总览](/docs/main/payment/overview)与[渠道配置](/docs/main/payment/channels)、[下单、查询与状态流转](/docs/main/payment/orders)、[回调处理与幂等](/docs/main/payment/notify)；`bizType` 分派（`dispatchPaidOrder`、`onPaid` 注入与失败语义）见[业务接入：bizType 分派](/docs/main/payment/integration)。本分组对支付域的实现细节只做一句话引用。

## 一、三条流程

| 流程 | 钱从哪来 | 业务单 | 唯一入账 / 实扣入口 | 详细页 |
| --- | --- | --- | --- | --- |
| 充值到账 | 会员在渠道扫码付款 | `sys_member_recharge`（`out_trade_no` 前缀 `RCH`） | `RechargeService.credit()` | [充值流程](/docs/main/payment-flow/recharge) |
| 余额支付 | 会员钱包里的余额（先冻结、后实扣） | `sys_order`（`order_no` 前缀 `ORD`，`pay_mode = balance`） | `WalletService.confirm()`（由 `OrderService.confirmTx` 调用） | [订单支付流程](/docs/main/payment-flow/order-payment) |
| 在线支付 | 会员在渠道扫码付款 | `sys_order`（`pay_mode = online`） | `OrderService.markPaid()` | [订单支付流程](/docs/main/payment-flow/order-payment) |

三者共同的「事实来源」是 `sys_pay_order` 一行——它是资金结论；业务侧只负责把资金结论翻译成业务结果（[业务接入：bizType 分派](/docs/main/payment/integration)）。

两条与直觉不同的边界：

- **余额支付没有 `sys_pay_order`**，也从不碰渠道。它靠 `sys_member_freeze` 的预扣状态机表达「钱已经占住但还没扣」；`WalletService.confirm` 才是真正扣钱的那一刻。
- **在线支付成功后不动余额**。`markPaidTx` 只改订单状态、核销优惠码、加销量；`WalletService.confirm` 不会被调用（`OrderService.ts:391-395` 的注释与 `:395-428` 的实现）。

## 二、全链路总览

```text
【充值】app/pages/system/wallet/index.vue
  sysMember.myRecharge
    └─ RechargeService.create
         ├─ payChannelRepo.findEnabled({})         渠道必须 status=1
         ├─ channel.verifyStatus === 1             否则 notVerified（测试配置未通过）
         ├─ members.resolveCoupon(scene='recharge') 校验券（不核销）
         ├─ rechargeRepo.insert   sys_member_recharge  status='WP'
         ├─ members.lockCoupon(bizNo=outTradeNo)      写 sys_member_coupon_use('locked')
         └─ try payOrderService.createPayment(bizType='recharge', outTradeNo, amount=payAmount)
              ├─ 成功 → rechargeRepo.attachPayOrder(payOrderId) → 返回二维码给页面
              └─ 失败 → rechargeRepo.markFailed('FL') + releaseCoupon → 抛 createFailed

  支付成功：POST /api/pay/notify/{channel}
    └─ PayNotifyDispatcher.markPaidIfPending（sys_pay_order → 'OD'）
         └─ dispatchPaidOrder  bizType='recharge'
              └─ RechargeService.credit(outTradeNo)
                   ├─ markCredited      status <> 'OD' → 'OD'   （条件更新，只生效一次）
                   ├─ WalletService.credit(account='recharge')  流水 dedup_key=recharge:{no}:recharge
                   ├─ WalletService.credit(account='gift')      流水 + 赠送金批次（金额 > 0 时）
                   └─ members.markCouponUsed(bizNo=outTradeNo)

【余额支付】app/pages/system/mall/index.vue（payMode='balance'）
  sysOrder.myCreate → OrderService.create → createTx（**单个事务**）
    ├─ goods.assertPurchasable / resolvePrice（等级价）
    ├─ members.resolveCoupon(scene='consume')
    ├─ goods.decreaseStockOrThrow            扣库存
    ├─ orderRepo.insert                      sys_order  status='WP'  expire_at=+15min
    ├─ members.lockCoupon(bizNo=orderNo)
    └─ WalletService.freeze(bizNo=orderNo, amount=payAmount, ttlMinutes=0)
         赠送金优先 → 不足部分落充值金；余额不足则 0 行受影响 → 整事务回滚
    → 返回冻结结果，用户被引导到我的订单「确认支付」

  sysOrder.myConfirm（或后台「确认支付」）
    └─ OrderService.confirmTx
         ├─ WalletService.confirm(freezeId)
         │    ├─ freezes.markConfirmed（只有 FROZEN 能确认）
         │    ├─ wallet.settleFrozen（扣余额 + 减冻结 + 累计消费）
         │    ├─ 流水 consume_confirm（gift / recharge 各一条，只在确认瞬间写一次）
         │    └─ consumeGiftBatches（按到期时间 FIFO 扣批次 remain_amount）
         ├─ orderRepo.markCompleted（where status='WP'）
         ├─ members.markCouponUsed(bizNo=orderNo)
         └─ goods.increaseSales

  取消 / 后台关闭 / 超时 → OrderService.cancelTx
    ├─ WalletService.release（幂等，只清冻结不动余额）
    ├─ members.releaseCoupon
    ├─ goods.rollbackStock
    └─ orderRepo.markClosed（where status='WP'，close_reason 落库）

【在线支付】sysOrder.myCreate（payMode='online'）→ OrderService.create
    ├─ createTx 同上，但**不冻结余额**
    ├─ （事务外）payOrderService.createPayment(bizType='order', outTradeNo=orderNo)
    │    └─ 成功 → attachPayOrder 回填 pay_order_id / pay_channel_code
    │    └─ 失败 → failOnlinePayment：订单 'FL' + rollbackStock + releaseCoupon
    └─ 返回 qrImageUrl / qrContent / payUrl

  支付成功：回调 → dispatchPaidOrder → OrderService.markPaid(orderNo)
              ├─ orderRepo.markCompleted（where status='WP'）—— **不动余额**
              ├─ members.markCouponUsed + goods.increaseSales
              └─ 服务类商品仍留在 fulfill_status='pending'，等后台「交付」
  主动同步：sysOrder.mySync / sysOrder.sync → OrderService.sync
              ├─ 支付单 CL / FL → cancelOrder 就地自愈关单
              └─ 支付单 OD     → markPaid（与回调同一条幂等路径）

  超时：order:expire-close（每 5 分钟）
    ├─ 本地支付单已是 'OD' → markPaid 补做业务后置（计入 recoveredCount），**不关单**
    └─ 否则 cancelTx(timeout) + 尽力关闭本地支付单 + 回滚库存 / 券 / 冻结
```

## 三、角色与入口

| 角色 | 充值 | 余额支付 / 在线支付 |
| --- | --- | --- |
| 会员（自助，`protectedProcedure`，无权限码） | `sysMember.myRecharge`（发起）、`myRechargeStatus`（只读轮询）、`myRechargeSync`（查渠道并到账或反向关单）、`myCouponCheck`（下单前校验券）、`myRecharges` / `myWallet` / `myLogs` | `sysOrder.myCreate`、`myConfirm`、`myCancel`、`mySync`、`myPayment`（只读本地支付码）、`myPage` / `myDetail` |
| 后台 | `sysMemberRecharge.create`（手工补录，可补成已到账）、`sysMemberRecharge.close`（关闭）、`sysMemberBalanceLog.reconcile` / `rechargeRetry`（一致性校验与未到账补偿）、`sysMemberFreeze.release`（人工释放冻结） | `sysOrder.confirm` / `close` / `sync` / `fulfill`、`sysPayOrder.syncStatus` / `close`（支付单层面的同步与本地关闭） |

页面入口：

| 页面 | 路径 | 做的事 |
| --- | --- | --- |
| 我的余额 | `app/pages/system/wallet/index.vue` | 充值表单 + 优惠码前置校验 + 二维码 + 轮询同步 + 余额 / 流水 / 充值记录 / 券记录 |
| 商城 | `app/pages/system/mall/index.vue` | 选 `payMode`（balance / online）下单；余额单提示「已冻结」并跳我的订单，在线单就地展示二维码并轮询 |
| 我的订单 | `app/pages/system/my-orders/index.vue` | 确认支付 / 取消 / 同步 / 查看支付码 |
| 充值单管理 | `app/pages/system/member-recharge/` | 列表、补录（`manualAdd`）、关闭、详情 |
| 订单管理 | `app/pages/system/order/` | 列表、确认支付、关闭、同步状态、交付、详情 |

权限码：`system:memberRecharge:add|close`、`system:memberBalanceLog:list|reconcile|export`、`system:memberFreeze:list|release`、`system:order:list|edit|del|confirm|close|sync|fulfill`（`server/trade-router/modules/order/index.ts:21-28`、`modules/memberRecharge/index.ts:14-19`、`modules/memberBalanceLog/index.ts:15-18`）。`confirm / close / sync / fulfill` 单独授权，因为它们都会推进状态并牵动资金 / 库存 / 券。

## 五、幂等键全景

这张表是本分组的核心：**业务侧的幂等全部落在「唯一键 + 条件更新」上**，没有任何一把分布式锁。

| 表 | 唯一键（定义处） | 键的取值 | 保证什么 | 命中后的行为 |
| --- | --- | --- | --- | --- |
| `sys_pay_order` | `uk_pay_order_out_trade_no`（`payOrder.ts:46`） | 就是业务单号：`RCH…` / `ORD…`（补录单为 `PAY…`） | 一笔业务只有一张支付单，支付单与业务单一对一 | `createPayment` 撞键直接抛错（预检只是降低概率，最终靠索引） |
| `sys_member_recharge` | `uk_member_recharge_out`（`memberRecharge.ts:31`） | 同上 | 充值单不重复 | 后台补录时转成 `module.system.memberRecharge.outTradeNoExists`（`SysMemberRechargeService.ts:76-81`） |
| `sys_member_balance_log` | `uk_member_log_dedup`（`memberBalanceLog.ts:28`） | `buildDedupKey(bizType, bizNo, account)` = `{bizType}:{bizNo}:{account}`（`wallet/utils.ts:97-99`） | **同一业务事件在同一账户上只写一次流水**，也就是「只加一次钱 / 只扣一次钱」 | 撞键 → `AlreadyAppliedError` → 事务整体回滚 → 外层返回 `reused: true`（`WalletService.ts:275-281`、`:952-961`） |
| `sys_member_freeze` | `uk_member_freeze_biz`（`memberFreeze.ts:28`） | `biz_no = orderNo` | 一个订单只能冻结一次 | `freeze` 撞键 → 回滚后按首次冻结结果返回 `reused: true`（`WalletService.ts:548-553`、`:996-1008`） |
| `sys_member_gift_grant` | `uk_member_gift_biz`（`memberGiftGrant.ts:22`） | 充值赠送为 `{outTradeNo}:gift` | 一批赠送金只建一次 | 撞键 → `AlreadyAppliedError`（`WalletService.ts:369-374`） |
| `sys_member_coupon_use` | `uk_member_coupon_use(coupon_id, biz_no)`（`memberCouponUse.ts:25`） | `biz_no = outTradeNo / orderNo` | 同一单只能用同一张券一次（锁券 + 累计核销数） | `lockCoupon` 撞键 → 返回 `reused: true`（`MemberService.ts:450-455`） |
| `sys_order` | `uk_order_no` / `uk_order_request`（`order.ts:52-53`） | `order_no` 自动生成；`request_id` 由前端每次提交生成 | 订单号唯一 **且** 重复提交只落一单 | 撞 `uk_order_request` → `OrderAlreadySettledError` → 外层按 `requestId` 重读返回 `reused: true`（`OrderService.ts:244-251`、`:627-641`） |
| `sys_pay_notify_log` | `uk_pay_notify_dedup`（`payNotifyLog.ts:36`） | 适配器生成（虎皮椒为 `out_trade_no:provider_status:transaction_id`，刻意不含时间戳 / 随机串） | 同一个平台事件只处理一次 | 已存在且是成功日志 → 直接返回 `duplicate` 且**不再调 `onPaid`**；并发撞键 → 补一条 duplicate 日志（[回调处理与幂等](/docs/main/payment/notify)） |

几处容易看错的取值：

| 业务事件 | `bizType` | `bizNo` | `account` | 完整 `dedup_key` |
| --- | --- | --- | --- | --- |
| 充值金到账 | `recharge` | `RCH…`（充值单号） | `recharge` | `recharge:RCH…:recharge` |
| 赠送金到账 | `recharge` | `RCH…:gift` | `gift` | `recharge:RCH…:gift:gift` |
| 余额消费实扣 | `consume_confirm` | `ORD…`（= 冻结单 `biz_no`） | `gift` / `recharge` | `consume_confirm:ORD…:gift` 等 |
| 赠送金过期扣减 | `gift_expire` | `gift_expire:{批次id}:{金额}` | `gift` | `gift_expire:gift_expire:{批次id}:{金额}:gift` |
| 手工调账 | `adjust` | `adjust:{requestId}`（`buildAdjustBizNo`） | 入参账户 | `adjust:adjust:{requestId}:{account}` |

`consume_confirm` 值得单独记住：它**只在确认瞬间写一次**——`freezes.markConfirmed` 的条件更新（`where status='FROZEN'`）保证同一张冻结单只会走到写流水这一步一次，重复确认在 `WalletService.confirm` 开头就按 `row.status === 'CONFIRMED'` 幂等返回了（`WalletService.ts:582-584`）。反向也成立：**释放冻结不写 `consume_confirm`**，只写 `sys_member_freeze`。

## 六、状态一览

| 单据 | 字段 | 取值 | 说明 |
| --- | --- | --- | --- |
| 充值单 | `sys_member_recharge.status` | `WP` / `OD` / `CL` / `FL` | `OD` 是终态且是唯一「钱已入账」的证据；`WP` 待支付；`CL` 人工关闭；`FL` 发起支付就失败（`RechargeService.ts:47-48` 与支付单状态语义一致） |
| 订单（资金） | `sys_order.status` | `WP` / `OD` / `CL` / `FL` | 与充值单同构（`domain/order/types.ts:10`）；`markCompleted` / `markClosed` / `markFailed` 都只从 `WP` 出发 |
| 订单（履约） | `sys_order.fulfill_status` | `none` / `pending` / `delivered` | 与资金维度分开（`types.ts:12`）；服务类商品下单即 `pending`（`OrderService.ts:236`），后台「交付」推到 `delivered` |
| 冻结单 | `sys_member_freeze.status` | `FROZEN` → `CONFIRMED` / `RELEASED` / `EXPIRED` | 所有流转都是 `where status='FROZEN'` 的条件更新（`freezeRepo.ts:44-79`） |
| 赠送金批次 | `sys_member_gift_grant.status` | `active` / `used` / `expired` | `used` 是余量用尽，`expired` 是过期清零；两者都由条件更新推进（`giftGrantRepo.ts:69-109`） |
| 券使用记录 | `sys_member_coupon_use.status` | `locked` → `used` / `released` | `markUsed` / `markReleased` 都带 `where status='locked'`，因此「释放后再核销」不会生效（`couponUseRepo.ts:65-88`） |
| 支付单 | `sys_pay_order.status` | `WP` / `OD` / `CD` / `CL` / `FL` / `RF` | 见[支付模块总览](/docs/main/payment/overview)的状态表；`RF` 无写入方 |
