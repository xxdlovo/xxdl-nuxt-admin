## 模块与配置

`nuxt.config.ts` 中的 i18n 配置：

```ts
i18n: {
  strategy: 'no_prefix',          // 路由不带 /zh、/en 前缀
  localeCookie: 'i18n_locale',    // 统一语言 Cookie 名
  locales: [en, zh],
  defaultLocale: 'en',
  translationDir: 'app/locales',
  meta: true
}
```

`strategy: 'no_prefix'` 意味着页面路径始终不含语言段，语言只由 Cookie 决定。

## 翻译文件结构

唯一书写落点：`app/locales/zh.json` 与 `app/locales/en.json`。顶层键为：

```text
system | auth | common | request | theme | route | module
page | form | dropdown | icon | datatable
```

业务文案全部写在 `module` 下，按模块层级嵌套：

```json
{
  "module": {
    "system": {
      "ossConfig": { "title": "OSS 配置" }
    },
    "demo": { "field1": "字段一" }
  }
}
```

模块目录 `system/ossConfig` 对应 key 前缀 `module.system.ossConfig`，代码中写作 `$ts('module.system.ossConfig.title')`。

> 不要手写 `app/locales/pages/**` 与 `server/assets/_locales/**`：这两个目录是 `nuxt-i18n-micro` 构建时生成的产物，手写内容会在下次构建被覆盖。

## $ts 的用法

`nuxt-i18n-micro` 注入两个翻译函数，项目统一使用返回字符串的 `$ts`：

| 函数 | 返回类型 | 说明 |
| --- | --- | --- |
| `$ts(key, params?, defaultValue?)` | `string` | 项目标准用法 |
| `$t(key, params?, defaultValue?)` | 非字符串的干净结果 | 需要字符串时需额外断言，项目里一般不用 |

```vue
<span>{{ $ts('module.demo.title') }}</span>
<UButton :label="$ts('common.search')" />
<span>{{ $ts('datatable.itemCount', { total: pagination.total }) }}</span>
```

- 未命中的 key 会回退为 key 本身，便于发现漏翻译。
- 带参数时用 `{ name }` 插值占位。

获取方式：

```ts
const { $ts } = useI18n()          // 脚本中
const { $ts } = useNuxtApp()       // 也常见于工具函数
```

## 语言切换

`app/components/base/BaseSwitchLocal.vue` 是语言切换组件：

- 通过 `useI18n()` 的 `$getLocales()` / `$switchLocale()` / `$getLocale()` 工作。
- 切换时同时写 `i18n_locale` Cookie（`maxAge` 一年），服务端错误翻译会读同一个 Cookie。
- 首次渲染时如果 Cookie 不存在，会用模块已解析出的当前语言初始化，避免重启后回退英文。

可见性由 `theme.general.localeVisible` 控制，可在主题抽屉的通用设置中开关。

## 与请求链路的配合

- tRPC 客户端在每次请求带上 `x-locale` 与 `accept-language`（取自 `i18n_locale` Cookie），服务端 `errorFormatter` 据此选择语言。
- 服务端非 tRPC 端点使用 `createServerT(event)`；`errorFormatter` 使用 `createLocaleT(locale)`。两者都直接读取 `app/locales/*.json`。
- 表格列在语言切换后会自动重建：`useTable` 内部 `watch(() => i18n.locale, reloadColumns)`，前提是列配置写成函数或 `computed`。

## 需要展示字典文案的场景

字典项的 `label` 或 `i18nKey` 同样走翻译：

- `useDictOptions(code)` / `useDictNumberOptions(code)`：把字典值转成 `USelect` 可用的选项并翻译。
- `useDictBadgeConfig(code)`：把字典值转成徽标配置（颜色 + i18nKey），配合 `useBadgeColumn` 使用。
- `translateOptions(options)`（`app/utils/common.ts`）：把常量表转成带翻译的选项。
- `useTransformRecordToOption(record)`：把 `Record<value, i18nKey>` 转成选项。

## 新增文案的步骤

1. 在 `app/locales/zh.json` 的 `module.<模块>` 下添加中文文案。
2. 在 `app/locales/en.json` 的同一路径添加英文文案，保持键结构一致。
3. 代码中使用 `$ts('module.<模块>.<key>')` 引用，模板与脚本都不用硬编码中文。
4. 表单校验消息如果是 i18n key（包含 `.`），`useZodValidation` 会自动翻译。
