## 权限模型速览

- 服务端是唯一的鉴权关口：`permissionMiddleware` 按权限码校验，管理员（`isAdmin === 1`）直接放行。
- 前端只做**展示控制**：按权限码决定按钮、列、菜单是否可见，不承担安全职责。
- 权限码格式为 `<资源>:<动作>`，例如 `system:user:list`、`system:user:add`。

生成规则定义在 `shared/auth/permission.ts`：

```ts
crudPermissionCodes('system:user')
// { list: 'system:user:list', add: '...:add', edit: '...:edit', del: '...:del' }

customPermissionCode('system:user', 'resetPwd') // 'system:user:resetPwd'
```

## useCrudPermissions

`app/composables/useCrudPermissions.ts` 为单个资源生成一整套判定：

```ts
const demoPermissions = useCrudPermissions('demo')
```

| 返回值 | 含义 |
| --- | --- |
| `codes` | `{ list, add, edit, del }` 四个权限码，用于传给组件或 `v-permission` |
| `canList` / `canAdd` / `canEdit` / `canDel` | 对应动作是否可用（管理员恒为 `true`） |
| `canOperate` | 有编辑或删除权限，用于决定是否渲染操作列 |

典型用法：

```vue
<TableHeaderOperation
  :add-permission="demoPermissions.codes.add"
  :delete-permission="demoPermissions.codes.del"
/>

<!-- 列内按钮 -->
<UButton v-if="demoPermissions.canEdit.value" @click="handleEdit(row.original.id)" />
```

## useRbacProfile 与 rbacProfile store

`useRbacProfile()` 包装了 `app/stores/rbacProfile.ts`：

| 返回项 | 说明 |
| --- | --- |
| `profile` | `auth.profile` 的返回结果，含 `user`、`permissions`、`menus` |
| `username` / `isAdmin` | 常用派生值 |
| `loadProfile(force?)` | 拉取档案；默认命中缓存，权限变更后传 `true` 强制刷新 |
| `clearProfile()` | 登出或切换账号时清空 |
| `hasPermission(code)` / `hasAnyPermission(codes)` / `hasAllPermissions(codes)` | 权限判定 |

store 内部用 `Set` 缓存 `permissions`，判定是同步的，可安全用在模板与渲染函数中。

## v-permission 指令

注册于 `app/plugins/permission.ts`，支持单个权限码或数组：

```vue
<UButton v-permission="'system:user:add'">新增</UButton>
<UButton v-permission="['system:user:edit', 'system:user:del']">操作</UButton>
```

行为约定：

- 档案未加载时先隐藏元素（`display: none`），加载后满足条件再恢复。
- 管理员或拥有任意一个权限码时显示；否则**直接从 DOM 中移除**该元素。
- 指令内部用 `effectScope` 管理 watcher，元素卸载时一并停止。

## 菜单如何渲染

服务端通过 `auth.profile` 返回菜单树，`app/utils/navigation.ts` 提供转换与查找工具：

| 函数 | 用途 |
| --- | --- |
| `toNavigationItems` / `toDropdownMenuItems` | 菜单树 → Nuxt UI 导航项 |
| `getRenderableMenus` | 过滤掉 `type === 2`（按钮）的节点 |
| `isClickableMenu` | 有 `path` 且非目录时才算可点击 |
| `findMenuByPath` / `findMenuTrail` | 按路径查找菜单与面包屑链路 |
| `resolveActiveTrail` | 高亮当前菜单链路，找不到时回退第一项 |
| `normalizeNavigationIcon` / `normalizeMenuIcon` | 把 `lucide:home` 之类写法规范成 `i-lucide-home` |

`app/layouts/system.vue` 取 `profile.menus` 渲染菜单，并在 `onMounted` 中 `loadProfile()`。

## 登录状态切换时的清理

`app/utils/common.ts` 提供统一入口：

```ts
afterUserLogin(username)
```

它会清空 RBAC 档案、字典缓存，并关闭全部标签页（保留不可关闭项）。切换账号或登出后必须调用，否则会残留上一个用户的菜单与权限。

## 新增一个受控资源的清单

1. 服务端 router 中使用 `crudPermissionProcedures('<资源码>')` 或 `proc({ permission: customPermissionCode(...) })`。
2. 在菜单管理里新增菜单与按钮记录，按钮权限码必须与代码一致（例如 `system:job:run`）。
3. 给角色分配对应权限，用户重新登录或刷新档案后生效。
4. 前端用 `useCrudPermissions('<资源码>')` 控制按钮、列与 `TableHeaderOperation`。
