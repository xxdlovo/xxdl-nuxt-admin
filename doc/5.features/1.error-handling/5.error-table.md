## 通用与系统级

| 场景 | 抛出位置 | i18nKey | 文案（中文） | tRPC code / HTTP | 前端表现 |
| --- | --- | --- | --- | --- | --- |
| 未登录访问受保护接口 | `authMiddleware` | `auth.unauthorized` | 请先登录 | `UNAUTHORIZED` / 401（`errorFormatter` 强制改写） | Toast：请先登录 |
| 已登录但无权限码 | `permissionMiddleware` | `auth.forbidden` | 无权限 | 沿用 tRPC 默认 | Toast：无权限 |
| demo 模式调用只读变更接口 | `demoReadonlyMiddleware` | `system.demoReadonly` | 演示环境不允许操作 | 沿用 tRPC 默认 | Toast：演示环境不允许操作 |
| 请求体不符合 Zod schema | tRPC `.input()` | `system.zodError` | 校验错误 | 沿用 tRPC 默认 | Toast 标题「校验错误」，描述为聚合后的字段消息 |
| 数据库异常 | Repo 层 | `system.dbError` | 数据库错误 | 沿用 tRPC 默认 | Toast：数据库错误（开发环境可看到堆栈） |
| 未归类的服务端异常 | 任意位置 | `system.serverError` | 服务端错误 | 沿用 tRPC 默认 | Toast：服务端错误 |
| 未指定具体 key 的通用业务失败 | 任意 Service | `common.notExist` | 查询数据不存在 | 沿用 tRPC 默认 | Toast：查询数据不存在 |
| 校验无字段错误可展示 | `errorFormatter` 兜底 | `common.pleaseCheckValue` | 请检查输入的值是否合法 | 沿用 tRPC 默认 | 同 Zod 错误 |

## 存储桶相关的 tRPC 错误

`SysStorageService` 是当前唯一直接抛 `TRPCError` 的服务，它与 `AppError` 的差异是**不会走 i18n 翻译**：

| 场景 | code | HTTP | message |
| --- | --- | --- | --- |
| key 含绝对路径、`..` 或空段 | `BAD_REQUEST` | 400 | `Invalid storage key` |
| 资源路径不在 `server/storage` 内 | `BAD_REQUEST` | 400 | `Resource path must be inside server/storage` |
| 访问不存在的 key | `NOT_FOUND` | 404 | `Storage key not found` |
| 读取的内容不是合法 JSON | `BAD_REQUEST` | 400 | `Storage value is not valid JSON` |

这些消息是固定的英文常量，前端会直接展示。如果需要中文提示，调用方应在此之前用 `AppError` 拦截。

## 关于 code 与 HTTP 状态的现状说明

`errorFormatter` 只对 `auth.unauthorized` 一个 key 改写了 `code` 与 `httpStatus`：其余 `AppError` 由 tRPC 包装后仍是 `INTERNAL_SERVER_ERROR`（HTTP 500）。

这带来两个可观察的行为：

1. `retryLink` 会把这类失败当作 5xx，对 `query` 自动重试一次；
2. 前端拿到的 `code` 不能用来区分业务错误类型，需要区分时请判断 `i18nKey`。

需要返回 400 类错误时，改用 `throw new TRPCError({ code: 'BAD_REQUEST', message })`，代价是失去自动翻译。选择建议：

| 需求 | 推荐写法 |
| --- | --- |
| 需要多语言文案 | `AppError(i18nKey)` |
| 需要 4xx 语义、避免 query 重试，文案可固定 | `TRPCError({ code: 'BAD_REQUEST', message })` |
