## 数据模型

**配置表 `sys_oss_config`**（决定「传到哪儿、怎么连」）：

| 字段 | 说明 |
| --- | --- |
| `config_key` / `config_name` | 配置标识与显示名 |
| `service` | 服务商标识：`aliyun`、`aws`、`tencent` |
| `endpoint` / `region` / `bucket_name` / `domain` | 连接与访问地址信息 |
| `access_key` / `secret_key` | 访问凭据 |
| `prefix` | 对象键前缀，用于按业务分目录 |
| `is_https` | 是否使用 HTTPS |
| `access_policy` | 访问策略 |
| `is_default` | 是否默认配置 |
| `verify_status` / `verify_time` / `verify_message` | 连通性验证结果 |
| `status` | 启用状态 |

**记录表 `sys_oss`**（决定「传了什么」）：`config_id`、`file_name`（对象键中的文件名）、`original_name`（用户原始文件名）、`file_suffix`、`content_type`、`bucket_name`、`object_name`、`url`、`md5`、`etag`、`service`、`upload_user_id`、`status`。

## 服务商适配器

`server/sys-router/ossConfig/providers/index.ts` 维护服务商表：

```ts
const providers: Record<string, OssProvider> = {
  aliyun: aliyunProvider,
  aws: awsProvider,
  tencent: tencentProvider
}
```

- `getOssProvider(service)` 按小写匹配，未命中返回 `null`；
- 业务层拿到 `null` 时抛 `AppError('module.system.oss.uploadProviderUnsupported')`；
- 当前没有本地文件系统适配器，新增服务商需要实现 `OssProvider` 接口（`upload` / `verify`）并在该表注册。

## 上传主流程

`SysOssService.uploadFile({ configId, fileName, contentType, body })` 的步骤：

```text
1. 校验 fileName 非空            → 否则 AppError('module.system.oss.uploadFileRequired')
2. 校验 configId 非空            → 否则 AppError('module.system.oss.uploadConfigRequired')
3. 取「启用且验证通过」的配置       → 取不到则 AppError('module.system.oss.uploadConfigUnavailable')
4. getOssProvider(config.service) → 未命中则 AppError('module.system.oss.uploadProviderUnsupported')
5. objectName = createObjectKey(config.prefix, fileName, id)
6. provider.upload({ objectKey, body, contentType }) → 得到 url / etag
7. md5 = md5(body)
8. 写 sys_oss 记录（含上面全部信息与 uploadUserId）
9. 返回记录
```

关键细节：

- 对象键由 `createObjectKey(prefix, fileName, uuid)` 生成，`id` 与对象键中的文件名同源，避免同名覆盖；
- 传给 provider 的是 `Uint8Array`，端点侧负责把 `Buffer` 转成 `Uint8Array`；
- `contentType` 缺省为 `application/octet-stream`。

## 连通性验证

`verifyOssConfig(config)`（`OssConfigVerifier.ts`）返回 `{ success, message }`：

| 情况 | 结果 |
| --- | --- |
| 未填 `service` | `success: false`，`message: '存储服务类型不能为空'` |
| 服务商不支持 | `success: false`，`message: '暂不支持 {service} 的自动验证'` |
| `provider.verify` 成功 | `success: true`，`message: '验证通过'` |
| `provider.verify` 抛错 | `success: false`，`message` 为异常信息 |

验证结果会写回 `verify_status` / `verify_time` / `verify_message`。只有验证通过的配置才能被上传流程选中，因此**新增配置后必须先验证再上传**，否则会得到「存储配置未启用、未验证或不可用」。

## 后台页面

| 页面 | 路由 | 作用 |
| --- | --- | --- |
| OSS 文件管理 | `/system/oss` | 查看上传记录、上传新文件、删除记录 |
| OSS 配置管理 | `/system/oss-config` | 新增/编辑配置、触发验证、设默认配置 |

权限码：`system:oss:list|add|edit|del`、`system:ossConfig:list|add|edit|del`（由 `crudPermissionCodes` 生成）。
