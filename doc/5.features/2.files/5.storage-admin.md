## 路由与权限

`server/sys-router/storage/index.ts` 只做三件事：权限声明、入参校验、调用服务类。

| 接口 | 类型 | 权限码 |
| --- | --- | --- |
| `sysStorage.list` | query | `system:storage:list` |
| `sysStorage.get` | query | `system:storage:list` |
| `sysStorage.remove` | mutation | `system:storage:del` |

删除被单独授权（`system:storage:del`）是因为它属于敏感操作；即便如此，删除接口的入参 schema 也只接受 `memory` 桶，资源桶没有删除通道。

## 入参 schema

```ts
/** 存储管理允许访问的两个逻辑桶。assets 默认对应 server/storage。 */
export const StorageBucketSchema = z.enum(['memory', 'assets'])

export const SysStorageListSchema = z.object({
  bucket: StorageBucketSchema,
  prefix: z.string().max(200).optional(),
  resourcePath: z.string().max(300).optional(),
  page: z.number().int().min(1).default(1),
  pageSize: z.number().int().min(1).max(100).default(20)
})

export const SysStorageGetSchema = z.object({
  bucket: StorageBucketSchema,
  key: z.string().min(1).max(500),
  resourcePath: z.string().max(300).optional()
})

export const SysStorageRemoveSchema = z.object({
  bucket: z.literal('memory'),
  key: z.string().min(1).max(500)
})
```

注意 `pageSize` 上限为 100，`key` 是桶内相对 key（不要带 `storage` 前缀，服务类会自行补全）。

## 页面用法

页面位置：`app/pages/system/storage/index.vue`，入口为「系统 → 存储管理」。

| 操作 | 说明 |
| --- | --- |
| 切换桶 | 在 `memory` 与 `assets` 之间切换；`assets` 桶不显示删除按钮 |
| 前缀筛选 | 传入逻辑前缀（如 `cache:rbac:`）缩小列表范围 |
| 分页浏览 | 按 key 的字典序排序，默认每页 20 条 |
| 查看详情 | 展示 `valueType`、`size`、`updatedAt`、`mimeType` 与格式化预览 |
| 删除 | 仅 `memory` 桶可用，删除后不可恢复 |

预览行为：字符串或 JSON 会尝试格式化并截断到 10000 字符；二进制内容 `previewable` 为 `false`，不返回预览。

## 排查手册

### 缓存看起来没生效

1. 打开存储管理页，桶选 `memory`，前缀填 `cache:`；
2. 确认目标 key 是否存在，例如字典为 `cache:dict:{encodeURIComponent(编码)}`，RBAC 为 `cache:rbac:user:{id}:roles`；
3. key 不存在 → 说明写缓存未执行或已过期（读路径会按 miss 处理并回源）；
4. key 存在但数据仍是旧值 → 说明写操作后没有执行对应的 `invalidate`，可对照 `/docs/features/cache/conventions` 检查。

### 读不到只读资源

- 确认文件确实位于 `server/assets/storage/**`；`server/storage/` 目录当前只有 `.gitkeep`；
- 确认 `resourcePath` 落在 `server/storage` 之下，否则会得到 `Resource path must be inside server/storage`；
- `readString` 返回 `null` 表示 key 不存在，不会抛错，业务侧要显式判断。

### 报 `Invalid storage key`

按 `/docs/features/files/nitro-storage` 的 key 规则逐条核对，最常见的原因是：

- 传了以 `/` 开头的路径；
- 把完整 key（含 `storage:` 或 `assets:` 前缀）当作相对 key 传入；
- key 中含 `..` 或连续冒号导致出现空段。

### 预览是空的

- 值为二进制（`Uint8Array` / `Buffer`）时不生成预览；
- 值过大时只返回前 10000 字符，属预期行为；
- JSON 解析失败会退回原始字符串，而不是报错。
