## 两个逻辑桶

| 桶 | 底层 | 读写 | 用途 |
| --- | --- | --- | --- |
| `memory` | `memory` driver（进程内存） | 可读可写可删 | 缓存、临时业务数据 |
| `assets` | `server/assets` 的只读挂载 | 只读 | 随代码发布的只读资源、配置、静态数据 |

代码中的取用方式：

```ts
// 业务临时数据命名空间
const memory = useStorage('memory')

// Nitro 对 server/assets 提供的只读挂载；不要使用默认的 useStorage()
const resources = useStorage('assets:server')
```

`nuxt.config.ts` 里为 `memory` 单独声明了 driver：

```ts
nitro: {
  // 业务临时数据使用独立的 memory 命名空间，避免误读 Nitro 默认
  // storage 中的 data、cache、root、build 等框架内部内容。
  storage: {
    memory: { driver: 'memory' }
  }
}
```

> 因此业务代码不要直接使用不带命名空间的 `useStorage()`，那会落到 Nitro 内部 key 空间。

## SysStorageService 能力清单

`server/sys-router/storage/SysStorageService.ts` 是唯一入口，服务类内部固定使用 `memory` 与 `assets:server` 两个桶：

| 方法 | 说明 |
| --- | --- |
| `list({ bucket, prefix?, resourcePath?, page, pageSize })` | 分页列出条目，返回 `{ list, page, pageSize, total }` |
| `get({ bucket, key, resourcePath? })` | 取单条详情，含安全预览；key 不存在抛 `NOT_FOUND` |
| `readString(relativePath, resourcePath?)` | 读取只读资源为 UTF-8 字符串，不存在返回 `null` |
| `readJson<T>(relativePath, resourcePath?)` | 读取并解析 JSON，格式非法抛 `BAD_REQUEST` |
| `readBuffer(relativePath, resourcePath?)` | 读取原始二进制，便于下载、哈希或 MIME 处理 |
| `removeMemory(key)` | 仅删除 memory 桶中的 key |
| `getCache` / `setCache` / `removeCache` / `clearCache` / `rememberCache` | 缓存能力，见 `/docs/features/cache/api` |

列表条目的视图字段：

| 字段 | 说明 |
| --- | --- |
| `key` | 桶内相对 key（已去掉资源根前缀） |
| `valueType` | `string` / `object` / `array` / `number` / `boolean` / `null` / `binary` |
| `size` | 优先取存储元数据，缺失时按值计算字节数 |
| `updatedAt` | 由 `mtime` 归一为 ISO 字符串，无元数据时为 `null` |
| `previewable` | 二进制为 `false` |
| `preview` | 详情接口返回，文本/JSON 格式化后截断到 10000 字符 |
| `mimeType` | 详情接口返回，来源为存储元数据 |

## key 安全规则

所有 key 都经过 `normalizePath` 归一化，命中任一条即抛 `BAD_REQUEST`（message 为 `Invalid storage key`）：

- 空字符串；
- 以 `/` 开头的绝对路径；
- 形如 `C:/...` 的 Windows 盘符路径；
- 包含空段、`.` 或 `..` 段；
- **冒号会被视作层级分隔符**，因此 `foo:..:bar` 这类写法同样会被拒绝（只校验斜杠是不够的）。

资源桶另有约束：传 `resourcePath` 时必须是 `server/storage` 本身或其子路径，否则抛 `Resource path must be inside server/storage`。默认根目录为 `server/storage`，完整写法（`server/storage/xxx`）与相对写法都可接受。

## 只读约束

资源桶永远只读，这一点在 schema 层就锁死了：

```ts
/** 删除接口明确限定为 memory 桶，资源桶永远只读。 */
export const SysStorageRemoveSchema = z.object({
  bucket: z.literal('memory'),
  key: z.string().min(1).max(500)
})
```

列表查询也做了收敛：以限定根路径调用 `getKeys`，过滤 `:$` 结尾的伪 key 与 `.gitkeep`，不枚举 `server/assets` 下的其它内容。

## 目录现状

| 路径 | 现状 | 说明 |
| --- | --- | --- |
| `server/assets/storage/` | 只读资源挂载点 | `assets:server` 桶的实际目录 |
| `server/storage/` | 仅含 `.gitkeep` | 计划中的资源根目录，当前没有业务资源文件 |

> 写代码或写文档时请以实际目录内容为准：`server/storage` 目前是空目录，不要假设其中已有配置文件。

## 使用示例

```ts
import { sysStorageService } from '#server/sys-router/storage/SysStorageService'

const storage = sysStorageService()

// 读取只读 JSON 配置
const config = await storage.readJson<{ enabled: boolean }>('server/storage/feature.json')

// 列出 memory 桶中以 tmp: 为前缀的条目
const page = await storage.list({ bucket: 'memory', prefix: 'tmp:', page: 1, pageSize: 20 })

// 删除 memory 桶中的临时数据
await storage.removeMemory('tmp:import:123')
```
