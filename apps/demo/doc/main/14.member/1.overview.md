title: 会员体系总览
description: 会员体系的八块能力边界、12 张表与关键唯一键、domain/member 与 domain/wallet 的分层和文件地图、8 个后台页面的权限码，以及与交易/支付/对外集成三个分区的分工。

会员体系解决「这个用户是谁的会员、是什么等级、等级值多少能力、他的钱够不够扣」这一组问题。代码分成两个领域：`domain/member`（档案、等级、开通单、优惠码）与 `domain/wallet`（余额、冻结、赠送金批次、流水、充值、对账），对外通过 `modules/*` 暴露 tRPC 接口，后台是 8 个页面。

## 一、能力边界

| 能力 | 落地位置 | 边界说明 |
| --- | --- | --- |
| 会员档案 | `sys_member` | 一行一个用户（`uk_member_user`）；建档时必生成 8 位邀请码（`generateInviteCode`） |
| 等级定义 | `sys_member_level` | 价格、时长、是否长期、是否默认等级；`uk_member_level_code` 保证 `code` 唯一 |
| 等级能力 | `sys_member_feature` + `sys_member_level_feature` | 目录 + 矩阵两级，见[等级能力与配额](/docs/main/member/level-feature) |
| 期限 | `sys_member.expire_at` | `NULL` = 永不过期；到期由 `member:expire-level` 回落默认等级 |
| 开通 / 续费 | `sys_member_level_order` | 三条支付通道（free / balance / online），见[开通与续费](/docs/main/member/open-renew) |
| 余额与钱包 | `sys_member_wallet` + `sys_member_balance_log` | 双账户（充值金 / 赠送金）+ 两列冻结，见[余额与钱包](/docs/main/member/wallet) |
| 优惠码 | `sys_member_coupon` + `sys_member_coupon_use` | 单张、不叠加，见[优惠码](/docs/main/member/coupon) |
| 定时任务与对账 | `packages/admin-trade/server/jobs/handlers.ts` | 5 个会员任务 + 1 个订单任务，默认全部禁用，见[定时任务与运维](/docs/main/member/jobs) |

反向边界，避免误解：

- **等级价不在这里。** 商品 × 等级的专属价是 `sys_goods_level_price`，属[交易模块](/docs/main/trade/overview)；会员体系只提供等级本身。
- **支付单不在这里。** 在线开通、充值都复用[支付模块](/docs/main/payment/overview)的支付单，会员侧只存 `pay_order_id` 与渠道快照。
- **开通单不吃优惠码。** `MemberLevelOrderService` 里没有 `resolveCoupon` / `lockCoupon`；优惠码只作用于充值与商品消费。
- **邀请关系只是档案上的三个字段**（`invite_code` / `inviter_id` / `invite_code_id`）加一张 `sys_member_invite_code`，本分区不展开。
- **没有退等级 / 退款流程。** 等级只能靠手工调整或到期降级；余额扣减后没有反向打款接口。

## 二、数据模型一览（12 张表）

下表 12 张表的 Schema 文件都在 `packages/admin-trade/server/drizzle/schema/system/` 目录下，文件名见「Schema」列（同目录的 `memberInviteCode.ts` 是邀请码表，不在本表内）。

| 表 | Schema | 用途 | 关键唯一键 |
| --- | --- | --- | --- |
| `sys_member` | `member.ts` | 会员档案：等级、期限、来源、邀请关系 | `uk_member_user(user_id)`、`uk_member_invite_code(invite_code)` |
| `sys_member_level` | `memberLevel.ts` | 等级字典：价格 / 时长 / 长期 / 默认 | `uk_member_level_code(code)` |
| `sys_member_feature` | `memberFeature.ts` | 功能目录（受控能力清单） | `uk_member_feature_key(feature_key)` |
| `sys_member_level_feature` | `memberLevelFeature.ts` | 等级 × 功能取值矩阵 | `uk_member_level_feature(level_id, feature_key)` |
| `sys_member_level_order` | `memberLevelOrder.ts` | 等级开通 / 续费单据（含手工留痕） | `uk_member_level_order_out(out_trade_no)`、`uk_member_level_order_request(request_id)` |
| `sys_member_wallet` | `memberWallet.ts` | 钱包主表：两个余额列 + 两个冻结列 + 三个累计列 | `uk_member_wallet_user(user_id)` |
| `sys_member_balance_log` | `memberBalanceLog.ts` | 余额流水（唯一的账实依据） | `uk_member_log_dedup(dedup_key)` |
| `sys_member_freeze` | `memberFreeze.ts` | 消费冻结单（预扣占位） | `uk_member_freeze_biz(biz_no)` |
| `sys_member_gift_grant` | `memberGiftGrant.ts` | 赠送金批次（按批过期） | `uk_member_gift_biz(biz_no)` |
| `sys_member_recharge` | `memberRecharge.ts` | 充值单 | `uk_member_recharge_out(out_trade_no)` |
| `sys_member_coupon` | `memberCoupon.ts` | 优惠码定义 | `uk_member_coupon_code(code)` |
| `sys_member_coupon_use` | `memberCouponUse.ts` | 优惠码锁定 / 核销 / 释放记录 | `uk_member_coupon_use(coupon_id, biz_no)` |

建表与菜单、任务由 3 个脚本分工，都是**只新增**、按 `job_code` / `uk_*` 幂等：

| 脚本 | 负责的表 | 附带内容 |
| --- | --- | --- |
| `packages/admin-trade/sql/mysql-ddl-member-balance.sql` | 建 10 张：等级、档案、邀请码、优惠码、使用记录、钱包、赠送金批次、余额流水、冻结单、充值单 | 37 行菜单 + 4 条任务（`status = 0`） |
| `packages/admin-trade/sql/mysql-ddl-member-level-price.sql` | 建 `sys_member_level_order`；给等级加价格 / 期限列，给档案加 `expire_at` / `level_start_at` / `level_source`，补 `request_id` 唯一键与列注释 | 1 条任务 `member:expire-level` |
| `packages/admin-trade/sql/mysql-ddl-member-entitlement.sql` | 建功能目录 + 等级矩阵 2 张 | 6 行菜单（含 `system:memberLevel:feature`） |

## 三、领域与模块分层

```text
tRPC 控制层   modules/{member,memberLevel,memberLevelOrder,memberCoupon,
                       memberRecharge,memberFreeze,memberBalanceLog,memberFeature}/index.ts
                 │  只声明权限码、入参 schema 与登录要求
                 ▼
模块 Service  modules/*/Sys*Service.ts        归属校验、日志、后台动作编排
                 │
                 ▼
领域服务      domain/member/MemberService.ts          建档 / 邀请 / 改等级 / 优惠码 / 到期降级
              domain/member/MemberLevelOrderService.ts 三条通道 / 生效 / 关闭 / 同步 / 手工留痕
              domain/member/levelOpenPolicy.ts         可开通决策（全项目唯一一份）
              domain/wallet/WalletService.ts           入账 / 调账 / 冻结 / 确认 / 释放 / 过期 / 对账
              domain/wallet/RechargeService.ts         充值发起 / 到账 / 关闭 / 未到账补偿
                 │  不写 SQL，只 import ./repo/*
                 ▼
mapper 层     domain/member/repo/{memberRepo,levelRepo,levelOrderRepo,couponRepo,couponUseRepo}.ts
              domain/wallet/repo/{walletRepo,balanceLogRepo,freezeRepo,giftGrantRepo,rechargeRepo}.ts
```

| 约定 | 做法 | 依据 |
| --- | --- | --- |
| 事务边界 | 领域工厂都收 `AppExecutor`；写方法自带事务，已在事务里的调用方用 `memberServiceIn(tx)` / `walletServiceIn(tx)` / `memberLevelOrderServiceIn(tx)` | `packages/admin-trade/server/trade-router/domain/member/MemberService.ts` |
| 唯一写入口 | 余额只能经 `WalletService` 改；改等级只能经 `MemberService.changeLevel` | 同上、`packages/admin-trade/server/trade-router/domain/wallet/WalletService.ts` |
| 单调链 | 会员档案没有等级时**不阻断**能力解析，全部回落目录默认值 | `packages/admin-trade/server/utils/entitlementSource.ts` |
| 等级规则 | 开通决策只写在 `resolveLevelOpenDecision`，列表与落单共用 | `packages/admin-trade/server/trade-router/domain/member/levelOpenPolicy.ts` |

## 四、权限码清单

后台接口用 `proc({ permission })` 声明权限码，来源是 `sys_menu.code`（规则见[权限模型](/docs/main/reference/rbac)）。

| 模块（页面） | 权限码 |
| --- | --- |
| 会员管理 `/system/member` | `system:member:list` / `:add` / `:edit` / `:del` / `:adjust`（手工调账）/ `:grant`（发赠送金）/ `:level`（改等级） |
| 会员等级 `/system/member-level` | `system:memberLevel:list` / `:add` / `:edit` / `:del` / `:feature`（保存能力矩阵） |
| 会员开通记录 `/system/member-level-order` | `system:memberLevelOrder:list` / `:edit`（关闭）/ `:query`（同步）/ `:del` |
| 优惠码管理 `/system/member-coupon` | `system:memberCoupon:list` / `:add` / `:edit` / `:del` / `:void`（作废） |
| 充值记录 `/system/member-recharge` | `system:memberRecharge:list` / `:add` / `:edit` / `:del` / `:close` |
| 消费冻结单 `/system/member-freeze` | `system:memberFreeze:list` / `:edit` / `:del` / `:release`（**没有 add**，单据只由领域层写） |
| 余额流水 `/system/member-balance-log` | `system:memberBalanceLog:list` / `:reconcile`（对账）/ `:export`（导出，带操作日志） |
| 功能与配额 `/system/member-feature` | `system:memberFeature:list` / `:add` / `:edit` / `:del` |

三点细节：

- **高敏感动作单独授码**：`adjust` / `grant` / `level` / `feature` / `void` / `release` / `query` / `reconcile` 都不与 `edit` 混用，便于只读与客服角色整组排除。
- **数据范围**：功能目录（`sys_memberFeature`）与等级下拉（`system:memberLevel:list` 的 `list`）用 `dataScope: false` 跳过数据权限，否则只读角色会看到被 `created_by` 收窄的空目录，导致能力解析与后台看到的功能集合不一致。
- **菜单里有、接口没用**：`sys_menu` 里存在 `system:memberBalanceLog:edit` 与 `:del` 两行按钮，但流水 router 只实现了 `list` / `reconcile` / `export`——流水是账实凭证，不给改删入口。

会员自助接口用 `protectedProcedure`（只要求登录）：`myWallet` / `myProfile` / `myEntitlements` / `myLogs` / `myRecharges` / `myRecharge` / `myRechargeSync` / `myCoupons` / `myLevelOptions` / `myOpenLevel` / `myLevelOrderStatus` / `myLevelOrderSync`，全部在 Service 层按 `ctx.user.id` 收敛归属。

## 五、与其它三个分区的分工

| 分区 | 它负责 | 本分区不重复的内容 |
| --- | --- | --- |
| [交易模块](/docs/main/trade/overview) | 商品、等级价、订单、库存、履约 | 等级价表 `sys_goods_level_price`、订单侧 `consume_confirm` 流水口径 |
| [支付模块](/docs/main/payment/overview) / [端到端支付流程](/docs/main/payment-flow/overview) | 支付单、渠道、回调分派、充值到账链路 | 支付单状态机、回调幂等、充值七步流程（[充值流程](/docs/main/payment-flow/recharge)）、[账实一致与补偿](/docs/main/payment-flow/consistency) |
| [对外集成](/docs/main/public-api/overview) | 宿主应用怎么调用 | 稳定的门面 API：能力与配额见[entitlement](/docs/main/public-api/entitlement)、余额与交易见[billing](/docs/main/public-api/billing) |

一句话分工：**本分区讲「后台怎么配、数据怎么落、任务怎么跑」，对外集成分区讲「代码里怎么调」**。同一件事两边各写一半时，配置侧以本分区为准，调用侧以对外集成分区为准。
