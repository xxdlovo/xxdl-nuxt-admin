「等级能给什么能力」在库里是两张表：目录（有哪些受控能力）+ 矩阵（某个等级对这些能力的取值）。后台两个入口都在维护这两张表，服务端与前端读的是同一份解析结果。**本页只讲怎么配**，代码里怎么断言、前端怎么隐藏，见[能力与配额（entitlement）](/docs/main/public-api/entitlement)。

## 一、两张表与两个入口

| 概念 | 表 | 谁维护 | 后台入口 |
| --- | --- | --- | --- |
| 功能目录 | `sys_member_feature` | 平台 / 研发 | 「功能与配额」页 `/system/member-feature`（权限 `system:memberFeature:list` 等 4 个） |
| 等级矩阵 | `sys_member_level_feature` | 运营 | 「会员等级」页 `/system/member-level` → 「等级能力矩阵」弹窗（读 `system:memberLevel:list`，存 `system:memberLevel:feature`） |

接口清单（都在 `packages/admin-trade/server/trade-router/modules/` 下）：

| 接口 | 用途 | 权限码 |
| --- | --- | --- |
| `sysMemberFeature.page` / `create` / `update` / `remove` / `batchDelete` | 目录增删改查 | `system:memberFeature:list` / `:add` / `:edit` / `:del` |
| `sysMemberFeature.resolvers` | 已注册的计量器键下拉（给 `resolver_key` 用） | `system:memberFeature:list` |
| `sysMemberLevel.featureMatrix` | 某等级的全部功能取值（未配置的显示目录默认值） | `system:memberLevel:list` |
| `sysMemberLevel.saveFeatures` | 整体覆盖某等级的矩阵 | `system:memberLevel:feature` |

## 二、功能目录 `sys_member_feature`

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `feature_key` | 能力键，**代码契约** | 全局唯一（`uk_member_feature_key`）；**创建后不可改** |
| `name` / `unit` / `group_name` / `sort_order` | 展示用的名称、单位、分组、排序 | 可空；后台按 `group_name + sort_order` 排序分组 |
| `kind` | `switch`（开关）或 `quota`（配额） | 只有 `quota` 走配额分支，其余一律按开关处理 |
| `default_value` | 等级**未配置**该键时的取值 | 不传时按类型兜底：`switch` → 1、`quota` → 0 |
| `resolver_key` | 配额已用量的计量器键 | `quota` 必填且必须已注册；`switch` 必须为空 |
| `admin_bypass` | 管理员是否绕过 | 默认 1（绕过） |
| `user_show` | 是否向端用户展示名称与额度 | 默认 1（展示） |
| `status` | 启停 | 停用的行不进入目录，等同于该键未登记 |

`feature_key` 为什么不能改——它同时出现在业务代码的 `assertEntitlement(ctx, 'student.max')` 与前端 `v-feature="'student.max'"` 里，改名等于换一个能力：旧代码里的键会变成「未登记」，按 fail-closed 一律拒绝。服务端在 `SysMemberFeatureService.updateById` 里显式拦截，抛 `module.system.memberFeature.featureKeyImmutable`。

两条一致的写入口校验（`normalizeResolverKey` / `assertFeatureValue`）：

- `quota` → `resolver_key` 必填，且必须在 `listEntitlementResolvers()` 的返回里，否则 `resolverRequired` / `resolverNotRegistered`；
- `switch` → 带 `resolver_key` 直接报 `resolverNotAllowed`（开关不计量，留着只会误导）；
- 取值：`switch` 只允许 `0` / `1`，`quota` 允许 `-1` 或 `>= 0`。

删除目录行是**软删且不清理矩阵**：目录是读取源，目录里没有的键不会进入能力档案，残留的矩阵行是惰性数据；恢复同键时旧值还能直接复用。

## 三、等级矩阵与取值语义

`sys_member_level_feature` 一行一个 `(level_id, feature_key)`，唯一键 `uk_member_level_feature`。**没有行 = 该等级未配置**，读取时回落到目录 `default_value`——这正是「新加一个功能，所有等级先按默认值生效」的实现方式。

`kind = 'switch'`：

| 值 | 含义 | 服务端 | 前端 |
| --- | --- | --- | --- |
| `0` | 关闭 | 拒绝 | `can()` false，`v-feature` 移除 / 禁用 |
| `1` | 开启 | 放行 | `can()` true |
| 其它 | 非法 | 保存时就报 `valueInvalid` | — |

`kind = 'quota'`：

| 值 | 含义 | 服务端判定 |
| --- | --- | --- |
| `-1` | 不限（`UNLIMITED`） | 直接放行，**不查计量器** |
| `0` | 禁止创建 | `used + delta > 0` 恒成立，一律拒绝 |
| `N > 0` | 上限 N | `used + delta <= N` 放行 |

两种「0」要分清：**开关的 0 是「功能关闭」，配额的 0 是「额度为零」**，后者仍然会走计量器与拒绝逻辑（只是必然失败）。

保存矩阵是**整体覆盖**（`saveFeatures` → `matrixRepo.replaceForLevel`）：请求里的 `values` 就是该等级最终的全部显式配置，未出现的键会被移除并回落目录默认值，`values: []` 等于清空该等级的全部显式配置。落库前一次做完四项校验：等级存在、键在**启用中的目录**里（否则 `featureUnknown`）、同请求不重复（`featureDuplicated`）、取值合法。

## 四、`admin_bypass` 与 `user_show`

| 字段 | 取值 | 效果 |
| --- | --- | --- |
| `admin_bypass` | `1`（默认） | 管理员（`sys_user.is_admin = 1`）取到「开关 = 1 / 配额 = 不限」，绕过在档案合并阶段完成 |
| | `0` | 管理员同样受限，适合平台级资源总量这类不该被绕过的东西 |
| `user_show` | `1`（默认） | 向端用户展示名称、单位与具体上限 |
| | `0` | **仅后端强制**：能力照常生效，但端用户侧不展示名称 / 额度，被拒时只提示「当前操作不可用」 |

`user_show = 0` 的具体表现，逐条对照 `packages/admin-core/server/utils/entitlementGuard.ts` 与 `packages/admin-trade/server/utils/entitlementProfile.ts`：

- 该键被收集进档案的 `hiddenFeatures`，前端 `useEntitlement().isHidden(key)` 为 true，页面不显示名称与额度；
- 配额超限时错误码从 `module.system.entitlement.quotaExceeded`（文案「该功能上限 N（单位）」）换成通用的 `module.system.entitlement.denied`（文案「当前操作不可用」），**不暴露上限数字**；
- **拦截强度不变**：隐藏只是展示层约定，服务端照常拒绝；
- **不影响剩余量计算**：`remainingEntitlement` 仍按真实上限返回，别把「隐藏」当成 0；
- **不影响后台**：后台的功能页与等级矩阵页照常看到完整配置（后台读的是表，不是端用户档案）。

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**判断该不该把 `user_show` 关掉，只看一条：这个上限本身是不是商业信息。**

比如「导出报表」这种内部能力开关、或者「并发锁定数」这种被风控卡出来的上限，向用户暴露具体数字既无意义又容易被试探；而「学员数量上限 100 人」是卖点，应当展示。关掉它不会降低安全性，只是把「403 带数字」变成「403 不带数字」。
::

## 五、fail-closed 与计量器

服务端只读 `ctx.entitlements`（由 auth 中间件每个请求解析一次），`assertEntitlement` 不查库。三条 fail-closed 规则：

| 场景 | 行为 | 日志 `reason` |
| --- | --- | --- |
| 键不在目录 / 目录被停用 | 拒绝 | `unregistered` |
| `switch` 值非 1 | 拒绝 | `switchOff` |
| `quota` 超限 | 拒绝（文案受 `user_show` 影响） | `quotaExceeded` |
| `quota` 没有计量器且调用方没传 `used` | **拒绝**（不把未知用量当 0） | `resolverMissing` |

配额功能的已用量只有两个来源：调用方显式传 `used`，或 `meta.resolverKey ?? 功能键` 指向的**计量器**现场统计。计量器是宿主在进程启动阶段注册的函数：

```ts
// 宿主应用的 server/plugins/entitlement-usage.ts（示意）
import { defineUsageResolvers } from '#admin/server/exports/entitlement'

export default defineNitroPlugin(() => {
  defineUsageResolvers({
    // 多个功能可以共用一个计量器
    studentCount: async (ctx, userId) => await countStudentsOf(ctx, userId)
  })
})
```

| 事项 | 说明 |
| --- | --- |
| 注册入口 | `registerEntitlementResolver(key, fn)` 单个注册；`defineUsageResolvers({...})` 批量注册；重复注册以最后一次为准 |
| 签名 | `(ctx, userId) => number \| Promise<number>`，返回**当前已用数量**，不是剩余量 |
| 必须早于请求 | 放在 `server/plugins` 里；放请求处理里会导致首个请求前保存配额功能时报「计量器未注册」 |
| 键与功能解耦 | `resolver_key` 不要求等于 `feature_key`，`student.max` 与 `student.export` 共用 `studentCount` 是标准用法 |
| 自检 | `listEntitlementResolvers()` 列出已注册键；后台保存配额功能时用它校验，未注册直接报错 |
| 缓存 | 目录与矩阵各 30 分钟缓存，所有写入口成功后主动失效，TTL 只作兜底 |

## 六、配好一项能力的顺序

1. **先注册计量器**（仅 `quota`）：在宿主 `server/plugins` 里 `defineUsageResolvers`，确认 `listEntitlementResolvers()` 能看到这个键。
2. **建目录**：`/system/member-feature` 新增，`feature_key` 按「业务域.能力」命名（`class.max` / `report.export`），`kind` / `default_value` / `resolver_key` / `admin_bypass` / `user_show` 一次定好。
3. **配矩阵**：`/system/member-level` 打开某等级的「等级能力矩阵」，按等级赋值——不填就是目录默认值。
4. **写代码**：服务端在写接口里 `assertEntitlement`，前端用 `v-feature` / `useEntitlement`。用法见[能力与配额（entitlement）](/docs/main/public-api/entitlement)。
5. **自检**：用会员账号请求 `sysMember.myEntitlements`，确认 `features` / `hiddenFeatures` / `meta` 与后台配置一致。

## 七、常见报错对照

| 报错 key | 触发点 | 处理 |
| --- | --- | --- |
| `module.system.memberFeature.featureKeyImmutable` | 编辑时改了 `feature_key` | 改名 = 换能力；确需改名请新建键并改代码 |
| `...featureKeyExists` | 新增时键已存在（含已软删的行） | 恢复原行，或换键 |
| `...resolverRequired` / `...resolverNotRegistered` | `quota` 未填键 / 键未注册 | 先注册计量器，再从下拉里选 |
| `...resolverNotAllowed` | `switch` 填了 `resolver_key` | 清空该字段 |
| `...defaultValueInvalid` / `...valueInvalid` | 取值与 `kind` 不匹配 | `switch` 用 0/1；`quota` 用 -1 或 ≥ 0 |
| `...featureUnknown` | 矩阵里出现目录中没有（或已停用）的键 | 先建目录再配矩阵 |
| `...featureDuplicated` | 同一次保存里出现重复键 | 前端去重后重提 |

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**配额功能上线前，务必在目标环境确认计量器已注册。** 缺计量器时的表现不是「悄悄放行」，而是「所有相关请求都 403、日志里 `reason = resolverMissing`」——这是设计如此，别去改守卫，去补注册。
::
