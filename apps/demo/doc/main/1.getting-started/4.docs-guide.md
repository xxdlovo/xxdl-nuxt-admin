本站由 Nuxt Content 3 驱动，源文件全部在 `doc/main/` 目录，构建后挂在 `/docs/main/**` 路由下。本页说明如何维护它。

## 一、站点是怎么跑起来的

| 环节 | 位置 |
| --- | --- |
| 内容集合定义（源目录 `doc/main/`，收集 `**/*.{md,yml}`） | `content.config.ts` |
| 模块注册（`@nuxtjs/mdc` + `@nuxt/content`） | `nuxt.config.ts` |
| 文档布局（左导航、右页内目录、上下页、搜索） | `app/layouts/docs.vue` |
| 文档页面渲染（`/docs/main/**` 动态路由） | `app/pages/docs/main/[...slug].vue` |
| `/docs/main` 入口跳转 | `app/pages/docs/main/index.vue` |

几个关键规则：

- **`/docs/main` 前缀是应用层补的**。内容集合内部的路径以 `/` 为根，例如文件 `doc/main/1.getting-started/2.installation.md` 的内容路径是 `/getting-started/installation`，应用路由才是 `/docs/main/getting-started/installation`。正文里写内链时请直接写 `/docs/main/...` 完整路由。
- **数字前缀只用于排序**，不会出现在 URL 里（`1.getting-started` → `/docs/main/getting-started`）。
- **`.navigation.yml` 只影响导航**，不作为页面渲染。

## 二、新增一个页面

1. 在目标分组目录下新建 `.md` 文件，文件名加数字前缀决定顺序：

```text
doc/main/5.features/2.files/6.new-topic.md
```

2. 写 front-matter：

```markdown
---
title: 页面标题
description: 一句话说明本页内容。
---

（正文从这里开始，用 H2 起头）
```

可选的 `navigation` 字段用于控制侧栏表现：

```markdown
---
title: 很长的页面标题
description: 说明。
navigation:
  title: 侧栏短标题
  icon: i-lucide-file-text
---
```

- `navigation: false` → 页面存在但不显示在侧栏（仍可通过完整 URL 直接访问）。
- 不加 `navigation` 时，侧栏直接使用 `title`。

3. **不要写 H1**。站点用 front-matter 的 `title` 渲染页头（`UPageHeader`），正文再写一次 `#` 标题会重复。正文从 `##` 开始，右侧「本页内容」目录也只抓 `##` / `###`。

## 三、新增一个分组

1. 建目录，目录名加数字前缀，例如 `doc/main/8.operations/`。
2. 在目录内放 `.navigation.yml`：

```yaml
title: 运维手册
icon: i-lucide-wrench
navigation: true
```

3. 在目录内按 `1.xxx.md`、`2.xxx.md` 添加页面。

图标使用 Iconify 名称。项目已内置 `lucide`、`tabler`、`simple-icons`、`selfhst` 图标集，自定义图标放在 `app/assets/icons`（前缀 `custom`）。分组图标推荐统一用 `i-lucide-*`。

## 四、嵌套分组（子目录）

`doc/main/5.features/` 演示了两级结构：分组内再放带 `.navigation.yml` 的子目录，就会形成「功能组件 → 错误使用 → 各页」的三级导航。当前布局使用 `default-open: true` 自动展开当前页面所属分组，其他分组可以手动展开；如果某个分组页数太多导致侧栏过长，可以把子目录改成扁平文件名（如 `1.error-overview.md`、`2.error-server.md`），层级和内容都不受影响。

## 五、正文可用的写法

普通 Markdown 全部可用，另外启用 MDC 语法，可以直接用类名控制容器样式：

```markdown
::div{.my-8.rounded-xl.border.border-primary/30.bg-primary/5.p-6}
### 提示块标题

这里是被包裹的内容。
::
```

常用约定：

| 场景 | 写法 |
| --- | --- |
| 代码 | 三个反引号 + 语言（`ts` / `vue` / `bash` / `sql` / `text`） |
| 强调块 | `::div{...}` + `:::` 包裹 |
| 项目内文件路径 | 行内代码，如 `` `server/trpc/init.ts` `` |
| 站内跳转 | 完整路由，如 `[前端手册](/docs/main/frontend-handbook/overview)` |
| 表格 | 标准 Markdown 表格，适合对照与矩阵类信息 |

## 六、内置的三个自动化能力

- **搜索**：`app/layouts/docs.vue` 通过 `queryCollectionSearchSections` 生成索引，支持顶栏搜索按钮与 `Ctrl/Cmd + K`。生成索引时会忽略 `style` 标签，避免代码高亮样式混入结果片段。
- **上下页**：由 `queryCollectionItemSurroundings` 生成，只取 `description` 字段。首篇/末篇会自动隐藏整块。
- **页内目录**：由正文的 `##` / `###` 生成，显示在右侧（`lg` 以下隐藏，改用正文上方的折叠目录）。

## 七、注意事项

1. 文档页面必须保持**单根节点**：`app/pages/docs/main/[...slug].vue` 已关闭页面过渡（`pageTransition: false`），且要求根级不能出现与容器并列的注释，否则切换页面时正文会消失。
2. 只有 `.md` 和 `.yml` 会成为内容，`.sql` 之类的脚本文件放在 `doc/main/` 下只是附件，不会生成页面。
3. 删除或重命名页面后，记得全局搜索旧路由，避免正文里留下死链。
4. 文档正文引用的源码路径请与仓库保持一致，代码改动后建议同步更新相关页面。
