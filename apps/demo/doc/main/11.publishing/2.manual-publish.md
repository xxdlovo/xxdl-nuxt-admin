CI 走通之后很少需要手动发布，但**首次发布**、或 CI 配置尚未就绪时，必须在本地做一次。

## 前置条件

- npm 账号，且**已开启 2FA**
- 账号的 2FA 至少有一种能在命令行上完成的形态（见下节）
- 本机 npm 的默认 registry 可能是镜像，但两个包的 `publishConfig.registry` 已锁定 `https://registry.npmjs.org/`，无需额外指定

## 先搞清楚你的 2FA 形态

npm 支持两种 2FA，只有一种能在 CLI 里用：

| 形态 | 表现 | `--otp` 能用吗 |
| --- | --- | --- |
| **TOTP**（验证器 App） | 每 30 秒一个 6 位数字 | ✅ 可以 |
| **Security Key / Passkey** | 浏览器弹窗 + 触摸 / PIN | ❌ 不产生数字码 |

如果账号只绑了 Security Key，`npm login` 会跳浏览器并要求 WebAuthn，而 `--otp` 无从取值 —— 这种情况下先给账号补一个 TOTP，或走下面的 token 路径。

## 方式一：`npm login`（交互式）

```bash
npm login --registry https://registry.npmjs.org/
```

浏览器会打开授权页。若卡在 Security Key（比如 Windows 安全中心报「使用通行密钥登录时出现问题」），换用方式二。

## 方式二：token + `--otp`（推荐）

完全绕开 CLI 登录，认证靠 token，2FA 靠命令行里现场给的一次性密码。

### 1. 网页生成 token

打开 `https://www.npmjs.com/`，用**密码 + TOTP 6 位码**登录（这一步走的是网页，不要求 Security Key）。

然后：头像 → **Access Tokens** → **Generate New Token** → 选 **Granular Access Token**：

| 项 | 值 |
| --- | --- |
| 权限 | Read and write |
| Packages | All packages（或分别指定两个包） |
| 过期时间 | 按需 |

生成后**只显示一次**，立即复制。

### 2. 写到本机配置

```bash
npm config set //registry.npmjs.org/:_authToken=<粘贴 token>
```

验证：

```bash
npm whoami --registry https://registry.npmjs.org/
```

返回用户名即生效。这一步不涉及 WebAuthn。

> 不要把这个 token 写进**项目目录**的 `.npmrc`，否则有被提交到公开仓库的风险。`npm config set` 写的是用户级配置（`C:\Users\<你>\.npmrc`）。

### 3. 发布时提供 OTP

```bash
cd D:\ws_project\xxdl-nuxt-admin

pnpm --filter xxdl-admin-core publish --access public --no-git-checks --otp=<6位码>
pnpm --filter xxdl-admin-trade publish --access public --no-git-checks --otp=<6位码>
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--filter <pkg>` | 指定发哪个 workspace 包 |
| `--access public` | 公开发布（scoped 包默认是私有） |
| `--no-git-checks` | 工作区有未提交改动时不报错 |
| `--otp=` | 现场提供的 TOTP，绕过「token 需 bypass 2FA」的限制 |

`prepack` 钩子会自动把 Swagger UI 资源同步进包，不需要手动准备。

## 发布前建议先跑的检查

```bash
pnpm typecheck
pnpm check:layers

# 只打包不发布，确认内容
pnpm --filter xxdl-admin-core pack --pack-destination ./release
tar -tzf ./release/xxdl-admin-core-*.tgz | head -30
```

## 常见卡点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `EOTP` | token 没有绕过 2FA 的权限，或 2FA 是 Security Key 而非 TOTP | 补 TOTP，或用 `--otp` |
| 浏览器要求 Security Key 且报错 | Windows Hello / Passkey 环境问题 | 改用方式二（token） |
| `cannot publish over existing version` | 该版本已发布 | 升级 `package.json` 的 version |
| `ERR_PNPM_BAD_PM_VERSION` | 未指定 registry，发到了镜像 | `publishConfig.registry` 已锁定，确认没被覆盖 |

## 手动发布之后

手动发过 `0.1.0` 之后，CI 再发必须从 `0.1.1` 起 —— npm 不允许覆盖已发布版本。

如果目标是让后续发布全自动，请继续配置 [CI 自动发布](/docs/main/publishing/ci-publish) 里的 Trusted Publishing。
