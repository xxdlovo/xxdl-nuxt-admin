## 认证类

### `EOTP: This operation requires a one-time password`

**出现位置**：CI 或本地 `publish` 时。

**原因**：用的是「不能绕过 2FA 的 token」，而发布要求 2FA 验证。若账号的 2FA 是 Security Key 而非 TOTP，则命令行根本拿不到 6 位码。

**处理**：

| 场景 | 做法 |
| --- | --- |
| CI | 改用 Trusted Publishing（OIDC），彻底不用 token |
| 本地 | 用 `--otp=<TOTP 6位码>`，或给账号补一个 TOTP |

### `npm login` 跳浏览器后要求 Security Key，Windows 安全中心报「使用通行密钥登录时出现问题」

**原因**：Windows Hello 的 Passkey 与 Chromium 的 WebAuthn 通信异常（常见于远程桌面、企业安全软件、或 PIN 与 Passkey 绑定损坏）。

**处理**：绕开 CLI 登录，改用 token 路径：

```bash
npm config set //registry.npmjs.org/:_authToken=<网页生成的 token>
npm whoami --registry https://registry.npmjs.org/
```

网页登录走的是 TOTP，不涉及 WebAuthn。

### CI 报 `401` / `not authorized to publish`

**原因**：Trusted Publishing 的三个字段有一处不匹配。

**核对**（每个包分别检查）：

| 字段 | 必须是 |
| --- | --- |
| Organization or user | `xxdlovo` |
| Repository | `xxdl-nuxt-admin` |
| Workflow filename | `publish.yml` |

另外确认 workflow 里有 `permissions: id-token: write`。

## 版本类

### `cannot publish over existing version`

**原因**：该版本号已经发过。npm 不允许覆盖已发布版本。

**处理**：升级 `package.json` 的 `version`，提交后重新打 tag。

workflow 里已有前置检查，正常情况下会在打包前就给出更清楚的提示：

```
::error::xxdl-admin-core@0.1.1 已存在于 npm，无法重复发布。
```

### 版本不一致导致失败

**日志**：

```
::error::版本不一致：tag 指向 0.1.1，但 xxdl-admin-core 的 package.json 是 0.1.0。
```

**原因**：tag 的版本和 `package.json` 不同步。

**处理**：二选一 ——

```bash
# 改 package.json 后重新打 tag
git tag -d core-v0.1.1              # 删本地 tag
git push origin :refs/tags/core-v0.1.1   # 删远端 tag
# 改版本 → 提交 → 重新打 tag
```

## 工作流类

### `Multiple versions of pnpm specified`

**日志**：

```
Error: Multiple versions of pnpm specified:
  - version 10 in the GitHub Action config
  - version pnpm@10.30.2 in package.json
```

**原因**：workflow 里写了 `with: version: 10`，而 `package.json` 有 `packageManager` 字段。

**处理**：删掉 workflow 里的 `version` 参数，让它读 `packageManager`：

```yaml
- name: Setup pnpm
  uses: pnpm/action-setup@v4
  # 不要写 with: version
```

同仓库其他 workflow 都是这个写法。

### Actions 页面看不到 `Publish to npm` / 没有 Run workflow 按钮

**原因**：`workflow_dispatch` 的 workflow 必须存在于**默认分支**（`main`）才会显示。

**处理**：先把 workflow 文件合并到 `main`。

### `Unmet peer` / `frozen-lockfile` 失败

**原因**：`package.json` 改过但没有更新 `pnpm-lock.yaml`。

**处理**：本地执行 `pnpm install` 后提交 lockfile。

## Trusted Publishing 类

### `Status: Pending validation`

**含义**：配置已保存，但还没被一次成功的 OIDC 发布验证过。

**处理**：在 npm 给的期限内发一个 patch 版本。成功后状态变为 `Active`。

**注意**：失败不会破坏配置，期限内可以重试。

### 配置了但发布仍走 token / 仍要求 OTP

**排查**：

1. workflow 里是否还残留 `env: NODE_AUTH_TOKEN`
2. workflow 是否有 `permissions: id-token: write`
3. 发布命令是否由 npm CLI 执行（`npm publish`，不是 `pnpm publish`）

## 无害的提示

### `npm notice npm tokens that bypass 2FA are being restricted...`

**这是信息提示，不是错误。**

npm 对**所有发布操作**都会打印这条迁移提醒。走 OIDC 时同样会打印，因为 npm 无法从 CLI 判断你是否还在用 token。

判断依据是日志里的这两行 —— 出现即说明是 OIDC：

```
npm notice Signed provenance statement with source and build information from GitHub Actions
npm notice Provenance statement published to transparency log: ...
```

### `npm warn Unknown user config "always-auth"`

`actions/setup-node` 写入 `.npmrc` 时带的旧字段，npm 11 已不识别。不影响功能。若想消除：

```yaml
- name: Clean stale npmrc entries
  run: sed -i '/always-auth/d' ~/.npmrc || true
```

## 定位问题的通用方法

1. 看 **Actions 运行页**，找第一个红的步骤
2. `Resolve target and version` 失败 → 版本/tag 问题
3. `Check version availability` 失败 → 版本已存在
4. `Publish` 失败 → 认证问题（OIDC 配置或权限）
5. 本地复现打包：

```bash
pnpm typecheck
pnpm check:layers
pnpm --filter xxdl-admin-core pack --pack-destination ./release
```
