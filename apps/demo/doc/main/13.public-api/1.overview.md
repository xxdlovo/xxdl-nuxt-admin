本分区面向两类读者：把 `xxdl-admin-core` / `xxdl-admin-trade` 作为 Nuxt Layer 装进自己项目的**宿主应用**，以及本仓库里**其它业务模块**。共同的诉求是——不读 `domain/*` 的内部实现，只在自己的业务代码里回答三个问题：这个功能当前能不能用、还能建几个、这笔钱能不能扣/加。

内部 `domain/*` 领域服务当然可以直接调，但它们是为本系统内部编排写的，签名会随重构调整；本分区只介绍**面向外部的稳定门面**，并把「什么时候该继续往下用领域服务」讲清楚。

## 一、两类能力

| 能力 | 解决什么问题 | 明确不负责 | 入口 |
| --- | --- | --- | --- |
| 能力与配额（entitlement） | 按会员等级限制「能不能用某个功能」（`switch`）与「能建多少个 / 用多少次」（`quota`） | 不碰钱、不创建订单、不记录业务数据 | [`#admin/server/exports/entitlement`](/docs/main/public-api/entitlement) |
| 余额与交易（billing） | 扣余额、加余额、查余额、断言余额充足；所有写入按业务单号幂等 | 不创建商品、订单、支付单，也不做履约 | [`#trade/server/exports/billing`](/docs/main/public-api/billing) |

两者可以组合，但职责不重叠：entitlement 决定「有没有资格」，billing 决定「钱够不够、扣多少」。典型顺序是先断言能力、再断言/扣减余额（完整示例见[余额与交易](/docs/main/public-api/billing)）。

## 二、我该用哪个

| 你的需求 | 用这个 | 说明 |
| --- | --- | --- |
| 只想控制某个功能开 / 关 | entitlement `switch` + `assertEntitlement` | 等级矩阵里配 0 / 1；前端用 `v-feature` 隐藏或禁用入口 |
| 想按数量限制（班级数、学员数、导出条数） | entitlement `quota` + 计量器 | 必须注册计量器（`registerEntitlementResolver`），否则 fail-closed 拒绝 |
| 要向用户收一笔钱 | billing `chargeBalance` | 一次性扣款，立即生效、不可撤销 |
| 要给用户发钱 / 补偿 / 活动赠送 | billing `creditBalance` | 按 `bizNo` 幂等，重复调用不会重复入账 |
| 只想查余额或提前判断够不够 | billing `getBalance` / `assertBalance` | `assertBalance` 只读，不做任何写入 |
| 要完整的商品 / 订单 / 履约 / 在线支付链路 | trade 的领域服务（`orderService` / `goodsService`）与支付模块 | 见[交易模块](/docs/main/trade/overview)、[支付模块](/docs/main/payment/overview)、[端到端支付流程](/docs/main/payment-flow/overview) |

一条快速判断链：

```text
你的动作需要「动钱」吗？
├─ 不需要，只是判断能不能用
│    ├─ 是开关 → entitlement switch
│    └─ 是数量 → entitlement quota + 计量器
├─ 需要，且是宿主业务自己定价的一次性扣款 → chargeBalance
├─ 需要，且是发钱 / 退款补偿 → creditBalance
└─ 需要订单、商品快照、履约、IP 或在线支付 → 不要用 billing 拼，直接走 orderService
```

## 三、两条通用约定

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**一、服务端校验才是权威。** 前端的 `v-feature` 与 `useEntitlement()` 只影响体验（隐藏入口、置灰按钮），任何直接调接口的请求都不会经过它们；隐藏功能（`user_show = 0`）同样会在服务端被拦截，只是拒绝文案不暴露具体上限。

**二、所有扣款 / 加款都按 `bizNo` 幂等。** 同一个业务单号重复提交只会生效一次，第二次返回 `reused: true` 且余额不再变化。因此 `bizNo` 必须由业务单号生成、在重试时保持不变，**不能每次请求重新生成**；同一笔业务也**只能用一个 `bizNo`**。
::

这两条约定分别展开在[能力与配额](/docs/main/public-api/entitlement)与[余额与交易](/docs/main/public-api/billing)里。
