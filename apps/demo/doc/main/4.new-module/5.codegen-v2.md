> 本节是[新增模块](/docs/main/new-module)分组的 **V2 分册**：V1 是「按文档手工生成」（见本组第 2~4 页），V2 是「系统内置工具 + 机器接口」。

## 一、V1 与 V2 的区别

| 版本 | 形态 | 谁生成代码 | 谁合并文件 |
| --- | --- | --- | --- |
| V1 | [文档流程](/docs/main/new-module) | 人或外部 AI 按文档手工写 | 人或外部 AI |
| V2 | 系统工具 + 机器接口 | 系统确定性生成 | 外部 AI 按 `mergePlan` 合并 |

V2 **不调用任何大模型**，也不需要配置 AI Key。它只负责：

1. 从数据库表配置生成一套完整、默认可用的代码；
2. 返回精确的 `files` 和 `mergePlan`；
3. 返回 Markdown 操作指南和 zip；
4. 让外部 AI/CLI 自己写入、合并、验证。

## 二、配置令牌

外部 AI/CLI 通过 Bearer Token 调用只读接口：

```env
NUXT_CODEGEN_TOKEN=replace-with-a-long-random-token
```

- 未配置时，接口只接受已登录后台会话，V2 页面仍可正常使用。
- 令牌只保护 `/api/system/gen/ai/**`，不提供通用文件访问。
- 建议使用至少 32 位随机字符串。

## 三、接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/system/gen/ai/guide` | Markdown 操作指南 |
| GET | `/api/system/gen/ai/tables` | 已导入的生成配置 |
| POST | `/api/system/gen/ai/plan` | 返回完整文件 + 合并计划 |
| POST | `/api/system/gen/ai/download` | 返回 zip |

```bash
curl -H "Authorization: Bearer $NUXT_CODEGEN_TOKEN" \
  http://127.0.0.1:3001/api/system/gen/ai/guide

curl -X POST \
  -H "Authorization: Bearer $NUXT_CODEGEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"tableName":"sys_demo","moduleName":"system/demo","businessName":"SysDemo"}' \
  http://127.0.0.1:3001/api/system/gen/ai/plan
```

`plan` 返回：

- `files`：每个文件的完整内容，可直接写入；
- `mergePlan`：需要合并的文件与精确片段；
- `instructions`：执行顺序；
- `download`：zip 下载接口。

如果表还没在 V2 页面导入，`plan` 会自动从 `INFORMATION_SCHEMA` 导入。

## 四、CLI

```bash
pnpm gen:ai:guide
pnpm gen:ai:tables
pnpm gen:ai:plan --table=sys_demo --module=system/demo --business=SysDemo
pnpm gen:ai:download --table=sys_demo --out=.data/codegen
```

环境变量：

```env
CODEGEN_BASE_URL=http://127.0.0.1:3001
CODEGEN_TOKEN=<与 NUXT_CODEGEN_TOKEN 相同>
```

`plan` 会把 JSON 写到 `.data/codegen/<table>-plan.json`，AI 直接读取即可。

### 4.1 列表行「AI」按钮（一键运行）

代码生成 V2 列表的每一行都有一个「AI」按钮。点击后：

- 服务端按该行表配置生成提示词；
- 自动替换 `tableName`、`moduleName`、`businessName`；
- 自动带上 `CODEGEN_BASE_URL` 和可用令牌；
- 直接复制到剪贴板，外部 AI 粘贴后即可执行。

默认复制的是 **15 分钟短期令牌**，不是长期 `NUXT_CODEGEN_TOKEN`，避免长期密钥进入浏览器和对话记录。确实需要复制长期令牌时，设置：

```env
NUXT_CODEGEN_COPY_SECRET=true
```

## 五、必须合并的文件

以下文件**不能整文件覆盖**，否则会丢掉其它模块的内容：

### 5.1 `packages/admin-core/server/drizzle/schema/index.ts`

- 追加 `mergePlan.schemaIndex.importLine`
- 在 export 列表中追加 `mergePlan.schemaIndex.exportEntry`

### 5.2 `packages/admin-core/server/trpc/routers.ts`

- 追加 `mergePlan.routers.importLine`
- 在 `appRouter` 中追加 `mergePlan.routers.registration`

### 5.3 `packages/admin-core/app/locales/zh.json` / `en.json`

在 `mergePlan.locales.jsonPath` 指向的节点深合并：

- `zhSubtree` → `zh.json`
- `enSubtree` → `en.json`

保留已有词条；不要删除其它模块的 key。

### 5.4 菜单

执行 `mergePlan.menuSql`，先把 `<MENU_ID>`、`<ADD_ID>`、`<EDIT_ID>`、`<DEL_ID>` 替换为实际 UUID。

## 六、验证

```bash
pnpm --filter xxdl-nuxt-admin-demo typecheck
pnpm check:layers
```

## 七、给 AI 的提示词

```text
请先读取 /api/system/gen/ai/guide（或 /docs/main/new-module/codegen-v2），然后：
1. 运行 pnpm gen:ai:plan --table=<tableName> [--module=<module>] [--business=<Business>]；
2. 按返回的 files 写入文件；
3. 按 mergePlan 合并 schema/index.ts、routers.ts、app/locales/zh.json、app/locales/en.json；
4. 执行 mergePlan.menuSql（替换占位 UUID）；
5. 运行 pnpm --filter xxdl-nuxt-admin-demo typecheck 和 pnpm check:layers；
6. 如果失败，读取错误并修正生成文件后重试，不要改动无关文件。
```
