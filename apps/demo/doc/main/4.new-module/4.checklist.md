## 一、命名逐级对照（最容易出错的部分）

同一个实体在不同层的命名风格不同，**不要混用**。以 `sys_oauth_account` 为例：

| 层次 | 命名 | 说明 |
| --- | --- | --- |
| 数据库表名 | `sys_oauth_account` | snake_case |
| Drizzle 变量 | `sysOauthAccount` | 表名转小驼峰 |
| Schema 文件 | `server/drizzle/schema/system/oauthAccount.ts` | 去掉 `sys_` 前缀的小驼峰 |
| 模块名 | `system/oauthAccount` | `<一级目录>/<业务目录>` |
| 业务名 | `SysOauthAccount` | 大驼峰，用于 `SysOauthAccountRepo` / `SysOauthAccountService` / 各 Schema |
| 资源码（权限码前缀） | `system:oauthAccount` | 模块名把 `/` 换成 `:` |
| **tRPC 路由名** | **`sysOauthAccount`** | 与 Drizzle 变量同名（**保留 `sys` 前缀**），前端调用 `$trpc.sysOauthAccount.*` |
| 页面目录 | `app/pages/system/oauth-account/` | kebab-case |
| i18n key | `module.system.oauthAccount` | 保留小驼峰 |

> **易错点**：tRPC 路由名用 `sys` 前缀（`sysOauthAccount`），而资源码与 i18n key 用 `system`（`system:oauthAccount`）。两者并不相同，一律以本表为准。可参考现有模块 `sysUser` / `sysOss` / `sysOssConfig` / `sysDictType`，它们的路由名都是 `sys` 前缀。

**路由注册名直接决定前端调用前缀**：`appRouter` 里注册成 `sysOauthAccount`，前端就必须写 `$trpc.sysOauthAccount.page.query()`。写错前缀时 tRPC 返回的是 `No procedure found on path "..."`（HTTP 404），而不是鉴权错误，很容易被误判成「路由没注册」。

## 二、路径别名对照

| 别名 | 实际路径 | 使用场景 |
| --- | --- | --- |
| `~~/` | 项目根目录 | 后端 import `server/drizzle/schema` 等 |
| `#server/` | `server/` | 后端 import repo、service、utils |
| `#shared/` | `shared/` | 前后端共享类型与常量 |
| `~/` | `app/` | 前端 import 组件、composable |

## 四、注意事项与已知问题

1. **`out/schema.ts` 是自动生成的**，可能带 typo（例如 `filed1` / `field1`），复制到 `server/drizzle/schema/` 后必须人工检查；同时清理多余 import（`mysqlSchema`、`AnyMySqlColumn`、`sql`、`json`、`longtext` 等只保留实际用到的）。
2. **搜索组件的 `schema` 变量必须引用当前模块的 `QuerySchema`**，抄模板时最容易残留上一个模块的引用。
3. **新增接口的 id 由 Service 层用 `randomUuid()` 生成**，前端新增表单不需要传 id。
4. **模糊查询**通过在 `common.ts` 字段上加 `.meta({ query: 'like' })` 实现，后端 `buildWhereBySchema` 会自动解析为 `LIKE %xxx%`。
5. **控制器统一使用 `proc({ permission })` 显式书写权限码**（如 `system:oauthAccount:add`），**不要使用 `crudPermissionProcedures` 工厂** —— 隐式拼接不利于检索。只有纯登录态接口才用 `protectedProcedure` / `permissionProcedure`。
6. **前端组件 import 必须有显式后缀 `.vue`**。
7. **`AppError` 接收 i18n key**（如 `new AppError('common.notExist')`），客户端会自动翻译显示。
8. **`input.ts` / `output.ts` 的 NOT NULL 规则**：`common.ts` 的 BaseSchema 统一用 `.nullish()` 便于复用，但在 `AddSchema` / `RespSchema` 中，DB 里 `NOT NULL` 的**业务字段**需通过 `extend()` 覆盖为必填（如 `z.string()` 而不是 `z.string().nullish()`）；ID 字段在 `AddSchema` 用 `.nonoptional()`、在 `UpdateSchema` 用 `.nonempty()`；`createdAt` / `updatedAt` 等 DB 自管字段保持 `nullish`。
9. **操作类型必须逐条核对**：读接口（`getOne` / `getById` / `page` / `list`）一律 `.query()`，写接口（`create` / `update` / `remove` / `batchDelete`）一律 `.mutation()`，详见 [后端步骤](/docs/main/new-module/backend-steps)的「操作类型与 `proc()` 参数」。
10. **`dataScope: false` 只在必要时添加**：列表接口需要全量数据（树结构、选择器、授权）时才传，并且要加注释说明原因，否则保持默认的数据权限过滤。
11. **页面目录与 i18n key 的命名映射**：`system/oauthAccount` → 页面目录 `system/oauth-account`（kebab-case）→ i18n key `module.system.oauthAccount`（小驼峰）→ 资源码 `system:oauthAccount`。三者大小写风格不同。
12. **`app/locales/pages/**` 与 `server/assets/_locales/**` 都是构建产物**（已 gitignore），不要手写，翻译只加在 `app/locales/{zh,en}.json`。
