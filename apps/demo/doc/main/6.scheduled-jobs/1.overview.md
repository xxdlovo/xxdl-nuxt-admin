## 能力范围

定时任务模块（`sys-job`）把「什么时候执行」和「执行什么」拆成两份数据：Cron 表达式存在任务表，真正的业务逻辑写成可注册的 Handler。

它提供以下能力：

| 能力 | 说明 |
| --- | --- |
| 任务管理 | 任务的增删改查、启用/停用、批量删除 |
| 表达式校验 | 新增或修改时校验 Cron 表达式，并计算 `next_run_at` |
| 到期派发 | 扫描到期且启用的任务，逐个触发执行 |
| 单次执行 | 后台「立即执行」或服务端 `runTask('sys-job:run')` |
| 执行留痕 | 每次执行写入 `sys_job_log`，记录结果、耗时与异常堆栈 |
| 状态回写 | 执行成功/失败后回写任务的最近执行时间、耗时与错误 |
| 内置任务 | `system:clean-log`（清理过期日志）等示例 Handler |

## 数据模型

### 任务定义 `sys_job`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | varchar(36) | 主键，UUID |
| `job_name` | varchar(100) | 任务名称 |
| `job_code` | varchar(100) | 任务编码，便于人工识别 |
| `handler_code` | varchar(100) | 绑定的 Handler 编码，必须已注册 |
| `cron_expression` | varchar(100) | Cron 表达式（5 位或 6 位） |
| `cron_timezone` | varchar(50) | 时区，默认且仅支持 `Asia/Shanghai` |
| `status` | tinyint | 启用状态：`1` 启用，`0` 停用 |
| `running_status` | tinyint | 运行标记：`1` 表示有执行正在处理中，正常为 `0` |
| `last_run_at` | timestamp | 最近一次开始执行时间 |
| `next_run_at` | timestamp | 下次执行时间；停用或计算不到时为 `null` |
| `last_success_at` | timestamp | 最近一次执行成功时间 |
| `last_fail_at` | timestamp | 最近一次执行失败时间 |
| `last_duration_ms` | int | 最近一次执行耗时（毫秒） |
| `last_error` | text | 最近一次的失败信息 |
| `sort_order` | int | 排序值 |
| `remark` | varchar(255) | 备注 |
| `is_deleted` | tinyint | 逻辑删除标记，`0` 为正常 |

### 执行日志 `sys_job_log`

| 字段 | 说明 |
| --- | --- |
| `job_id` / `job_name` / `job_code` | 任务标识，任务被删除后日志仍可读 |
| `handler_code` | 执行时绑定的 Handler 编码 |
| `cron_expression` | 执行时使用的表达式快照 |
| `trigger_type` | 触发方式：`schedule`（调度触发）或 `manual`（手动触发） |
| `status` | 执行状态：`0` 运行中，`1` 成功，`2` 失败 |
| `started_at` / `finished_at` | 开始与结束时间（`YYYY-MM-DD HH:mm:ss`） |
| `duration_ms` | 执行耗时（毫秒） |
| `result` | Handler 返回值的 JSON |
| `error_message` / `error_stack` | 失败信息与堆栈 |

字段定义见 `server/drizzle/schema/system/job.ts`、`server/drizzle/schema/system/jobLog.ts`，对外类型见 `shared/system/job/index.ts` 与 `shared/system/jobLog/index.ts`。

## 执行链路

一次调度执行按以下顺序发生：

1. **派发**：`sys-job:dispatch` 任务按到期条件查出任务列表；
2. **转发**：对每个任务调用 `runTask('sys-job:run', { jobId, triggerType: 'schedule' })`，单个任务失败只记录结果，不影响其它任务；
3. **执行准备**：`runSysJob` 读取任务、校验 Handler 是否存在；
4. **日志占位**：先插入一条 `status = 0` 的日志，并把任务 `running_status` 置为 `1`、写入 `last_run_at`；
5. **运行业务**：调用 Handler 的 `run({ db, jobId, jobCode, triggerType })`；
6. **结果回写**：成功时更新日志为 `status = 1` 并写入 `result`、耗时，任务写入 `last_success_at`、`next_run_at`；失败时更新日志为 `status = 2` 并写入错误与堆栈，任务写入 `last_fail_at`、`last_error`，随后把异常继续抛出。

链路实现见 `server/sys-router/job/SysJobRunner.ts`、`server/tasks/sys-job/dispatch.ts`、`server/tasks/sys-job/run.ts`。

## 后台入口

| 页面 | 前端路由 | 说明 |
| --- | --- | --- |
| 任务管理 | `/system/job` | 任务列表、启用/停用、立即执行、维护表达式 |
| 任务日志 | `/system/job-log` | 执行历史、结果与失败详情 |
