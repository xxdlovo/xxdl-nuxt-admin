## 字段构成

表达式支持 **6 位**（含秒）与 **5 位**（不含秒）两种写法。5 位写法会按「每分钟的第 0 秒」处理，等价于在最前面补一个 `0`。

| 位置 | 字段 | 取值范围 | 备注 |
| --- | --- | --- | --- |
| 1 | 秒 | `0-59` | 仅 6 位表达式提供 |
| 2 | 分 | `0-59` | |
| 3 | 时 | `0-23` | 24 小时制 |
| 4 | 日 | `1-31` | 月份中的第几天 |
| 5 | 月 | `1-12` | 支持英文缩写 |
| 6 | 周 | `0-7` | `0` 与 `7` 都表示周日 |

解析实现在 `server/sys-router/job/cron.ts`，字段范围以该文件的 `FIELD_RANGES` 为准。

## 支持的语法

| 语法 | 示例 | 含义 |
| --- | --- | --- |
| 任意值 | `*` | 该字段的任意值 |
| 问号 | `?` | 与 `*` 等价（兼容常见 Cron 写法） |
| 枚举 | `1,15,30` | 命中列举的任意值 |
| 范围 | `10-20` | 命中区间内的值 |
| 步长 | `*/5` | 按步长取值 |
| 起始值 + 步长 | `0/20` | 从起始值开始，按步长一直取到该字段上限 |
| 月份别名 | `jan`、`dec` | 等价于 `1`、`12` |
| 星期别名 | `sun`、`mon` | 等价于 `0`、`1` |

各段之间用空格分隔，多个语法可以组合，例如 `0 9-18/2 * * mon-fri`。

### 需要留意的语义

- **`0/20` 不是「只匹配 0」**：本项目的解析器把它解释为「从 0 开始，每 20 取一次，直到字段上限」，因此 `0/20 * * * *` 会命中每个小时的第 0、20、40 分钟。
- **周字段的 `0` 与 `7` 等价**：内部会把 `7` 归一为 `0`。
- **5 位表达式补秒**：`0 2 * * *` 与 `0 0 2 * * *` 含义相同，都是每天 02:00。
- **月份与星期可以在同一个表达式里同时出现**：解析器只做集合匹配，不实现某些实现里「日/周互斥」的额外规则。

## 常见表达式示例

| 表达式 | 含义 |
| --- | --- |
| `0 2 * * *` | 每天 02:00（后台新增任务时的默认值） |
| `*/5 * * * *` | 每 5 分钟 |
| `0 */2 * * *` | 每 2 小时的整点 |
| `0 0 1 * *` | 每月 1 日 00:00 |
| `30 2 * * 1` | 每周一 02:30 |
| `0 0 3 1 jan *` | 每年 1 月 1 日 03:00 |
| `0 0 0 ? * *` | 每天 00:00（6 位写法） |
| `0/20 * * * * *` | 每分钟内的第 0、20、40 秒 |

## 对外函数

| 函数 | 作用 | 行为 |
| --- | --- | --- |
| `assertValidCron(expression)` | 校验表达式 | 合法则返回，非法则抛出 `Error` |
| `nextRunAt(expression, from?)` | 计算下次执行时间 | 从 `from` 的下一秒开始逐秒匹配，返回 `Date` |
| `formatMysqlDate(date?)` | 格式化时间 | 输出 `YYYY-MM-DD HH:mm:ss`，用于写库 |

`nextRunAt` 最多向前搜索 366 天；若在此范围内找不到匹配时间（例如月份与日期组合永远无法同时成立），会抛出 `Unable to calculate next run time`。

## 时区说明

- `sys_job.cron_timezone` 只接受 `Asia/Shanghai`，其它值会被服务端拒绝（错误 key：`module.system.job.timezoneUnsupported`）。
- 新增/修改任务时即使不传，也会被 `server/sys-router/job/SysJobService.ts` 归一为 `Asia/Shanghai`。
- 计算 `next_run_at` 使用的是服务进程的本地时间（`new Date()`），并不读取 `cron_timezone` 字段。容器部署时需要保证进程时区与预期一致，否则「每天 02:00」会按容器时区解释。

## 校验与错误

| 场景 | 触发位置 | 结果 |
| --- | --- | --- |
| 表达式为空 | 表单 schema `SysJobAddSchema` | 提交前提示 `form.required` |
| 表达式非法（字段数不对、范围越界、步长非法等） | `SysJobService.validateTask` | `module.system.job.cronInvalid` |
| 时区不是 `Asia/Shanghai` | `SysJobService.validateTask` | `module.system.job.timezoneUnsupported` |
| Handler 未注册 | `SysJobService.validateTask` | `module.system.job.handlerMissing` |
| 启用任务时表达式已失效 | `SysJobService.enable` | 直接抛出解析异常，需先修正表达式 |

校验入口集中在 `validateTask`，新增、修改与启用任务都会走同一套判断，详见 `server/sys-router/job/SysJobService.ts`。
