## 客户端注册

`app/plugins/01.client.ts` 创建并注入 `$trpc`：

```ts
const trpc = createTRPCNuxtClient<AppRouter>({
  links: [customLink, httpLink({ url: '/api/trpc', headers: () => getHeader(), fetch })],
})

return { provide: { trpc } }
```

- 类型来自 `#server/trpc/routers` 的 `AppRouter`，前端因此获得完整的接口类型推断。
- 注册后通过 `const { $trpc } = useNuxtApp()` 取用。

## 两个 link 的职责

| 顺序 | link | 行为 |
| --- | --- | --- |
| 1 | `customLink` | 捕获错误并统一弹出错误提示（先 `toast.clear()` 再 `toast.add()`） |
| 2 | `httpLink` | 一次调用一个请求，不合并批量；注入请求头与 `credentials: 'include'` |

两点约定：

- **没有 `retryLink`**：失败请求不会被自动重试，错误立即由 `customLink` 展示；需要重试的场景由业务自己在交互层决定。
- **不合并请求**：`httpLink` 而不是 `httpBatchLink`，因此同一时刻的多个调用会产生多个 HTTP 请求，换取的是每个请求的独立错误处理与更直观的网络面板。

## 请求头与登录态

```ts
const getHeader = () => {
  const locale = useCookie<string>('i18n_locale').value || 'en'
  return { 'zoo': 'zoo', 'x-locale': locale, 'accept-language': locale }
}
```

- `x-locale` / `accept-language` 让服务端错误信息按当前语言翻译（`errorFormatter` 会优先读 `x-locale`）。
- `fetch` 被包装为 `credentials: 'include'`，session Cookie 才能随请求发送；漏掉会导致“登录成功但接口未登录”。

## 错误提示如何统一

`customLink` 在收到错误时先 `toast.clear()` 再 `toast.add({ title: data.type, description: message, color: 'error' })`：

- 文案由服务端翻译好后直接展示，前端不重复翻译。
- 页面里不需要再为“请求失败”加提示，只需处理业务分支（例如关闭弹窗、回滚状态）。
- `app/plugins/02.errHandle.client.ts` 目前是未实现的占位插件，真正的全局提示逻辑在 `01.client.ts`。

## 调用范式

```ts
const { $trpc } = useNuxtApp()

// 查询
const page = await $trpc.demo.page.query({ page: 1, pageSize: 20 })
const one = await $trpc.demo.getById.query(id)

// 变更
await $trpc.demo.create.mutate(state)
await $trpc.demo.update.mutate(state)
await $trpc.demo.remove.mutate(id)
await $trpc.demo.batchDelete.mutate(ids)
```

注意点：

- 入参形状由 `shared/system/<模块>` 中的 Zod schema 决定；调用超出 schema 的字段会在服务端被拒绝。
- `mutate` 没有返回值时也会在失败时抛错，因此需要更新的列表要显式 `await refresh()`。
- 接口命名以服务端 router 为准，常见为 `list`、`page`、`getOne`、`getById`、`create`、`update`、`remove`、`batchDelete`。

## 页面中的典型用法

- 表格分页查询：把 `$trpc.<模块>.page.query` 作为 `usePaginatedTable` 的 `query` 参数（见表格章节）。
- 字典与配置读取：`useDictStore().loadDict(code)`、`$trpc.sysConfig.getValueByKey.query(key)`，或直接使用 `useConfig()`、`useDictOptions()` 这类封装。
- 首屏加载：`ssr: false` 场景下统一写在 `onMounted` 中，例如 `onMounted(async () => { await search() })`。

## 与原生 HTTP 接口的分工

tRPC 承载业务 CRUD。文件上传等需要 `multipart/form-data` 或需要进度回调的场景使用原生端点，例如 `POST /api/system/oss/upload`，在页面中用 `UFileUpload` + `XMLHttpRequest` 调用（参考 `app/pages/system/oss/components/sys-oss-operate.vue`）。
