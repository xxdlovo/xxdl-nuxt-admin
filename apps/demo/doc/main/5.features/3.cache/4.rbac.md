## 三层结构

权限判断是典型的高频读操作，缓存拆成互不重叠的三层，避免出现「用户菜单树 + 角色关系」这类重复且难以失效的副本：

| 层 | key | 缓存内容 |
| --- | --- | --- |
| 用户 → 角色 | `cache:rbac:user:{encodeURIComponent(userId)}:roles` | 用户当前启用的角色摘要 |
| 角色 → 菜单 | `cache:rbac:role:{encodeURIComponent(roleCode)}:menu-list` | 角色关联的启用菜单、目录与按钮权限 |
| 管理员菜单 | `cache:rbac:admin:menu-list` | 管理员可见的全部启用菜单与按钮权限 |

TTL 统一为 **15 分钟**（`RBAC_CACHE_TTL_SECONDS = 15 * 60`）。相比字典缓存更短，因为权限变更对用户是立即可感的。

## 用法

```ts
import { rbacCacheService } from '#server/sys-router/storage/cache/RbacCacheService'

const cache = rbacCacheService()

const roles = await cache.getUserRoles(
  user.id,
  () => sysRoleService(ctx).listEnabledByUserId(user.id)
)

const menus = await cache.getRoleMenus(
  roles[0].code,
  () => sysMenuService(ctx).listEnabledByRoleIds([roles[0].id])
)

const adminMenus = await cache.getAdminMenus(
  () => sysMenuService(ctx).listEnabledForAdmin()
)
```

| 方法 | 说明 |
| --- | --- |
| `getUserRoles(userId, loader)` | 用户角色，miss 时执行 loader 并回填 |
| `getRoleMenus(roleCode, loader)` | 角色菜单，按角色编码缓存（同一个角色被多个用户共享） |
| `getAdminMenus(loader)` | 管理员菜单，全局唯一 key |
| `invalidateUser(userId)` | 失效某个用户的角色缓存 |
| `invalidateRole(roleCode)` | 失效某个角色的菜单缓存 |
| `invalidateAllRoles()` | 清理全部角色菜单缓存 |
| `invalidateAllUsers()` | 清理全部用户角色缓存 |
| `invalidateAdmin()` | 失效管理员菜单缓存 |

## 失效矩阵

| 变更 | 必须执行的失效 |
| --- | --- |
| 用户的角色发生变化 | `invalidateUser(userId)` |
| 角色的菜单 / 按钮权限发生变化 | `invalidateRole(roleCode)` |
| 角色编码被修改 | `invalidateRole(oldRoleCode)` **和** `invalidateRole(newRoleCode)` |
| 管理员可见菜单发生变化 | `invalidateAdmin()` |
| 不确定受影响的角色 | `invalidateAllRoles()` |
| 不确定受影响的用户 | `invalidateAllUsers()` |

角色编码变更必须同时清理新旧两个 key，这是最容易遗漏的一项：按新编码失效后，旧编码对应的缓存仍会被其他路径命中。

角色、菜单、用户角色等写服务在成功后已自动执行相应失效，调用方通常不需要重复清理；新增这类写接口时应沿用同样的做法。

## 一致性边界

- 缓存中**不保存**密码、session 或完整用户 profile；
- 缓存只保存**已过滤的启用**角色、菜单和按钮权限；
- 权限中间件仍然负责服务端鉴权，**缓存不能绕过它**——缓存只减少数据库读取次数；
- `AuthService` 使用这三层缓存组装 profile 与 permission codes，因此缓存内容与鉴权结果必须保持一致，不要往缓存里塞未经权限过滤的原始菜单集合。

## 排查

| 现象 | 可能原因 |
| --- | --- |
| 修改用户角色后前端菜单未变化 | 写操作未调用 `invalidateUser`，或前端仍持有旧 profile，需重新拉取 |
| 新增菜单后管理员看不到 | 未调用 `invalidateAdmin()` |
| 角色编码改后权限错乱 | 只清理了新编码，旧编码缓存仍在（见失效矩阵第三条） |
| 权限已收回但用户仍可操作 | 多数是前端按钮可见性问题；服务端仍以 `permissionMiddleware` 判定，需确认接口是否真的被调用成功 |
