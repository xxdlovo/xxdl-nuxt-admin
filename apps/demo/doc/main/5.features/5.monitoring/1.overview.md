## 页面入口

| 项 | 说明 |
| --- | --- |
| 页面 | `/system/monitor` |
| 权限 | `system:monitor:list` |
| 刷新 | 默认 5 秒自动刷新，可关闭 |
| 接口 | `sysMonitor.overview` |

页面分为三个页签：**服务监控**、**缓存监控**、**连接池**。

## 服务监控

采集位置：`server/utils/systemMonitor.ts`。

| 指标 | 来源 | 说明 |
| --- | --- | --- |
| CPU 使用率 | `os.cpus()` 时间片差分 | 首次采样等待 200ms；后续按请求间隔计算 |
| CPU 核心/型号 | `os.cpus()` | 只读展示 |
| loadavg | `os.loadavg()` | Windows 通常为 0 |
| 系统内存 | `os.totalmem()` / `os.freemem()` | 总量、可用、已用 |
| 进程内存 | `process.memoryUsage()` | RSS、Heap、External |
| 磁盘 | `fs.statfs(process.cwd())` | 失败时显示“不可用”，不影响其它指标 |
| 运行信息 | `process` / `os` | Node 版本、PID、平台、运行时长 |

不采集环境变量、数据库密码、Session 密钥等敏感信息。

## 缓存监控

当前项目没有 Redis，缓存是 Nitro 的 `memory` 命名存储。

| 指标 | 说明 |
| --- | --- |
| 缓存 Key 数 | `useStorage('memory').getKeys('cache:')` 的数量 |
| 前缀分布 | 按 key 前两段聚合，例如 `rbac:role`、`dict:data` |
| 命中率 | hits / (hits + misses) |
| hits / misses | `getCache` 命中与未命中次数 |
| sets / deletes | 写入与删除次数 |
| 平均读写耗时 | 单进程内累计耗时 / 次数 |
| 累计写入量 | 写入 envelope 的近似字节数 |

指标采集在 `server/utils/cacheMetrics.ts`，由 `SysStorageService` 的
`getCache` / `setCache` / `removeCache` / `clearCache` 记录。

### 边界

- 指标是**单进程**的，多实例部署各自独立；
- 进程重启后计数清零；
- 只统计经过 `SysStorageService` 的缓存，不统计业务直接使用 `useStorage` 的读写；
- 缓存本身仍然只用于读优化，不能作为持久化数据源。

## 连接池

采集位置：`server/drizzle/db.ts` 的 `getDbPoolStats()`。

| 指标 | 说明 |
| --- | --- |
| total | 当前物理连接总数 |
| active | 已获取未释放的连接数（事件计数） |
| idle | 空闲连接数 |
| waiting | 等待获取连接的请求数 |
| connectionLimit | 连接池上限，当前为 10 |
| created | 创建连接事件累计 |
| acquired / released | 获取/释放事件累计 |
| enqueued | 排队事件累计 |

优先读取 mysql2 内部连接数组，读不到时用事件计数回退。统计是近似值，不改变连接池行为。
