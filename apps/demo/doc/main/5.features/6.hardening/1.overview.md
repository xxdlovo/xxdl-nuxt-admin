## 防重复提交

同一个用户（未登录时按 IP）在 5 秒内，对同一个接口提交完全相同的入参，只允许第一次通过。

```ts
const addProc = proc({
  permission: 'system:user:add',
  repeatSubmit: true
})
```

- 实现：`server/trpc/middlewares/rateLimit.ts` 的 `repeatSubmitMiddleware`；
- key：用户/IP + tRPC path + 稳定序列化后的入参；
- 命中重复：抛出 `system.repeatSubmit`，HTTP 429；
- 窗口：5 秒；
- 已应用：用户、公告、岗位、任务新增/修改，代码生成导入表。

## 接口限流

固定窗口计数，超过上限返回 `system.rateLimited`（HTTP 429）。

```ts
const loginProcedure = publicProcedure.use(rateLimitMiddleware({
  limit: 10,
  windowMs: 60_000,
  scope: 'login'
}))
```

| 场景 | 限额 |
| --- | --- |
| 登录 | 每 IP 10 次/分钟 |
| 手动执行任务 | 每用户 9 次/分钟 |

限流不默认启用，只在高风险接口上显式声明。

### 边界

- 计数保存在 Node 进程内，多实例部署各自计数；
- 不引入 Redis，不保证跨实例强一致；
- 重启后计数清零；
- 不做全局限流，避免正常高频查询被误伤。

## 注册接口的限流与 IP 约束

**结论：注册接口目前只受「注册开关」控制，没有速率限制，也没有按 IP 的访问限制。**

### 现状

注册链路 `auth.register`（`server/sys-router/auth/index.ts`）→ `authService(ctx).register()`（`server/sys-router/auth/AuthService.ts`）→ `sysUserService(ctx).register()`（`server/sys-router/user/SysUserService.ts`）：

| 环节 | 位置 | 实际校验 |
| --- | --- | --- |
| 路由声明 | `server/sys-router/auth/index.ts` 的 `register` | `publicProcedure`，**没有挂 `rateLimitMiddleware`** |
| 注册开关 | `AuthService.register` | 读 `sys_config.system_register_enable`，不等于 `yes` 时抛 `auth.registerDisabled` |
| 唯一性 | `SysUserService.register` | 用户名 / 手机号查重（`auth.usernameExists`、`auth.phoneExists`） |

也就是说：**没有频率限制、没有单 IP 注册数量限制、没有验证码**。开启注册后，同一个 IP 可以连续提交注册请求。

### 项目中真正的「IP 维度限制」在哪里

| 能力 | 位置 | 维度与阈值 |
| --- | --- | --- |
| 登录限流 | `server/sys-router/auth/index.ts` 的 `login` | `rateLimitMiddleware({ limit: 10, windowMs: 60_000, scope: 'login' })`；未登录时 `identity` 回落为请求 IP |
| 图形验证码限流 | `server/api/captcha.get.ts` | 每 IP 30 次/分钟（`WINDOW_MS` + `MAX_REQUESTS_PER_WINDOW`） |
| 登录失败锁定 | `AuthService.login` | 按**账号**累计失败次数（`sys_config.system_login_max_retry`，默认 5 次）并锁定（`system_login_lock_minutes`，默认 10 分钟） |
| 请求 IP 解析 | `server/utils/requestInfo.ts` | `x-forwarded-for` → `x-real-ip` → h3 `getRequestIP`，用于登录日志与限流身份 |
| 支付回调 IP 白名单 | `server/trade-router/domain/pay/PayNotifyDispatcher.ts` | 按渠道配置的 `ipAllowlist`（交易域，与注册无关） |

> 注意：`rateLimitMiddleware` 的 `identity()` 优先用登录用户 id，未登录才用 IP。因此登录限流对暴力破解是「每 IP 10 次/分钟」，注册若沿用同一中间件也会是 IP 维度。

### 要给注册补限制时的改动点

1. `server/sys-router/auth/index.ts` 的 `register` 挂显式限流：

```ts
register: publicProcedure
    .use(rateLimitMiddleware({ limit: 5, windowMs: 60_000, scope: 'register' }))
    .input(SysUserRegisterSchema)
    .mutation(async ({ ctx, input }) => authService(ctx).register(input))
```

2. 如需「同一 IP 每日注册上限」，在 `AuthService.register` 里基于 `requestInfo` 的 IP 做计数（进程内 Map，和现有 limiter 一样不跨实例）。
3. 如需人机校验，复用登录页的图形验证码机制（`server/utils/captcha.ts` 的 `createCaptcha` / `verifyCaptcha`）。

> 这三项属于加固增强，**当前代码未实现**；本文档只记录现状，避免误以为注册已有频率/ IP 防护。

## 公开查询接口与白名单维护

未登录页面（登录、注册、官网、落地页、H5）需要的只读数据，走 `publicProcedure` 的公开查询接口。

### 已公开接口

| 接口 | 鉴权 | 数据范围 | 返回字段白名单 |
| --- | --- | --- | --- |
| `sysDictData.publicListByTypeCode` | 匿名 | 只认 `publicDictTypeCodes` 白名单，且只含 `status=1` | `value`、`label`、`i18nKey`、`listClass`、`sortOrder` |
| `sysConfig.getValueByKey` | 匿名 | 只认 `publicConfigKeys` 白名单，其余返回 `null` | 配置值本身 |
| `sysConfig.publicValues` | 匿名 | 批量版，非白名单 key 静默忽略 | `{ key: value }` |
| `sysNotice.publicPage` | 匿名 | 已发布且发布时间已到 | 公告展示字段（内容经 XSS 清洗） |
| `sysOrder.publicMallList` | 匿名 | 只列上架商品，价格用基础价 | 商品卡片字段，**不含** `detail` 与内部列 |
| `sysOrder.publicMallDetail` | 匿名 | 上架商品 | 商品卡片字段 |
| `sysPayChannel.publicList` | 匿名 | 已启用 + 已验证通过的渠道 | `id`、`configName`、`channelCode`、`mode`、`currency`、`isDefault`、`sortOrder` |
| `sysOauthConfig.enabledPlatforms` | 匿名 | 已启用的第三方登录平台 | 平台标识与展示名 |

### 需要长期维护的白名单

这两个常量是公开数据面的**默认白名单**，位置在 `packages/admin-core/shared/constants/business.ts`：

| 常量 | 作用 | 当前默认值 | 不维护的后果 |
| --- | --- | --- | --- |
| `publicDictTypeCodes` | 允许匿名读取的字典类型 | `no_yes`、`user_gender`、`enable_status`、`notice_type` | 新增的字典未加入 → 公开页面拿到空数组（`[]`），表现为"下拉是空的" |
| `publicConfigKeys` | 允许匿名读取的系统配置 | `system_register_enable`、`system_captcha_enabled`、`system_otherlogin_enable` | 新增的配置未加入 → 公开页面读到 `null`，表现为"开关一直不生效" |

#### 业务系统怎么追加白名单（不用改 layer）

业务系统**不要**去覆盖 `packages/admin-core/shared/constants/business.ts`：

- 消费方用的是 `#admin/shared/constants/business`，该别名直接指向 layer 包目录；
- 宿主放一份同名 `shared/constants/business.ts` 不会被读到；
- 复制整份文件再劫持别名会让后续 layer 升级漂移。

正确做法是**运行时注册**（与 `registerUserOnboardHook`、`registerSysJobHandlers` 同一套模式）。在宿主或业务层的 Nitro 插件里追加：

```ts
// server/plugins/public-allowlist.ts
import {
  registerPublicConfigKeys,
  registerPublicDictTypes
} from '#admin/server/utils/publicAllowlist'

export default defineNitroPlugin(() => {
  // 字典类型：登录前页面要读的自定义枚举
  registerPublicDictTypes(['industry_type', 'company_scale'])
  // 系统配置：登录前页面要展示的站点信息
  registerPublicConfigKeys(['site_filing_no', 'site_kf_phone'])
})
```

实现位置：`packages/admin-core/server/utils/publicAllowlist.ts`

- `registerPublicDictTypes(codes)` / `registerPublicConfigKeys(keys)`：追加，自动去重；
- `getPublicDictTypeCodes()` / `getPublicConfigKeys()`：返回「默认 + 追加」合并结果，`publicListByTypeCode`、`getValueByKey`、`publicValues` 都读这个合并结果；
- 注册表只在服务端可用，客户端无法调用；注册发生在 Nitro 插件初始化阶段，早于任何请求。

约束：**只能追加，不能移除** layer 的默认项（白名单是安全边界，避免误关默认公开项）。

### 维护检查清单

新增下列内容时，多问一句"未登录页面要不要用"，然后同步维护白名单：

1. **新增字典类型（`sys_dict_type`）**
   - 要被登录前页面 / 官网使用 → 在宿主 `server/plugins/public-allowlist.ts` 里 `registerPublicDictTypes([...])`
   - 只是后台内部枚举 → 不加（公开接口返回 `[]` 是预期行为）
   - 若同时属于所有宿主通用的字典，也可提 PR 加进 layer 默认值
2. **新增系统配置（`sys_config`）**
   - 要被登录前页面读取（如注册开关、公告条幅文案）→ `registerPublicConfigKeys([...])`
   - 含密钥、渠道参数、内部阈值 → 绝不加入
3. **新增公开查询接口**
   - 用 `publicProcedure`，并显式挂 `rateLimitMiddleware({ limit: 60, windowMs: 60_000, scope: 'public-xxx' })`
   - 返回字段必须显式 pick，不能直接返回整行（`remark`、`createdBy`、`config` 等一律不返回）
   - 只查询启用 / 上架 / 已验证的数据
   - **不要**写 evlog 宽事件（匿名请求会刷爆日志）
   - 把接口与字段白名单补进本文档「已公开接口」表格

### 安全约束

| 约束 | 说明 |
| --- | --- |
| 字段白名单 | 公开接口显式挑字段，杜绝整行返回 |
| 状态过滤 | 只返回 `status=1`（公告额外要求已发布、支付渠道额外要求验证通过） |
| 分页上限 | `pageSize ≤ 50`，避免匿名全量导出 |
| 限流 | 每个公开接口 60 次/分钟/IP |
| 日志 | 不写 evlog 宽事件 |
| 白名单兜底 | 字典返回 `[]`、配置返回 `null`，不抛错，避免匿名探测资源是否存在 |

## 公告 XSS 过滤

公告富文本使用 `sanitize-html` 清洗，保存与读取两侧都会执行。

实现：`server/utils/sanitizeHtml.ts`。

| 规则 | 说明 |
| --- | --- |
| 允许标签 | `p`、`br`、`strong`、`em`、`ul/ol/li`、`a`、`img`、`h1-h6`、`blockquote`、`code`、`pre`、表格等 |
| 允许属性 | `a[href,target,rel]`、`img[src,alt,width,height]`、`class` |
| 协议 | `http`、`https`、`mailto`；图片只允许 http/https |
| 移除 | `script`、`style`、`iframe`、`on*` 事件、`javascript:` 链接 |

`SysNoticeService` 在 `create` / `updateById` 清洗写入，在 `getById` / `getOne` / `page` / `list` / `latest` 清洗返回，兼容历史脏数据。

## 菜单外链与路由参数

`sys_menu` 新增：

| 字段 | 说明 |
| --- | --- |
| `external_link` | 外链地址；设置后优先于 `path`，点击新窗口打开 |
| `query` | 路由查询参数，不带 `?`，例如 `tab=1&from=menu` |

菜单表单已增加对应输入项。导航转换在 `app/utils/navigation.ts`：

- 外链：`to = externalLink`、`target = _blank`、`external = true`；
- 普通菜单：`to = path + '?' + query`。
