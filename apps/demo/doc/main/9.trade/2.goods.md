交易模块只有一张商品表：**服务不是独立实体**，而是 `type = 'service'` 的商品（`server/trade-router/domain/goods/types.ts:1-6`）。本页讲清商品/服务的数据结构、等级价的两张表关系与解析规则，以及后台商品页的实现要点。

## 一、sys_goods 字段

表结构定义在 `server/drizzle/schema/system/goods.ts:3-28`，字段口径与建表脚本 `doc/main/mysql-ddl-goods-order.sql:28-51` 一致。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | varchar(36) | 主键，模块层用 `randomUuid()` 生成（`modules/goods/SysGoodsService.ts:42-50`）；契约里的 `id` 只用于修改定位 |
| `name` | varchar(100) | 商品名称，必填 |
| `subtitle` | varchar(200) | 副标题 / 卖点，列表里显示在名称下方 |
| `cover` | varchar(500) | 封面图 URL，可以是对象存储上传结果，也可以手填 |
| `price` | decimal(12,2) | **基础价**（元），默认 `0.00`；会员未配等级价时用它 |
| `stock` | int | 库存，默认 `0`；不限库存时该字段被忽略 |
| `unlimited_stock` | tinyint | `1 = 不限库存`；`0`（默认）时按 `stock` 判定 |
| `sales_count` | int | 累计销量，**支付完成后**由 `increaseSales` 累加 |
| `type` | varchar(20) | `virtual`（默认）/ `service` / `physical`（预留） |
| `service_notice` | varchar(500) | 服务类下单提示 / 交付说明，仅 `service` 使用 |
| `detail` | text | 商品详情，商城详情弹窗里按 `whitespace-pre-wrap` 展示 |
| `sort_order` | int | 显示排序，默认 `0`；列表与商城都按它升序 |
| `status` | tinyint | `0` 下架 / `1` 上架（默认） |
| `remark` | varchar(255) | 备注 |
| `created_by` / `created_at` / `updated_by` / `updated_at` / `is_deleted` | 审计字段 | 逻辑删除，`is_deleted = 0` 才参与查询 |

索引：`idx_goods_status(status, is_deleted, sort_order)`、`idx_goods_type(type, status)`（`server/drizzle/schema/system/goods.ts:25-26`）。

契约约束（`shared/system/goods/input.ts:9-36`）：`name` 必填 1–100；`price` 是 `string | number`（**没有下限校验**）；`stock` 整数 ≥ 0 默认 0；`unlimitedStock` 默认 0；`type` 默认 `virtual`；`status` 默认 1；`sortOrder` 默认 0。

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**`price` 的负数只在「用它的那一刻」才会被拦。**接口层不校验正负，真正归一是领域层的 `normalizeMoney(..., { allowZero: true })`（`domain/goods/GoodsService.ts:50,64`），它会让金额为负时抛 `module.system.member.amountInvalid`——错误码来自钱包域。后台表单把输入框限制为 `:min="0"`（`app/pages/system/goods/components/sys-goods-operate.vue:493-500`），但绕过界面写库的负数价格会在**商城列表/下单**时报错，而不是在保存时。
::

## 二、商品类型：`virtual` / `service` / `physical`

类型枚举定义在 `shared/system/goods/input.ts:6`，展示文案在 `shared/constants/business.ts:193-197`（`goodsTypeRecord`，**故意不放进字典表**，避免被后台改坏）。

| 类型 | 展示 | 代码里的实际差异 |
| --- | --- | --- |
| `virtual` | 虚拟物品 | 无特殊逻辑；`fulfill_status` 恒为 `none` |
| `service` | 人工服务 | 下单时 `quantity` 强制 1、`contact` 必填、`fulfill_status` 置 `pending` |
| `physical` | 实物（预留） | **只有枚举与文案**，没有物流/地址/收货逻辑，`fulfill_status` 也是 `none` |

服务类的三点差异全部落在下单事务里（`server/trade-router/domain/order/OrderService.ts:178-183,236`）：

```text
isService = goodsRow.type === 'service'
quantity  = isService ? 1 : Math.max(1, Math.floor(input.quantity))   // 服务恒为 1，不报错
if (isService && !input.contact?.trim())  → module.system.order.contactRequired
fulfillStatus = isService ? 'pending' : 'none'
```

注意 `quantity` 的处理方式：**服务类不是抛错而是被静默改成 1**。i18n 里存在 `module.system.order.quantityInvalid`（文案是「服务类商品只能购买 1 份」），但代码中没有任何抛出点（`app/locales/zh.json:1778`）。

## 三、不限库存（`unlimited_stock`）

库存相关一律是**条件 UPDATE + `affectedRows`**，从不「先查再改」，因此不存在超卖窗口（`server/trade-router/domain/goods/repo/goodsRepo.ts:1-6`）：

```sql
-- 扣减（goodsRepo.ts:52-62）
update sys_goods
set stock = stock - :quantity
where id = :goodsId and is_deleted = 0
  and (unlimited_stock = 1 or stock >= :quantity)

-- 回滚（goodsRepo.ts:65-75）
update sys_goods
set stock = stock + :quantity
where id = :goodsId and is_deleted = 0 and unlimited_stock = 0
```

| 规则 | 落点 |
| --- | --- |
| 服务类商品**建议**打开不限库存（DDL 注释 `doc/main/mysql-ddl-goods-order.sql:16`） | 配置约定，不是代码强制 |
| `unlimited_stock = 1` 的商品：扣减语句里的 `or unlimited_stock = 1` 让它永远命中 | `goodsRepo.ts:58` |
| 同上：回滚语句里的 `and unlimited_stock = 0` 让它**不动库存字段**（本来就没扣） | `goodsRepo.ts:71` |
| 扣减影响行数为 0 → 抛 `module.system.order.stockNotEnough` | `GoodsService.ts:160-166` |
| 影响行数为 0 也可能是「商品不存在 / 已逻辑删除」，代码不区分，统一按库存不足报错 | `goodsRepo.ts:48-51` 注释 |

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**商城列表里的库存显示口径与扣减口径不同**：`toMallCard()` 在不限库存时把 `stock` 置为 `null`、`unlimited_stock` 置为 1，前端据此显示「不限量」（`modules/order/SysOrderService.ts:54-71`、`shared/system/goods/output.ts:57-61`）。后台列表则直接显示 `unlimitedStock === 1 ? '不限库存' : stock`（`app/pages/system/goods/index.vue:268-274`）。
::

## 四、sys_goods_level_price 字段

一个商品 × 一个会员等级一行；**没有行 = 该等级用商品基础价**（`server/trade-router/domain/goods/repo/goodsLevelPriceRepo.ts:1-6`）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | varchar(36) | 主键 |
| `goods_id` | varchar(36) | 商品 id |
| `level_id` | varchar(36) | 会员等级 id（`sys_member_level.id`） |
| `price` | decimal(12,2) | 该等级专属价，默认 `0.00` |
| `remark` | varchar(255) | 备注 |
| 审计字段 | — | 同样带 `is_deleted`，但**保存时并不使用软删**（见第六节） |

索引：唯一键 `uk_goods_level(goods_id, level_id)`、`idx_goods_level_goods(goods_id, is_deleted)`、`idx_goods_level_level(level_id)`（`server/drizzle/schema/system/goodsLevelPrice.ts:16-19`、`doc/main/mysql-ddl-goods-order.sql:66-68`）。

## 五、等级价解析：`member > level > base`

解析入口是 `GoodsService.resolvePrice()`（`server/trade-router/domain/goods/GoodsService.ts:41-68`）：

```text
resolvePrice({ goods, levelId })
   ├─ base = normalizeMoney(goods.price, { allowZero: true })
   ├─ levelId 为空            → { unitPrice: base, priceSource: 'base', levelId: null }
   ├─ 查 sys_goods_level_price（goods_id + level_id + is_deleted = 0）
   │      查不到              → { unitPrice: base, priceSource: 'base', levelId }   ← levelId 仍带上，便于追溯
   └─ 命中                    → { unitPrice: 该行 price, priceSource: 'level', levelId }
```

三条要点：

1. **`member`（会员协议价）是预留值，解析链路里根本没有这个分支**，枚举只出现在 `PriceSource`（`domain/goods/types.ts:11-15`）与展示常量 `orderPriceSourceRecord`（`shared/constants/business.ts:227-231`）里。
2. **没配等级价时 `levelId` 也会带上**，`priceSource` 是 `base`——落单后可以解释「这一单是按基础价成交的，但当时会员在某个等级」。
3. **`allowZero: true`**：0 元商品（免费商品）与付费商品走同一条链路，是否拦截交给调用方；真正禁止的是「应付金额为 0 的订单」（`OrderService.ts:199-202` 抛 `module.system.order.payAmountInvalid`）。

批量版本 `resolvePrices()` 供商城列表使用（`GoodsService.ts:74-109`）：先用 `listByGoodsIds()` 一次取回所有等级价再在内存里按 `goodsId` 建 Map，避免 N+1；这条路径是 `mallList` 用的，`mallDetail` 与下单用单条 `resolvePrice()`。

## 六、保存策略：整体替换（物理删除）

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**保存等级价 = 物理删除该商品的全部旧行，再插入新行。**

原因写在 `goodsLevelPriceRepo.deleteByGoodsId()` 的注释里（`server/trade-router/domain/goods/repo/goodsLevelPriceRepo.ts:67-73`）：唯一键 `uk_goods_level(goods_id, level_id)` **不包含 `is_deleted`**，若改成软删，重新给同一等级配价时会撞唯一键。等级价是配置数据、不是资金凭证，所以不保留软删历史。
::

流程与规则（`GoodsService.saveLevelPrices()`，`GoodsService.ts:122-157`）：

```text
saveLevelPrices({ goodsId, items, operatorId })
   ├─ goods.findById(goodsId)   不存在 → module.system.order.goodsNotFound
   ├─ levelPrices.deleteByGoodsId(goodsId)        物理删除（原生 SQL delete）
   ├─ items.filter(price 非空)                      price 为 null/undefined/空串的项**直接跳过**
   │      → 等价于「该等级用基础价」
   ├─ normalizeMoney(price, { allowZero: true })   金额归一
   └─ insertMany(rows)                             空数组时直接 return，不发 SQL
```

事务边界：`goodsService(db).saveLevelPrices()` 用 `db.transaction()` 包住（`GoodsService.ts:212-220`），所以「删除 + 插入」要么都成功要么都回滚。

三个连带的注意点：

- **未提交的项会被清掉**：因为整体替换，接口只能提交「本次想保留的完整集合」。前端为此做了差量判断（见第八节）。
- **停用等级的价格会被回显并原样带回**：`levelPrices` 只列启用等级，但若某个已停用等级还留着专属价，弹窗会以 `disabled` 行补显并一起提交，否则整体替换会静默清掉它（`app/pages/system/goods/components/sys-goods-operate.vue:327-342`）。
- **契约注释与实际实现不一致**：`shared/system/goods/input.ts:76` 写的是「先软删旧行再插新行」，`goodsLevelPriceRepo.ts:5` 的文件头注释也写「先软删该商品旧行」，**代码是物理删除**（`:74-77`）。以代码为准。

## 七、价格与等级的快照

下单时把价格解析结果**快照**进订单行，商品之后改价不影响历史单（`server/trade-router/domain/order/OrderService.ts:186-227`）：

| 订单字段 | 来源 |
| --- | --- |
| `unit_price` | `resolvePrice()` 的 `unitPrice` |
| `price_source` | `base` / `level` |
| `level_id` | 命中的等级 id（`priceSource = base` 时也带上当前等级） |
| `goods_name` / `goods_cover` / `goods_type` | 商品行当时的名称 / 封面 / 类型 |
| `total_amount` | `fromCents(toCents(unitPrice) * quantity)`，即「单价 × 数量」的整数分运算 |

会员等级从**会员档案**取：`members.getMember(userId)?.levelId`（`OrderService.ts:186`）。会员没有档案时 `levelId` 为 `null`，价格回落到基础价。

这也是「商品可以随便删」的原因：订单不依赖商品行，详情页展示的快照来自订单自己（`app/pages/system/order/components/sys-order-detail.vue:184-216`）。

## 八、后台商品页要点

页面：`app/pages/system/goods/index.vue`（列表）+ `components/sys-goods-operate.vue`（新增/编辑弹窗）+ `components/sys-goods-search.vue`（搜索）。

### 列表

| 列 | 说明 |
| --- | --- |
| 封面缩略图 | 无封面时显示 `i-lucide-image-off` 占位（`index.vue:219-228`） |
| 名称 + 副标题 | 两行展示，超长截断 |
| 类型 | `service` 用 warning 色徽标 + `i-lucide-headset` 图标突出，其余为灰色文本（`index.vue:242-254`） |
| 基础价 | 金额下方附带「已配置 N 个等级价」的辅助提示 |
| 库存 | `unlimitedStock === 1` 显示「不限库存」，否则显示数字 |
| 销量 / 排序 / 状态 | 状态用 `goodsStatusConfig` 徽标 |

**等级价数量的补查**：契约 `SysGoodsRespDTO` 里没有这个字段，列表页只能对当前页的行逐个调 `sysGoods.levelPrices` 再缓存（`index.vue:72-166`）。实现要点：

- 只查缓存里没有的 id；**失败不写缓存**（写 `-1` 占位，显示时跳过），下次刷新会重试；
- 每批 5 个并发（`chunkSize = 5`），并用 `levelPriceCountToken` 做「列表已翻页就丢弃旧结果」的保护；
- 弹窗保存后回传被改动的商品 id，只删该行的缓存再刷新（`index.vue:168-175`）。

### 搜索

`sys-goods-search.vue` 提供名称（like）、类型、状态、价格区间（`priceMin` / `priceMax`）与创建时间区间；后两者是非表字段，由 Repo 用 `extraWhere` 追加（`modules/goods/SysGoodsRepo.ts:41-70`）。契约里 `subtitle` 也是 like 字段，但界面上没有对应输入框。

### 新增 / 编辑弹窗

- **等级价子表只在编辑态渲染**。新增态显示提示「新增商品保存后，请再次编辑该商品以配置会员等级价」（`sys-goods-operate.vue:671-677`），因为 `create` 只返回布尔值、此时还没有 id。
- **等级列表只含启用中的会员等级**：`sysGoods.levelOptions` → `members.listLevels()` → `levels.listEnabled()`（`modules/goods/SysGoodsService.ts:104-107`、`domain/member/MemberService.ts:486-489`）。等级名由模块层合并（领域层不跨域查会员等级，`SysGoodsService.ts:109-135`），等级被停用或查不到时 `levelName` 为 `null`，前端回落显示 levelId。
- **只有真的改动过才调 `saveLevelPrices`**：打开弹窗时把待提交的 items 序列化成基线（`levelPriceBaseline`），提交时比较 `JSON.stringify(buildLevelItems())`，相同就跳过接口，避免把停用等级的价格误清（`sys-goods-operate.vue:299-307,445-454`）。
- **「留空 = 该等级用基础价」在两层都成立**：前端 `buildLevelItems()` 过滤掉 `price === null` 的行（`:299-305`），领域层再过滤一次空值（`GoodsService.ts:141-152`）。
- **`serviceNotice` 只对服务类保留**：切回 virtual/physical 时前端会把它清成 `null`（`sys-goods-operate.vue:418-419`）。

### 封面上传与降级行为

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**封面上传依赖 `system:oss:add` 权限，缺权限时整块上传区降级为「只填 URL」，不影响商品保存。**

判定是 `isAdmin || hasPermission('system:oss:add')`（`sys-goods-operate.vue:145`）；上传走原生 XHR `POST /api/system/oss/upload`（该接口用 `requirePermission(ctx, crudPermissionCodes('system:oss').add)` 鉴权，`server/api/system/oss/upload.post.ts:21-23`），手填 URL 输入框**始终存在**（`sys-goods-operate.vue:606-607`），无权限时替换上传区的是一条 warning 提示 `module.system.goods.coverUploadUnavailable`（文案：「当前账号没有对象存储上传权限，请直接填写封面地址」，`app/locales/zh.json:1739`）。

三处容错：上传配置列表拉取失败 → 只保留手填 URL（`:169-175`）；上传中途关弹窗会 `abort()` 并把进度归零（`:401-407`）；上传中/保存中禁止点击遮罩关闭弹窗（`dismissible: !uploading && !saving`，`:477`）。
::
