交易模块的前端共四个页面 + 两个入口。后台两页走 `useCrudPermissions` 的 CRUD 权限位，会员自助两页只要求登录（服务端 `protectedProcedure` + 归属校验）。

## 一、页面与入口总览

| 页面 | 路径 | 路由权限 | 数据来源 |
| --- | --- | --- | --- |
| 商品管理 | `app/pages/system/goods/index.vue` | `system:goods:{list,add,edit,del}` | `sysGoods.*` |
| 订单管理 | `app/pages/system/order/index.vue` | `system:order:{list,edit,del,confirm,close,sync,fulfill}` | `sysOrder.*` |
| 商城（自助） | `app/pages/system/mall/index.vue` | 仅登录 | `sysOrder.mallList` / `mallDetail` / `myCreate` / `mySync` |
| 我的订单（自助） | `app/pages/system/my-orders/index.vue` | 仅登录 | `sysOrder.myPage` / `myDetail` / `myConfirm` / `myCancel` / `mySync` / `myPayment` |

入口：头像菜单 `app/components/UserProfile.vue:29-39` 提供「商城」`/system/mall` 与「我的订单」`/system/my-orders`（与 `/system/wallet` 并列）；商城页顶部与我的订单页顶部也互有跳转按钮（`mall/index.vue:30-35`、`my-orders/index.vue:14-19`）。

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**商城与我的订单是会员自助页，不做路由级权限拦截。**它们出现在 `sys_menu` 里只为演示方便，页面本身不校验 `system:mall` / `system:myOrder` 权限码（`doc/main/mysql-ddl-goods-order.sql:127-129`），服务端也只要求登录 + 订单归属。因此不要在菜单里给它们配「按钮权限」并期待生效。
::

## 二、后台商品管理页

完整的字段、等级价子表与封面上传降级行为见[商品与服务模型](/docs/main/trade/goods)第八节。这里只列页面级的权限与交互要点：

| 元素 | 显示条件 | 依据 |
| --- | --- | --- |
| 新增按钮 | `system:goods:add` | `goods/index.vue:23,26` |
| 批量删除按钮 | `system:goods:del` + 已勾选 + 非 loading | `:21-28` |
| 行内「编辑」 | `canEdit`（`system:goods:edit`） | `:186-193` |
| 行内「删除」 | `canDel`（`system:goods:del`），带 Popconfirm | `:195-205` |
| 勾选列 | 只有 `canDel` 才渲染 | `:212` |
| 操作列 | `canOperate` = 有 edit 或 del | `:286`、`app/composables/useCrudPermissions.ts:15` |

`canOperate`、`canEdit` 这类判断都来自 `useCrudPermissions('system:goods')`（`index.vue:69`），管理员一律放行，与服务端 RBAC 规则一致。

## 三、后台订单管理页

页面结构：搜索区 → 4 张统计卡 → 列表卡片（含批量删除）。

### 统计卡与查询

| 卡片 | 字段 | 口径 |
| --- | --- | --- |
| 今日订单数 | `todayCount` | 固定「今天 00:00:00 起」的订单数（不含已删除） |
| 今日成交额 | `todayAmount` | 同上区间内 `status = 'OD'` 的 `pay_amount` 之和 |
| 待支付订单数 | `pendingCount` | 全量 `status = 'WP'`，不受时间区间影响 |
| 待交付服务订单数 | `pendingFulfillCount` | 全量 `status = 'OD' and fulfill_status = 'pending'` |

`summary` 接口返回 6 个字段（`shared/system/order/output.ts:94-109`），页面只用其中 4 个；`todayFrom` 在领域层写死为「今天零点」（`domain/order/OrderService.ts:849-866`）。

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**统计卡实际不随搜索区间变化。**页面在搜索时把 `createdFrom` / `createdTo` 传给了 `summary`（`order/index.vue:208-220`），但真正跟随区间的两个字段是 `totalCount` / `totalAmount`，而它们**没有显示在任何卡片上**；显示的 4 张卡（today / pending / pendingFulfill）都是全量或固定今日口径。页面上方注释「区间汇总……（不随区间变化）」容易让人误以为部分卡片会跟随区间，实际是「四张卡都不会跟随」。另外服务端 `sumByRange` 的 `totalCount` 统计的是区间内**全部** `is_deleted = 0` 的订单（含 `CL` / `FL`），只有 `totalAmount` 限定 `status = 'OD'`（`domain/order/repo/orderRepo.ts:258-281`），而契约注释写的是「区间内订单数（不含已关闭/失败）」。
::

筛选条件（`components/sys-order-search.vue`）：

| 条件 | 作用字段 |
| --- | --- |
| 订单号 | `order_no`（like） |
| 会员 | `user_id`，用 `MemberUserSelect` 组件（`source="sysMemberOrder"` → `sysOrder.userOptions`，即 `members.searchUserOptions`） |
| 状态 / 支付方式 / 履约状态 | `status` / `pay_mode` / `fulfill_status` 精确匹配 |
| 金额区间 | `amountMin` / `amountMax` → 打在 `pay_amount` |
| 下单时间区间 | `createdFrom` / `createdTo` → 打在 `created_at`，日期选择器提交时补成 `00:00:00` / `23:59:59` |

### 列表列

| 列 | 说明 |
| --- | --- |
| 序号 | 按分页计算 `(page - 1) * pageSize + index + 1` |
| 订单号 | 等宽加粗，`break-all` |
| 会员 | 昵称（回落账号）+ 手机号两行；来自 Repo 的 `leftJoin sysUser` |
| 商品 | 商品名快照 + 商品类型徽标（`goodsTypeRecord`） |
| 应付金额 | `payAmount` 加粗，下方附「单价 × 数量」 |
| 价格来源 | `orderPriceSourceRecord`；`priceSource === 'level'` 时用 success 色高亮（等级价是权益兑现的信号） |
| 支付方式 | `orderPayModeRecord` |
| 状态 | `orderStatusConfig` 徽标 |
| 履约状态 | **只有 `goodsType === 'service'` 才展示徽标**，其余显示 `-`（`order/index.vue:464-485`） |
| 创建时间 | 直接展示 `created_at` |
| 操作 | 见下表 |

列表与详情共用 Repo 的 `profileColumns`（订单全字段 + 昵称 / 账号 / 手机号 / 等级名），通过两次 `leftJoin` 得到（`modules/order/SysOrderRepo.ts:32-39,74-118`）。

### 动作按钮与权限位

| 按钮 | 显示条件（前端） | 权限码 | 服务端行为 |
| --- | --- | --- | --- |
| 详情 | 始终 | 无（列表页已有数据，详情再拉一次 `getById`） | `getById` 需 `system:order:list` |
| 确认 | `status = WP` 且 `payMode = balance` | `system:order:confirm` | 余额实扣（冻结确认 + 核销券 + 加销量） |
| 查看支付码 / 同步 | `status = WP` 且 `payMode = online` | `system:order:sync` | 外呼渠道并推进订单（`sysOrder.sync`） |
| 交付 | `status = OD` 且 `fulfillStatus = pending` | `system:order:fulfill` | 只推进履约 |
| 关闭 | `status = WP` | `system:order:close` | 释放冻结 / 券 / 库存并置 `CL` |
| 删除 | `status = CL` 或 `FL` | `system:order:del` | 二次校验后才软删 |
| 批量删除 | 有勾选 + `canDel` | `system:order:del` | 逐单校验 `CL` / `FL` |

按状态与支付方式隐藏按钮的口径（`order/index.vue:342-401`）：

| 状态 | 余额单 | 在线单 |
| --- | --- | --- |
| `WP` | 确认、关闭、删除（删除按钮不显示，因为 `WP` 不满足条件） | 同步、关闭 |
| `OD` | 交付（仅服务类待交付） | 同左 |
| `CL` / `FL` | 删除 | 删除 |

两个细节：

- 四个动作权限分别是独立权限码（`order/index.vue:132-136` 用 `customPermissionCode('system:order', 'confirm')` 等），所以可以只给某个角色「同步」而不给「确认」；`confirm` / `close` / `sync` / `fulfill` 都是会推进状态、牵动资金的动作（`server/trade-router/modules/order/index.ts:24` 注释）。
- 单行动作有 `actingId` 行级 loading，避免同一行被连点两次（`order/index.vue:156-157,249-261`）。

### 详情、关闭、交付三个弹窗

- **详情**（`components/sys-order-detail.vue`）：打开时用 `sysOrder.getById` 拉一次最新数据（列表行可能已过期，例如被他人操作或被定时任务关掉），失败时退化为列表行数据（`:126-145`）。分区展示：状态 / 履约 / 价格来源徽标 → 商品快照 → 金额（商品金额 / 优惠 / 应付 / 赠送金 / 充值金）→ 会员信息 → 链路信息（订单号、支付方式、优惠码、`freezeId`、`payOrderId`、渠道码、联系方式、备注）→ 服务交付区（仅服务类）→ 关闭原因 / 失败原因告警 → 时间轴（创建、过期、支付、完成、关闭，**只渲染有值的节点**，`:111-124`）。
- **关闭**（`components/sys-order-close.vue`）：必须填关闭原因，前端先拦一次再发请求（`:45-50`），失败时保留弹窗并附带服务端 message。
- **交付**（`components/sys-order-fulfill.vue`）：交付说明可选，留空只做状态推进。

## 四、会员自助商城

`app/pages/system/mall/index.vue`：关键字 / 类型筛选 + 12 条一页的卡片网格 + 详情弹窗（弹窗同时就是下单表单）。

### 「我的价格」

卡片上的主价格是 `myPrice`，由**服务端**按当前会员等级解析（`sysOrder.mallList` → `goods.resolvePrices`，`modules/order/SysOrderService.ts:336-373`），前端不参与计算：

| 展示 | 条件 |
| --- | --- |
| `¥{{ myPrice }}` 主价 | 始终 |
| 划线 `¥{{ price }}`（基础价） | `priceSource === 'level'` |
| 等级名徽标 | `priceSource === 'level'`，取 `levelName`（回落显示「等级价」文案） |
| 库存文案 | `unlimitedStock === 1` → 「不限量」；否则「剩余 N」（`stock` 在不限库存时为 `null`） |
| 服务徽标 | `type === 'service'` |
| 服务说明 | 详情弹窗里 `type === 'service' && serviceNotice` 时用 info 告示展示 |

打开详情弹窗时会**重新调 `mallDetail`** 取服务端价格，而不是复用列表里的旧值（`:330-336`）——等级可能在两次请求之间被调整。

### 下单表单

| 字段 | 显示条件 / 约束 |
| --- | --- |
| 数量 | 非服务类显示，范围 1–99；服务类不显示（前端提交时也强制 1） |
| 支付方式 | 单选「余额支付 / 在线支付」，默认余额（`orderForm.payMode = 'balance'`） |
| 优惠码 | 可空，附帮助文案 |
| 联系方式 | **仅服务类**，`required`，且未填时下单按钮 `disabled`（`:207`） |
| 需求说明 | 仅服务类 |

提交时用 `randomUuid()` 作为 `requestId`（`:415-423`），响应带 `reused: true` 时提示「该订单已存在，已为你打开原订单」。

::div{.my-6.rounded-xl.border.border-default.bg-elevated.p-5}
**幂等键的边界**：`requestId` 是在 `submitOrder()` 内部每次调用 `randomUuid()` 现生成的（`mall/index.vue:422`），所以它保护的是「同一次请求被重复执行（重试 / 网络重放）」，**不是「用户连点两次下单」**——两次点击会拿到两个不同的 `requestId`，服务端会落两张单。连点防护只有按钮的 `:loading="creating"`（`:202-213`）。
::

### 余额支付与在线支付

| 支付方式 | 结果处理 |
| --- | --- |
| `balance` | 提示「已冻结余额 ¥{amount}，请到「我的订单」确认支付」（`balanceFrozen`），关闭弹窗并跳 `/system/my-orders`。**此时钱只是冻结，订单仍是 `WP`**，必须去我的订单点「确认支付」才实扣 |
| `online` | 展示支付码区块（二维码图片或二维码内容）并开始轮询 |

在线支付的轮询（`:271-406`）：

| 参数 | 值 |
| --- | --- |
| 间隔 | 5 秒（`POLL_INTERVAL = 5000`） |
| 总超时 | 10 分钟（`POLL_TIMEOUT = 10 * 60 * 1000`），到时提示 `pollTimeout` 并停止 |
| 连续失败阈值 | 3 次（`pollFailures >= 3`），提示 `pollFailed` 并停止 |
| 轮询动作 | `sysOrder.mySync`（服务端会外呼渠道查询，含 3 秒节流） |
| 停止条件 | 状态不再是 `WP`（含变成 `OD`）、关闭弹窗、组件卸载 |

二维码区块的展示优先级：`qrImageUrl`（直接显示图片）→ `qrContent`（可复制的文本，本地渲染）→ 都没有时提示「暂无二维码」；`payUrl` 存在时额外给一个「打开支付链接」按钮（`:154-193`）。

## 五、我的订单

`app/pages/system/my-orders/index.vue`：状态筛选 + 分页表格（10 条一页）+ 详情弹窗。

| 列 | 说明 |
| --- | --- |
| 订单号 | 原样展示 |
| 商品 | 封面缩略图 + 商品名快照 |
| 应付金额 | `payAmount` |
| 支付方式 / 状态 / 履约状态 | 走 `orderPayModeRecord` / `orderStatusConfig` / `orderFulfillStatusConfig` |
| 创建时间 | `created_at` |
| 操作 | 只有「详情」 |

详情弹窗的动作**只对 `WP` 显示**（`:140-188`），与服务端状态机一致：

| 按钮 | 显示条件 | 接口 | 说明 |
| --- | --- | --- | --- |
| 确认支付 | `WP` + `payMode = balance` | `myConfirm` | 实扣冻结余额 |
| 查看支付码 | `WP` + `payMode = online` | `myPayment` | **只读本地支付单、不发渠道请求**，因此可重复点击；页面刷新后仍能重新看到二维码 |
| 同步 | `WP` | `mySync` | 外呼渠道并按幂等路径推进 |
| 取消 | `WP` | `myCancel` | Popconfirm 二次确认；来源固定 `user`、原因固定「用户取消」 |

其他展示：履约提示条（`pending` → 「待交付」说明；`delivered` → 交付说明或默认文案）、关闭原因提示条（`status = CL` 且有 `closeReason`）、价格来源等级徽标、以及一节明细（订单号、支付方式、价格来源、优惠码、赠送金 / 充值金抵扣、`freezeId`、`payOrderId`、联系方式、备注、各时间节点、失败原因）。打开详情时同样会用 `myDetail` 拉一次最新数据（`:295-303`）。

`myPayment` 的返回在**没有关联支付单**（余额单）或支付单不存在时给出 `null` 字段，前端据此隐藏二维码区块（`modules/order/SysOrderService.ts:296-328`）。

## 六、i18n 与常量复用

| 位置 | 内容 |
| --- | --- |
| `shared/constants/business.ts:190-231` | `goodsTypeRecord`、`goodsStatusConfig`、`orderStatusConfig`、`orderPayModeRecord`、`orderFulfillStatusConfig`、`orderPriceSourceRecord` |
| `app/locales/zh.json` `module.system.goods.*` | 商品页文案，含 `levelPrice.*` 子表文案与 `coverUploadUnavailable` |
| 同上 `module.system.order.*` | 订单页文案，含 `status.*` / `payMode.*` / `fulfillStatus.*` / `priceSource.*` 与动作、提示文案 |
| 同上 `module.system.mall.*` | 商城文案，含 `balanceFrozen` / `polling` / `pollTimeout` / `pollFailed` / `qrContentTip` |
| 同上 `module.system.myOrder.*` | 我的订单文案 |
| `app/composables/badgeColorClasses.ts` | 徽标配色；列表与详情都按 `config.color` 取类名 |

状态、支付方式、履约状态、价格来源、商品类型**都走常量映射而不是字典表**——这些枚举一旦被后台改坏，资金与履约的语义就解释不清了（与支付状态不进字典表同一考虑，见[支付模块总览](/docs/main/payment/overview)第五节）。类型文案的取法见 `goods/index.vue:105-109` 的 `typeLabel()`：常量里查不到时回落显示原始值，不显示空白。
